# PRD: harness-plate

## 목표
에이전트가 어떤 도구로 일하든 같은 규격(단계 순서, 기록 위치와 형식, 통과 조건)으로 작업하게 하는 하네스 "레일"을 만든다(ADR-004). 막을 실패는 둘이다: 긴 세션의 컨텍스트 팽창, 검증 없는 완료 선언. 막는 장치는 규칙 구간이 기본이고 Claude Code 훅이 테스트 먼저와 계획 없는 편집을 더 막는다. 규칙 구간은 셋업이 `AGENTS.md`에 넣는 작업 규칙(계획부터 세우고, task는 회고가 통과해야 끝나고, tasks는 끝의 코드 평가와 하네스 eval을 담은 보고가 나와야 끝난다)이고, 스킬 본문의 절차와 함께 막는다.

## 사용자
개인용이다(가정으로 둔 것). 프로젝트에 플러그인으로 설치하고, 그 프로젝트의 모든 작업을 하네스의 파이프라인으로 진행한다(ADR-005).

## 핵심 기능
단계별로 하나씩 완성한다.
1. 셋업: 프로젝트에 하네스 문서의 위치 기준을 세운다. 1단계에서 만들었다.
2. 맥락: 스캔과 질문 라운드로 맥락 문서를 채운다. 추측으로 적지 않는다. 2단계에서 만들었다.
3. 계획: 요청 하나를 tasks로 계획해 tasks 머리(`docs/tasks/plan.md`)와 task 폴더마다의 머리(`plan.md`)와 phase마다의 `phase-N.md`로 남긴다. 추측으로 정하지 않고 묻는다. 3단계에서 만들었고 `010-tasks-cycle`에서 tasks > task > phase로 나눴다.
4. 실행: 계획이 정한 phase마다 새 컨텍스트의 에이전트가 수행해 그 phase의 `phase-N.md`에 기록을 덧붙이고, 다른 새 에이전트가 확인한다. 확인이 통과한 phase의 파일은 `done-phase-N.md`로 이름을 바꾼다. 4단계에서 만들었고 `010-tasks-cycle`에서 확인을 수행과 나눴다.
5. task 회고: task의 phase가 모두 통과하면 새 컨텍스트의 에이전트가 task 전체를 완료 조건과 맥락 문서에 대어 보고 `retro.md`에 기록을 남기고, tasks 끝에 볼 것을 `docs/tasks/FRICTION.md`에 적는다. 회고가 통과하지 않은 task는 끝나지 않는다. 5단계의 검증을 `010-tasks-cycle`에서 회고와 합쳤다.
6. TDD와 엣지케이스: 테스트가 있는 프로젝트에서 테스트 먼저인 phase는 실패하는 테스트 → 구현 → 통과 순서로 수행하고 두 출력을 기록에 남긴다. plan은 phase마다 테스트 먼저를 적고 엣지케이스를 논의할지 묻는다. Claude Code 훅이 테스트 먼저와 계획 없는 편집을 막는다. 6단계에서 만들었다.
7. 자동 사이클: run이 시작할 때 실행 방식을 묻는다. task 하나씩은 task 회고가 끝날 때마다 묻고, tasks 일괄은 묻지 않고 모든 task를 처리하며 회고에서 나온 문제는 고칠 phase를 더해 고친다. 어느 방식이든 막힘, 계획이 틀림, 같은 확인이나 회고의 세 번 실패에서는 멈추고 원인과 해결책을 논의한다. `010-tasks-cycle`에서 만들었다.
8. 평가: 모든 task가 끝나면 새 에이전트가 tasks에서 바뀐 코드를 다섯 범주(신뢰성, 보안, 유지보수성, 테스트 적절성, 기능 적합성)로, 다른 새 에이전트가 하네스를 여섯 기준(결과 성공, 일관성, 효율, 규칙 준수, 사람 개입률, 실패 양상)으로 A~E로 매긴다. 코드의 통과선은 Sonar way다. run이 전체 보고와 함께 고칠지 한 번에 묻고, 고치면 고침 task를 더해 같은 레일로 돌리고, plate 자체의 고칠 거리는 GitHub 이슈로 올리고(ADR-020), 미룬 소스 문제는 `docs/BACKLOG.md`에 적는다. tasks 끝의 평가는 `010-tasks-cycle`에서 만들었다. 로컬 리뷰 뒤 PR을 열고 CI 에이전트가 판정하는 일은 011에서 만든다.
9. 정리·리팩터링: 코드베이스를 정기·비정기로 살펴 정리하는 스킬을 둔다. 9단계에서 만든다.

9단계까지 만든 뒤 1.0.0을 낸다.

## 범위 밖
- 파이프라인을 건너뛰는 예외 경로. 예외 없이 모든 작업이 파이프라인을 거친다.
- 옛 plate v0.3.0의 결정과 장치를 이어받는 것. 완전히 새로 시작한다.
- superpowers를 설치해 기대는 것. 기법만 가져온다(ADR-005).
- README, CHANGELOG 같은 일반 문서의 위치 관리. 위치 규칙은 하네스 기록에만 적용한다.
- 여러 파일로 나뉜 기존 문서를 하나로 합치는 것. 지도에 경로만 적는다.
- 검증 없는 종료를 막는 훅. v1.0 뒤에 한다.
- v1.0 전에 다른 도구(Codex, Grok Build)에서 같은 결과를 확인하는 것. 완성 판정은 Claude Code로만 하고, 다른 도구로 넓히는 일은 v1.0 뒤에 한다(ADR-018).
