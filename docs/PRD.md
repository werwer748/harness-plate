# PRD: harness-plate

## 목표
에이전트가 어떤 도구로 일하든 같은 규격(단계 순서, 기록 위치와 형식, 통과 조건)으로 작업하게 하는 하네스 "레일"을 만든다(ADR-004). 강제로 막을 실패는 둘이다: 긴 세션의 컨텍스트 팽창, 검증 없는 완료 선언(ADR-003).

## 사용자
개인용이다(가정으로 둔 것). 프로젝트에 플러그인으로 설치하고, 그 프로젝트의 모든 작업을 하네스의 파이프라인으로 진행한다(ADR-003, ADR-005).

## 핵심 기능
단계별로 하나씩 완성한다(ADR-002).
1. 셋업: 프로젝트에 하네스 문서의 위치 기준을 세운다. 1단계에서 만들었다.
2. 맥락: 스캔과 질문 라운드로 맥락 문서를 채운다. 추측으로 적지 않는다. 2단계에서 만들었다.
3. 계획: 요청 하나를 작업으로 계획해 phase로 나눈 `plan.md`로 남긴다. 추측으로 정하지 않고 묻는다. 3단계에서 만들었다.
4. 실행: 계획이 정한 phase마다 새 컨텍스트의 에이전트가 수행하고 `phase-N.md`로 기록을 남긴다. 만들기 전이다.
5. 검증: 검증 없는 완료 선언을 막고 `verify.md`로 기록을 남긴다. 만들기 전이다.

4~5단계의 세부는 각 단계를 만들기 전에 질문 라운드에서 정한다.

## 범위 밖
- 파이프라인을 건너뛰는 예외 경로. 예외 없이 모든 작업이 파이프라인을 거친다(ADR-003).
- 옛 plate v0.3.0의 결정과 장치를 이어받는 것. 완전히 새로 시작한다(ADR-001).
- superpowers를 설치해 기대는 것. 기법만 가져온다(ADR-005).
- README, CHANGELOG 같은 일반 문서의 위치 관리. 위치 규칙은 하네스 기록에만 적용한다(ADR-006).
- 여러 파일로 나뉜 기존 문서를 하나로 합치는 것. 지도에 경로만 적는다(ADR-008).
- v1.0 전에 다른 도구(Codex, Grok Build)에서 같은 결과를 확인하는 것. 완성 판정은 Claude Code로만 하고, 다른 도구로 넓히는 일은 v1.0 뒤에 한다(ADR-018).
