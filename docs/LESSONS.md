# 회고에서 배운 것

## 프로젝트에서 배운 것
- (004-context-rules, phase 1) `phase-1.md`의 기록으로는 자동 모드에서 띄운 수행 넷이 `plugins/plate/skills/context/SKILL.md`의 편집에서 막혔고 다섯째 수행에서 풀렸다. 무엇이 달라져 풀렸는지는 기록에 없고, 이 사실은 `docs/TOOLS.md`에도 없다. Phase 2의 넷째 TODO도 같은 파일을 고칠 수 있다.
- (004-context-rules, phase 1) ADR-013의 "없다고 답한 칸은 "없음"으로 적는다"는 이제 줄 전체가 칸일 때만 그대로다. 문장 중간에 있는 칸은 이어지는 문장으로 적는다(context 스킬 본문의 74번 줄). 이 갈림은 이 작업의 결정과 스킬 본문에만 있고 `docs/ADR.md`에는 없다.
- (004-context-rules, phase 2) 완료 조건 4의 확인은 `~/plate-rail-test/ctx-cells`의 커밋하지 않은 변경과 `~/plate-rail-test/logs/ctx-cells-*.jsonl`을 본다. 작업 전체를 검증하기 전에 그 폴더를 되돌리거나 같은 로그 이름으로 다시 돌리면 결과가 바뀐다(`run.sh`는 `logs/<로그 이름>.jsonl`을 덮어쓴다).

## 하네스의 문제점
- (004-context-rules, phase 1) plan 스킬의 "phase를 나누는 기준" 2(머리와 그 phase의 파일만 읽고 할 수 있다): "줄 전체가 칸"에 항목 이름 뒤에 칸만 있는 줄(`- **이유**: {확인 필요}`)이 드는지가 머리와 `phase-1.md`에 없고 `phase-2.md`의 첫 TODO("줄 전체가 칸인 것 스물하나")에만 드러나 있다. 수행한 쪽은 그 파일을 읽지 못해 풀어서 본문에 적었다. 풀이는 `phase-2.md`의 셈과 맞는다(커밋 `7c37c9b`의 `docs/ADR.md`에 그런 줄이 스물하나, 문장 중간의 칸이 여섯이다).
- (004-context-rules, phase 1) 계획(`plan.md`의 완료 조건 2): 세 가지에 "답을 받은 갈래는 적는다"가 없는데 완료 조건 4의 닫힌 칸 확인(`뺀 이유는 .*잘못된 작업의 기록`)은 그것을 기대한다. 수행한 쪽이 본문에 한 문장을 더했다.
- (004-context-rules, phase 1) 계획(`phase-1.md`의 읽을 것): 시험 문서(커밋 `7c37c9b`의 `docs/ADR.md`)가 없다. 그 문서에서 문장 중간의 칸 여섯은 모두 줄 끝에 있고 칸 뒤에 마침표가 없어서, 결정의 예(`멈춘 이유는 없다.`)의 마침표가 칸 자리의 글에 든다는 것은 그 문서를 봐야 알 수 있다.
- (004-context-rules, phase 1) run 스킬의 3번("막힘"이면 다시 맡길지 멈출지 묻는다): 막힌 까닭을 가르지 않는다. 이 phase는 같은 파일의 편집이 권한에 막힌 수행이 넷 이어졌다. 띄워진 에이전트는 자기 권한을 바꿀 수 없어 까닭이 권한이면 다시 맡겨도 같고, 계획과 phase 스킬에도 phase가 필요로 하는 권한을 적는 자리가 없다.
- (004-context-rules, phase 1) phase 스킬의 4번(이미 있는 기록은 지금 상태로 고쳐 쓰고 "하네스에서 걸린 것"의 줄만 남긴다): 첫 수행이 막힌 곳과 까닭을 적은 줄이 지금 파일에 없다. "하네스에서 걸린 것"의 둘째 줄은 "같은 편집이 같은 까닭으로 막혔다"인데 가리키는 줄이 없고 "남은 것"은 "없음"이다. 막힌 수행은 커밋하지 않아(5번) git 이력에도 남지 않는다.
- (004-context-rules, phase 2) 계획(완료 조건 4의 "저장소 밖" 확인): 시험 폴더에 대응하는 메모를 두지 않아(머리의 범위 밖) 실패할 수 없는 쪽에 가깝다. 절대 규칙 5의 둘째 갈래(세션에 실린 저장소 밖의 내용을 근거로 쓰지 않는다)는 실제 실행으로 확인되지 않고 본문의 글(완료 조건 3)로만 확인됐다. 확인 명령도 `calls.py`가 보이는 앞 300자만 훑어서, 입력 전체는 따로 훑어야 했다.
- (004-context-rules, phase 2) 계획(같은 확인): 저장소 밖의 경로만 보므로 context 스킬 2번 절의 "아래 목록만 읽는다"에서 벗어난 저장소 안의 읽기는 잡지 않는다. 이번 1턴은 목록에 없는 `CLAUDE.md`를 열었고, 폴더 목록을 한 단계 아래보다 깊게 봤다(`find .claude-plugin .agents plugins -maxdepth 3`, `ls docs/tasks`).
- (004-context-rules, phase 2) context 스킬 "답을 적는 규칙"의 문장 중간 칸 규칙과 여럿을 묻는 칸 규칙이 한 칸에 겹칠 때: 칸 앞의 글이 두 갈래를 묶어 "…뺀 이유는"으로 끝나므로 갈래를 칸 안에서 "앞의 것은 {확인 필요}, 뒤의 것은 …"으로 나눠야 했다. 본문에 이때의 꼴이 없어 실행한 쪽이 꼴을 정하고 초안에서 고칠 곳으로 물었다.
- (004-context-rules, phase 2) context 스킬 3번의 4("문서의 초안 전체를 보여 주고 승인받는다"): 2턴의 초안은 바뀌는 세 줄의 표와 함께 문서를 보였지만 ADR-016~020의 바뀌지 않는 줄 일부를 "(지금과 같음, 바뀌지 않음)"으로 줄였다(줄였다고 알렸다). 긴 문서에서 바뀌는 곳이 적을 때 무엇까지 보여야 "전체"인지 본문에 없다.
