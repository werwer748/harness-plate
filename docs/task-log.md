# 작업 기록 — 작업당 한 줄

> [구현 규칙](rules.md) "진행 방식" 2번과 [결정 기록](decisions.md)의 측정 수단 결정을 구현한 파일이다. 기호(M4)는 [HANDOFF.md](../HANDOFF.md)의 "재료" 표에 있다.

**막는 실패**: 세션 단위 토큰만 보면 큰 세션이 낭비였는지 필요한 작업이었는지 가를 수 없고, 한 작업을 여러 세션으로 나누면 싸 보인다. 작업 단위로 세션·개입·결함을 묶어 두어야 장치를 유지할지 판단할 수 있다.

**수명**: 하네스가 v1.0이 되면 이 기록은 모두 지운다. 이 파일에 기대는 장치는 만들지 않는다.

**적는 법**
- 작업이 끝나면 한 줄을 더한다. 프로젝트를 가리지 않고 여기에 모은다.
- **세션**: M4가 보여 주는 세션 ID 앞 8자리. 한 작업이 여러 세션에 걸쳤으면 모두 적는다. 토큰과 시간은 옮겨 적지 않고 `session-report.py <프로젝트> --timeline <ID>`로 본다.
- **개입**: 사용자가 방향을 고치거나 다시 시킨 횟수. 처음 요청과, 에이전트가 물은 질문에 답한 것은 세지 않는다.
- **뒤에 발견한 결함**: 완료했다고 한 뒤에 드러난 문제. 없으면 `없음`, 아직 모르면 비워 두고 나중에 고친다.
- **켠 장치**: 기본 흐름에 더해 쓴 것(plan mode, 서브에이전트, `/code-review` 등). 없으면 `없음`.
