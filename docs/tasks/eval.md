**하네스 고칠 거리**
1. 실행이 phase 에이전트를 띄우기 전에 쓰기 권한과 plan 모드를 확인하지 않아, 첫 수행이 쓰기 막힘으로 버려졌다 (근거: 실패 1). 갈래: plate 자체
   - 이슈 제목: run: phase를 맡기기 전에 쓰기 권한과 plan 모드를 확인한다
   - 이슈 본문: tasks 일괄 실행의 첫 phase 수행 에이전트가 파일 쓰기를 두 번 막혀(auto mode 분류기가 plan 모드가 켜진 채라 쓰기를 판정하지 않음) 수행을 버리고 사용자에게 물어 다시 맡겼다. 수행 하나만큼의 토큰과 시간이 되풀이됐다. 원인: run 스킬은 시작할 때 실행 방식만 묻고, 띄울 에이전트가 쓰기를 할 수 있는 권한 상태인지(plan 모드, 권한 모드)를 보지 않는다. 해결책: run의 시작 단계에서 plan 모드가 켜져 있거나 쓰기가 막힐 권한 모드면 첫 에이전트를 띄우기 전에 알리고 바꿀지 묻는다. 확인할 수 없는 도구면 그렇다고 적고 잇는다. 근거: `cleanup`, `8fca125` `docs/tasks/001-cleanup-skill/done-phase-1.md`, `docs/tasks/RUNLOG.md`의 멈춤 줄
2. 계획의 결정이 뒤 phase가 정할 산출물의 동작(스킬의 명령, 절차의 차례)을 짐작해 확인 절차를 정해, 확인 phase에서 어긋났다 (근거: 실패 2, 실패 3). 갈래: plate 자체
   - 이슈 제목: plan: 앞 phase가 정할 동작에 기대는 결정은 그 phase의 결과에 대어 보게 한다
   - 이슈 본문: 스킬 본문을 쓰는 phase와 그 스킬을 돌려 보는 phase로 나눈 task에서, 계획의 결정이 돌려 보는 차례("plan은 승인 전에 아무것도 쓰지 않는다")와 허용 목록을 아직 쓰이지 않은 본문의 동작을 짐작해 정했다. 본문이 다른 차례와 다른 명령을 쓰게 되어 확인 phase가 복제본을 되돌리고, 막힌 명령 탓에 일부 판정이 작업 트리로만 이뤄졌다. 원인: plan 스킬은 결정을 계획할 때 확정하게 하고, 뒤 phase의 결정이 앞 phase의 산출물에 기댈 때 그것을 표시하거나 앞 phase의 결과로 다시 보게 하는 규칙이 없다. phase 스킬은 그런 어긋남을 "계획과 달라진 점"으로 넘기고 멈추지 않는다. 해결책: plan에서 뒤 phase의 실행 조건(허용 목록, 차례)이 앞 phase의 산출물에 기대면 그 phase의 TODO 첫 줄에 "앞 phase의 산출물에 대어 조건을 맞춘다"를 두거나, 결정에 "앞 phase의 결과로 정한다"고 적게 한다. 근거: `cleanup`, `59f6a76` `docs/tasks/001-cleanup-skill/done-phase-2.md`
3. phase 수행이 다른 phase의 파일을 읽지 말라는 규칙을 어겼다. 앞 phase의 결과가 필요한 phase의 "읽을 것"에 그 근거가 없었다 (근거: 실패 4, 규칙 준수의 근거). 갈래: plate 자체
   - 이슈 제목: phase: 앞 phase의 기록이 필요하면 읽지 말고 계획의 읽을 것으로 받는다
   - 이슈 본문: 앞 phase가 만든 파일을 돌려 보는 phase의 수행이 시작할 때 앞 phase의 `done-phase-N.md`를 읽었다. 바꾼 것은 없었지만 phase 스킬 1번(다른 phase의 파일을 읽지 않는다)을 어겼다. 원인: phase 스킬은 금지만 적고, 앞 phase의 맥락이 필요할 때 어떻게 할지(멈춤, 계획의 읽을 것)를 적지 않는다. plan 스킬도 뒤 phase의 읽을 것에 앞 phase가 정한 것(달라진 점)을 넘기는 길을 두지 않는다. 해결책: phase 스킬 1번에 "앞 phase의 결과가 필요하면 그 산출물 파일만 읽고, 기록이 필요하면 하네스에서 걸린 것에 적는다"를 더하고, run이 앞 phase의 "계획과 달라진 점"을 다음 phase 에이전트에게 넘기게 한다. 근거: `cleanup`, `59f6a76` `docs/tasks/001-cleanup-skill/done-phase-2.md`
4. review의 테스트 적절성 등급표가 결과물인 마크다운(스킬 본문)을 실행 결과로 판정하는 프로젝트에 맞지 않는다 (근거: 실패 7). 갈래: plate 자체
   - 이슈 제목: review: 결과물인 마크다운의 테스트 적절성을 실행 결과 기록으로도 매길 수 있게 한다
   - 이슈 본문: 바뀐 코드의 거의 전부가 결과물인 마크다운(스킬 본문)인 tasks에서, 그 동작을 헤드리스 실행 기록으로 판정했는데도 테스트 적절성이 "주된 동작의 절반 넘게 테스트가 없다"로 D가 나왔다. 원인: review 스킬의 테스트 적절성 등급표는 실행 코드의 되풀이 가능한 테스트만 센다. 해결책: 결과물인 마크다운에는 맥락 문서가 정한 판정 방식(실행 결과의 기록)을 근거로 쓸 수 있는 칸을 두거나, 되풀이할 수 없는 손 시험은 따로 적고 등급을 한 칸만 낮춘다. 근거: `cleanup`, `23b0e7e` `docs/tasks/review.md`

   - 이슈 본문: task의 마지막 phase 통과 커밋 뒤에 run이 더한 회고와 코드 평가의 `RUNLOG.md` 줄이 커밋되지 않은 채 남아, 다음 phase 수행과 코드 평가가 저마다 그 변경을 커밋에서 빼야 했다. 원인: run 스킬은 `RUNLOG.md`를 phase 통과 커밋과 `plan: NNN-slug 수정` 커밋에만 넣고, 회고 뒤와 tasks 끝 평가 뒤에는 넣는 커밋이 없다. 해결책: 회고 에이전트가 돌아온 뒤와 평가 에이전트가 돌아온 뒤 run이 `RUNLOG.md`만 넣는 커밋을 하거나, 다음 통과 커밋 전까지 미루는 것을 명시하고 다른 스킬이 그 변경을 무시하게 적는다. 근거: `cleanup`, `1d4b54e`, `23b0e7e` `docs/tasks/review.md`, `docs/tasks/002-docs-release/done-phase-1.md`
