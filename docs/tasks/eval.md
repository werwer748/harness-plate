**하네스 고칠 거리**
1. 스킬 본문에 규칙을 더하는 계획이 같은 대상을 다루는 본문의 기존 규칙과 맞물리는지를 점검하지 않고, 완료 조건이 새 글이 있는지만 본다 (근거: 실패 1). 갈래: plate 자체
   - 이슈 제목: plan: 규칙을 더하는 계획이 본문의 기존 규칙과의 충돌을 점검하지 않는다
   - 이슈 본문: 스킬 본문에 새 규칙을 더하는 tasks에서, 더한 규칙(확인은 `HEAD`가 아니라 작업 트리로 적는다)이 같은 절의 기존 규칙(본문 해시를 `HEAD:<경로>`와 견준다)과 서로 다른 것을 시켰고, phase 확인은 새 글이 있는지만 봐 통과시켰고 task 회고에서야 잡혀 고칠 phase가 더해졌다. 원인: plan 스킬의 6번 초안 점검과 적는 규칙 "조건"이 새로 넣을 글의 자리만 보게 하고, 같은 대상(같은 명령, 같은 낱말)을 다루는 본문의 기존 줄을 읽을 것에 넣거나 완료 조건에서 어긋남을 보게 하지 않는다. 해결책: 6번에 "본문에 규칙을 더하거나 바꾸는 task면, 그 규칙이 다루는 대상(명령, 낱말)을 본문에서 찾아 기존 줄을 읽을 것에 적고, 완료 조건에 그 줄들과 새 규칙이 같은 것을 시키는지 보는 확인을 둔다"는 점검을 더한다. 근거: `plan-check-rules`, `fdcb594` `docs/tasks/001-plan-rules/plan.md`, `9b84318` `docs/tasks/001-plan-rules/retro.md` 회고 1
2. 회고의 문제를 고치는 더한 phase의 읽을 것과 TODO가 고칠 글을 그대로 찾는 테스트를 담지 않는다 (근거: 실패 3). 갈래: plate 자체
   - 이슈 제목: run: 고칠 phase가 고칠 글을 지키는 테스트를 읽을 것과 TODO에 넣지 않는다
   - 이슈 본문: 회고의 문제(스킬 본문의 한 줄)를 고치려고 실행이 더한 phase의 읽을 것은 회고 절과 맥락 문서, TODO의 파일은 문제에 적힌 본문 하나뿐이었고, 그 줄의 글을 그대로 찾는 테스트가 빠져 수행이 "계획과 달라진 점"으로 테스트를 고쳤다. 원인: run 스킬 8번의 고칠 phase 규칙("TODO는 … 문제의 글과 그 TODO가 고치는 파일의 경로를 옮긴다", "읽을 것에는 맥락 문서를 모두 넣는다")이 고칠 글을 지키는 테스트를 찾게 하지 않는다. 해결책: 고칠 phase를 쓸 때 문제에 적힌 글(또는 고칠 줄의 핵심 낱말)을 테스트 폴더에서 찾아, 걸리는 테스트를 읽을 것과 그 TODO의 파일 목록에 함께 넣는다는 규칙을 더한다. 근거: `plan-check-rules`, `095d765` `docs/tasks/001-plan-rules/phase-2.md`, `ccb6d7b` `docs/tasks/001-plan-rules/done-phase-2.md` "계획과 달라진 점"
3. 같은 phase의 수행을 다시 맡길 때 앞 에이전트가 무엇을 했고 왜 다시 맡기는지가 어느 기록에도 남지 않는다 (근거: 실패 2). 갈래: plate 자체
   - 이슈 제목: run: 수행을 다시 맡긴 까닭을 RUNLOG에 남기지 않는다
   - 이슈 본문: `RUNLOG.md`에 같은 phase의 수행 줄이 확인 줄 없이 둘 있었고, 첫 줄은 사용량이 모두 `모름`이었으며, 첫 수행이 무엇을 했는지·왜 다시 맡겼는지가 `RUNLOG.md`, phase 기록, 보고 어디에도 없어 회고가 문제로 올렸고 eval의 일관성·효율 계산이 첫 시도를 알 수 없었다. 원인: run 스킬의 `RUNLOG.md` 절이 에이전트 줄의 꼴(역할, task와 phase, 토큰, 도구 호출, 시간)과 사용량이 돌아오지 않은 까닭만 적게 하고, 확인을 거치지 않고 같은 역할을 다시 띄운 자리의 까닭을 적게 하지 않는다. 해결책: 확인이나 회고를 거치지 않고 같은 phase의 수행(또는 같은 역할)을 다시 띄우면 에이전트 줄 끝에 까닭(결과 없이 끝남, 권한으로 막힘 같은 것)을 덧붙이고, 그 자리가 사용자에게 물은 것이면 물은 줄로 남긴다는 규칙을 더한다. 근거: `plan-check-rules`, `22cf8b9`·`44ca558` `docs/tasks/RUNLOG.md`
4. 계획의 TODO가 본문에 넣을 명령의 예(`git stash create`)를 정했지만 그 예가 맞는지 돌려 보는 확인이 통과 조건에 없어 확인과 회고가 통과시켰다 (근거: 실패 4). 갈래: plate 자체
   - 이슈 제목: plan: 스킬 본문에 명령 예를 넣는 TODO에 그 예를 돌려 보는 확인이 없다
   - 이슈 본문: 계획의 TODO가 스킬 본문에 넣을 명령의 예를 정했는데, 그 명령이 규칙이 바라는 결과(추적하지 않는 새 파일까지 든 작업 트리)를 내지 않았다. phase 확인과 task 회고는 글이 있는지만 봐 통과시키고 tasks 끝의 코드 평가가 신뢰성 문제로 찾았다. 원인: plan 스킬의 적는 규칙 "조건"과 6번 초안 점검이 본문에 넣는 명령 예의 동작을 확인하게 하지 않는다. 해결책: 스킬 본문에 명령의 예를 넣는 TODO가 있으면, 그 예를 시험 저장소에서 규칙이 다루는 경우(새 파일, 바뀐 파일 같은 것)로 돌려 보는 확인을 통과 조건에 두거나 예를 빼라는 점검을 6번에 더한다. 근거: `plan-check-rules`, `fdcb594` `docs/tasks/001-plan-rules/phase-1.md` TODO 1, `3d972d1` `docs/tasks/review.md` 평가 1 소스 문제 1

**하네스에서 걸린 것**
- `RUNLOG.md`의 phase 1 첫 수행 줄이 사용량을 모두 `모름`으로 두어 효율의 세 합에서 그 줄을 뺐다. 그래서 되풀이 몫은 원래 맡긴 첫 수행의 몫 없이 두 번째 수행만 되풀이로 세어 계산됐다
- `review.md` 평가 1의 "하네스에서 걸린 것" 둘째 줄(완료 조건 1이 본문을 읽기만 하고 plan의 동작은 `돌리지 않음`)은 계획이 돌리지 않기로 정한 위험이고 회고가 "문제"로 판정하지 않아 실패로 세지 않았다. 첫째 줄(커버리지·중복·보안 도구 없음, ADR-024)은 측정 못함의 까닭이고 ADR로 정해 둔 것이라 이 프로젝트만의 고칠 거리로 두지 않았다
