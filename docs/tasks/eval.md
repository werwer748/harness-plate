**하네스 고칠 거리**
1. plan이 "어떤 줄이 없다"를 grep으로 확인하게 할 때, 그 grep이 부재를 설명하는 줄(테스트 설명, 결정 줄, 변경 기록)에도 걸리는지 초안에서 보게 한다 (근거: 실패 1). 갈래: plate 자체
   - 이슈 제목: plan: "없다"를 보는 grep 확인이 그 부재를 설명하는 줄에 걸린다
   - 이슈 본문: 한 phase의 통과 조건이 "맥락 문서에 이 규칙을 말하는 줄이 없다"를 정규식 grep 0건으로 확인했는데, 같은 phase가 맥락 문서의 테스트 설명 줄에 "이 규칙이 없음"을 적자 grep이 그 설명 줄에 걸렸다. 수행하는 쪽은 설명 글을 돌려 적어 grep을 피했고, 확인과 회고는 이를 잡지 않았다. 원인: plan 스킬의 적는 규칙(**조건**)과 6번 초안 점검이 부재를 grep으로 확인할 때 그 부재를 설명하는 글(테스트 설명, 결정, 변경 기록)도 같은 패턴에 걸리는지 보게 하지 않는다. 해결책: **조건**에 "줄이 없다를 grep으로 볼 때는 규칙을 시키는 글의 꼴(명령형, 동사)로 패턴을 좁히거나, 걸려도 되는 줄(테스트 설명 같은 것)을 확인에 적어 둔다"를 더하고, 6번 초안 점검에 그 항목을 한 줄로 둔다. 근거: `cleanup-fixes`, `0289edb` `docs/tasks/001-tools-doc/done-phase-1.md`
2. plan이 완료 조건의 확인을 "모으면 같다"처럼 명령 없이 적지 않게, 견주는 확인에는 돌릴 명령이나 뽑는 법을 적게 한다 (근거: 실패 4). 갈래: plate 자체
   - 이슈 제목: plan: 견주는 완료 조건 확인에 돌릴 명령이 없어 코드 평가가 스크립트를 짠다
   - 이슈 본문: tasks 머리의 완료 조건 하나가 "보고서의 발견 번호와 세 task 머리 완료 조건의 발견 번호를 모으면 같다"를 확인으로 적었지만 뽑고 견주는 명령이 없어, tasks 끝의 코드 평가가 그 스크립트를 직접 짜 돌렸다. 다른 쪽이 같은 확인을 다르게 짜면 결과가 갈릴 수 있다. 원인: plan 스킬의 적는 규칙(**조건**)이 확인을 "돌릴 명령과 기대"로 적게 하면서, 여러 파일에서 값을 뽑아 견주는 확인은 명령 없이 글로 적는 것을 막지 않는다. 해결책: **조건**에 "값을 뽑아 견주는 확인은 뽑는 명령(또는 패턴)과 견주는 법을 적는다. 적을 수 없으면 읽어서 견줄 자리를 적는다"를 더한다. 근거: `cleanup-fixes`, `8d1356c` `docs/tasks/plan.md`, `0f986e1` `docs/tasks/review.md`
3. eval 본문 `낱말`의 "정해 둔 물음" 정의가 run의 물은 자리를 하나하나 옮겨 적어, run에 물은 자리 `브랜치`가 더해지자 목록이 어긋났다. 목록을 지우고 run의 `RUNLOG.md` 절을 가리키게 하거나, 두 목록이 같은지 테스트로 묶는다 (근거: 하네스에서 걸린 것, `002-run-rules` `done-phase-3.md` 확인 1 "하네스에서 걸린 것"). 갈래: plate 자체
   - 이슈 제목: eval: "정해 둔 물음" 목록이 run의 물은 자리 목록과 어긋난다
   - 이슈 본문: run 스킬의 `RUNLOG.md` 절에 물은 자리 `브랜치`가 더해졌는데, eval 스킬 `낱말`의 "정해 둔 물음"은 물은 자리를 이름으로 늘어놓아 `브랜치`가 없다. "실행 스킬이 목록을 바꾸면 그것을 따른다"는 단서로 셈은 맞지만, 읽는 쪽이 두 목록을 견줘야 한다. 원인: eval 스킬 `낱말`의 "정해 둔 물음" 정의가 run의 목록을 복사해 둔다. 해결책: 이름 목록을 지우고 "물은 자리가 `멈춤`이 아닌 줄"만 남기거나, 두 목록이 같은지 보는 단위 테스트를 더한다. 근거: `cleanup-fixes`, `406464d` `docs/tasks/002-run-rules/done-phase-3.md`
4. 한글이 든 파일을 `python3 - <<'EOF'` heredoc으로 고치면 stdin 인코딩 때문에 깨진다는 도구 동작을 한 줄로 남긴다 (근거: 실패 2). 갈래: 이 프로젝트만
   - 고칠 곳: `docs/TOOLS.md`
   - 해결책: `## Claude Code` 첫 목록에 "한글 본문을 `python3 -` heredoc으로 고치면 `SyntaxError: Non-UTF-8 code`로 깨질 수 있다. Edit 도구나 `python3 -c`, 파일로 쓴 스크립트를 쓴다"를 확인한 버전과 함께 한 줄로 더한다(tasks 결정 (4)의 "다음 계획이 알아야 할 도구 동작")

**하네스에서 걸린 것**
- 이 저장소는 plate 자체라 `FRICTION.md`의 `002-run-rules` 경계 밖 두 줄(댓글로 이슈 올림을 건너뛰는 길, 계획 커밋이 tasks 브랜치에 들지 않는 갈래)은 run 스킬 본문의 문제이면서 이 프로젝트의 소스 문제이기도 하다. eval의 낱말대로 프로젝트 소스의 문제로 보아 실패와 고칠 거리에 넣지 않았다. 코드 평가의 소스 문제에도 없으므로 `docs/BACKLOG.md`로 미룰지 정할 자리가 따로 있어야 한다
- 실패 3(API 오류)은 하네스를 고쳐 막을 수 없어 고칠 거리로 두지 않았다
- `RUNLOG.md`에 `권한` 물음이 두 번 있다(멈춤 뒤 두 번째 답 "auto mode 끔"). 첫 답 뒤에도 쓰기가 막힐 모드로 돌아갔던 것으로 보이나, 기록에 그 까닭이 없어 실패로 세지 않았다
- `review.md` 평가 1 "하네스에서 걸린 것" 첫 줄(커버리지·중복·보안 도구가 없어 측정 못함)은 ADR-024가 도구를 두지 않기로 정한 것이라 이 프로젝트만의 고칠 거리로 두지 않았다
