**하네스 고칠 거리**
1. plan이 수행 쪽이 돌릴 통과 조건을 적을 때 phase 스킬이 커밋 전에 돌리고 phase 파일을 고치는 것(TODO 체크, 기록, 끝의 한 커밋)을 감안하게 한다 (근거: 실패 1, 2, 3, 6). 갈래: plate 자체
   - 이슈 제목: plan: 수행 쪽이 돌릴 통과 조건이 phase 스킬의 커밋 전 확인과 phase 파일 고침을 감안하지 않는다
   - 이슈 본문: 한 tasks의 세 task 모두에서 phase 통과 조건의 "`mktemp -d`에 `git archive HEAD`를 풀어 본문 글을 지우고 테스트가 실패하는지 본다"가 수행 때 돌 수 없었다. phase 스킬은 통과 조건을 돌린 뒤 바꾼 것과 기록을 한 커밋으로 넣으므로 그때의 HEAD에는 그 phase의 변경이 없고, 수행마다 스테이지한 트리, `git stash create`, `rsync` 복사로 저마다 다르게 대신했다. 같은 tasks의 다른 phase에서는 "돌리기 전과 뒤의 원본 `git status --short`가 같다"가 phase 스킬 2번의 TODO 체크가 원본의 `phase-N.md`를 바꾸는 것과 맞물려, "전"을 재지 못하고 추론으로 적었다. 원인: plan 스킬 적는 규칙 "조건"이 통과 조건의 확인은 phase 스킬이 커밋 전에, phase 파일을 고치면서 돌린다는 것을 적지 않는다. 해결책: "조건"에 "phase의 통과 조건은 커밋 전의 작업 트리에서 돈다. `HEAD`를 풀거나 보는 확인은 작업 트리(예: `git stash create`로 얻은 트리)로 적고, 원본이 바뀌지 않았는지 보는 확인은 그 phase의 `phase-N.md`를 빼고 본다"를 더하고, 6번 초안 점검에 수행이 돌릴 확인에 `HEAD`가 있는지 보는 항목을 더한다. 근거: `eval-issues`, `39804cf` `docs/tasks/001-run-rules/done-phase-1.md`, `580f722` `docs/tasks/002-plan-rules/done-phase-1.md`, `2563971` `docs/tasks/003-agent-rules/done-phase-1.md`, `506a73b` `docs/tasks/003-agent-rules/done-phase-2.md`
2. 본문의 글을 지우고 테스트가 실패하는지 보는 확인에 지울 글을 정확히(앞뒤 경계까지) 적고 실패할 테스트를 함께 적게 한다 (근거: 실패 7). 갈래: plate 자체
   - 이슈 제목: plan: 글을 지워 테스트 실패를 보는 확인에 지울 글의 경계와 실패할 테스트가 없다
   - 이슈 본문: tasks 완료 조건의 "본문의 해결 글을 지우고 돌리면 실패한다"가 지울 글을 "#49 해결 글"처럼 이름으로만 가리켜, 코드 평가가 지울 글의 경계(줄 끝의 앞 공백)를 다시 골랐다. phase 확인과 회고는 같은 확인을 지나쳐 tasks 끝에서야 드러났다. 원인: plan 스킬 적는 규칙 "조건"이 이런 꼴의 확인에 지울 글과 기대한 실패를 어떻게 적을지 정하지 않는다. 해결책: "조건"에 "글을 지우거나 바꿔 테스트가 실패하는지 보는 확인은 지울 글을 본문에 있는 그대로 인용하고(줄 하나면 그 줄 전체), 실패할 테스트 이름을 기대로 적는다"를 더한다. 근거: `eval-issues`, `053c464` `docs/tasks/review.md`
3. 뒤 task의 결정이나 TODO가 앞 task가 바꿀 글을 인용하면 바뀐 뒤의 글 그대로 적게 한다. 지금 #52의 해결은 읽을 것에만 걸린다 (근거: 실패 5). 갈래: plate 자체
   - 이슈 제목: plan: 뒤 task의 결정이 앞 task가 바꿀 글을 바뀌기 전 꼴로 덧붙여 적는다
   - 이슈 본문: 한 task의 결정에 적은 장면 프롬프트 "맡기는 글의 세 줄과 표지 줄"이, 앞 task가 이미 표지 줄을 셋째 줄로 넣은 맡기는 글과 겹쳐 네 줄로 읽혔고, 수행이 묻지 않고 한쪽으로 읽어 돌렸다. 원인: plan 스킬 적는 규칙 "phase의 파일"의 읽을 것 항목은 앞 task의 변경을 절 이름과 바뀐 글로 가리키게 하지만, task 머리의 결정과 phase의 TODO가 앞 task가 바꿀 글을 인용할 때의 규칙은 없다. 해결책: 적는 규칙에 "결정이나 TODO가 앞 task가 바꿀 글을 인용하면 바뀐 뒤의 글 그대로 적고, 앞 task가 더할 줄을 다시 덧붙이지 않는다"를 더하고, 6번 초안 점검에 task 사이에 같은 글을 바꾸거나 인용하는 곳이 맞물리는지 보는 항목을 더한다. 근거: `eval-issues`, `506a73b` `docs/tasks/003-agent-rules/done-phase-2.md`

**하네스에서 걸린 것**
- 실패 3은 수행이 기록의 "하네스에서 걸린 것"이 아니라 "계획과 달라진 점"에 적었다. 2번 표의 모으는 곳에 "계획과 달라진 점"이 없어 `FRICTION.md`(task의 회고)로 모았지만, 수행이 스스로 적은 것이라 잡힌 곳은 낱말 "잡힌 곳"의 정의대로 그 자리로 셌다
- `FRICTION.md` 2·3·5행은 #49를 고치기 전의 retro가 확인 절의 `남은 것:` 줄을 회고 "문제 아님" 판정과 상관없이 `문제`로 옮긴 것이다. eval 2번의 `남은 것:` 규칙대로 회고가 "문제"로 판정하지 않았으므로 실패로 세지 않았다. 이 꼴은 이 tasks의 003이 고친 retro 5번으로 다시 나지 않아 고칠 거리에 넣지 않았다
- 실패 4는 run 세션이 띄울 때의 본문으로 맡기는 데서 온 것이고, 이 tasks가 run의 맡기는 글에 표지 줄을 넣어 다음 tasks부터는 다시 나지 않으므로 고칠 거리에 넣지 않았다
