**하네스 고칠 거리**
1. plan의 초안 점검에 `-`로 시작하는 패턴을 `-e`(또는 `--`)로 넘기는지 보는 줄을 더한다 (근거: 실패 1). 갈래: plate 자체
   - 이슈 제목: plan: `-`로 시작하는 패턴을 넘기는 확인 명령이 옵션으로 읽혀 돌지 않는다
   - 이슈 본문: tasks 머리와 task 머리의 완료 조건 확인에 `grep -F '- …'`처럼 `-`로 시작하는 패턴을 `-e`나 `--` 없이 적었고, grep이 이것을 옵션으로 읽어 종료 코드 2로 돌지 않았다. tasks 끝의 코드 평가가 적힌 그대로 돌려 완료 조건의 확인 실패로 찾았고 기능 적합성이 B로 내려갔다. 원인: plan 스킬의 적는 규칙 "조건"과 6번 "초안을 보여 주기 전에 아래를 본다." 목록이 확인 명령이 적힌 그대로 도는지(인자가 옵션으로 읽히지 않는지)를 보지 않는다. 해결책: 6번 점검에 "확인 명령의 패턴이나 인자가 `-`로 시작하면 `-e`나 `--`로 넘기는지 본다"를 더하고, 적는 규칙 "조건"의 `확인은 돌릴 명령과 기대 결과를 우선한다` 항목에 적힌 그대로 돌아야 한다는 것을 잇고, 그 글의 테스트를 더한다. 근거: `compare-checks`, `7f179c6` `docs/tasks/plan.md`, `0ea2a6d` `docs/tasks/review.md`
2. phase와 check(그리고 retro)가 계획의 확인 명령을 적힌 그대로 돌리지 않고 고쳐 돌렸으면 그 사실을 기록에 남기게 한다 (근거: 실패 1, 규칙 준수의 근거). 갈래: plate 자체
   - 이슈 제목: phase·check·retro: 확인 명령을 고쳐 돌리고도 기록에 남기지 않아 틀린 명령이 tasks 끝까지 간다
   - 이슈 본문: 통과 조건의 확인 명령이 적힌 그대로는 돌지 않았는데 수행은 `--`를 넣어 돌리고 "계획과 달라진 점: 없음"으로 적었고, 확인과 회고도 같은 고친 명령으로 통과시켰다. 틀린 명령이 tasks 끝의 코드 평가에서야 드러났다. 원인: phase 스킬의 "그 밖의 차이 … '계획과 달라진 점'에 적는다"가 확인 명령을 고쳐 돌린 경우를 들지 않고, check와 retro 스킬은 적힌 명령이 그대로 돌지 않을 때 실패로 볼지, 고쳐 돌리고 "하네스에서 걸린 것"에 적을지를 정하지 않는다. 해결책: phase에 "확인 명령을 적힌 그대로 돌리지 못해 고쳐 돌렸으면 고친 명령과 까닭을 '계획과 달라진 점'과 '하네스에서 걸린 것'에 적는다"를 더하고, check·retro에 "적힌 그대로 돌리고, 돌지 않아 고쳐 돌렸으면 '하네스에서 걸린 것'에 적는다"를 더한다. 근거: `compare-checks`, `0c8f9ef`·`3504098` `docs/tasks/001-compare-checks/done-phase-1.md`, `517a292` `docs/tasks/001-compare-checks/retro.md`
3. review의 테스트 적절성에서 바뀐 실행 코드가 결과물인 마크다운의 글을 보는 테스트 파일뿐인 경우 어느 등급표를 쓸지 정한다 (근거: 실패 2). 갈래: plate 자체
   - 이슈 제목: review: 테스트 파일만 실행 코드로 바뀐 tasks의 테스트 적절성 등급표가 정해져 있지 않다
   - 이슈 본문: 결과물인 마크다운(스킬 본문)과 매니페스트 버전 말고는 그 글의 존재를 보는 테스트 파일만 바뀐 tasks에서, 테스트 파일이 실행 코드라 기본 등급표를 써 A가 나왔다. 실제 바뀐 동작(스킬 본문대로 에이전트가 하는지)은 `돌리지 않음`이었다. 원인: review 스킬의 테스트 적절성 표 고르기가 "결과물인 마크다운만 바뀐 경우"와 "실행 코드가 바뀐 경우"만 가르고, 바뀐 실행 코드가 테스트 파일뿐인 경우를 다루지 않는다. 해결책: 바뀐 실행 코드가 테스트 파일뿐이면 결과물인 마크다운만 바뀐 경우의 표를 쓰거나, 그 경우의 칸을 기본 등급표에 더한다. 근거: `compare-checks`, `0ea2a6d` `docs/tasks/review.md`
