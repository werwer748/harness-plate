**하네스 고칠 거리**
1. plan이 읽을 것과 확인에서 파일의 자리를 줄 번호로 가리키는 것을 줄인다: 앞 phase나 앞 task가 고칠 파일은 절 이름으로 가리키고, 줄 번호로 가리킨 확인은 같은 사실을 잇는 이웃 줄까지 덮는지 초안 전에 대어 본다 (근거: 실패 1, 실패 3). 갈래: plate 자체
   - 이슈 제목: plan: 앞 phase가 고칠 파일을 줄 번호로 가리키는 읽을 것과 확인이 어긋난다
   - 이슈 본문: 한 tasks에서 뒤 phase의 읽을 것이 앞 phase가 같은 파일에 줄을 더하기 전의 줄 번호로 적혀 실제 위치와 달랐고, 다른 task의 완료 조건 확인이 맥락 문서를 한 줄 번호로만 가리켜 같은 사실을 잇는 바로 다음 줄이 확인에 들지 않았다(수행이 "남은 것"에 적어 회고가 따로 읽었다). 원인: plan 스킬의 적는 규칙 "phase의 파일"의 읽을 것 줄은 뒤 phase가 앞 phase의 결과를 쓰면 위치를 경로로 적으라고만 하고, 앞 phase가 고칠 파일을 줄 번호로 가리키지 말라는 줄이 없다. 적는 규칙 "조건"에도 줄 번호로 가리킨 확인이 이웃 줄을 덮는지 대어 보라는 줄이 없다. 해결책: "phase의 파일"의 읽을 것 줄과 "조건"에 "앞 phase나 앞 task가 고칠 파일은 줄 번호 대신 절 이름이나 낱말로 가리킨다"를 더하고, 6번의 초안 전 점검에 "줄 번호로 가리킨 읽을 것과 확인이 앞 phase가 고칠 파일을 가리키지 않는지, 같은 사실을 잇는 이웃 줄을 빠뜨리지 않는지 본다"를 더한다. 근거: `eval-fixes`, `466e3ab` `docs/tasks/001-plan-rules/done-phase-2.md`, `cc070c3` `docs/tasks/002-run-review/done-phase-1.md`, `docs/tasks/FRICTION.md`
2. run의 작업 트리의 스킬 줄이 세션에 실린 본문과 작업 트리의 본문이 다를 때 작업 트리 쪽을 따른다고 띄운 에이전트에게 말하게 한다 (근거: 실패 4). 갈래: plate 자체
   - 이슈 제목: run: 작업 트리의 스킬 줄이 두 본문 가운데 어느 쪽을 따를지 말하지 않는다
   - 이슈 본문: run이 tasks가 바꾼 스킬을 맡길 때 맡기는 글에 "plate의 {스킬}을 불러 그 절차를 따른다"와 "작업 트리의 {경로}를 읽어 그 절차를 따른다"가 함께 들어간다. 이 줄이 붙는 때는 바로 두 본문이 다를 수 있는 때인데, 다르면 어느 쪽을 따르는지가 띄운 에이전트가 받는 글에 없어 고치기 전의 절차로 돌 수 있다. phase의 확인과 task 회고는 이것을 통과시켰고 코드 평가가 신뢰성 문제로 찾았으며, 코드 평가 자신도 이 자리에서 모호함을 겪었다. 원인: run 스킬의 낱말 "작업 트리의 스킬 줄"이 작업 트리 쪽이 이기는 이유를 run 본문에만 적고, 줄의 글에는 넣지 않았다. 해결책: 줄의 꼴을 "작업 트리의 {경로}를 읽어 그 절차를 따른다. 불러 온 스킬의 본문과 다르면 이 파일을 따른다."로 바꾼다. 근거: `eval-fixes`, `cc070c3` `plugins/plate/skills/run/SKILL.md`, `docs/tasks/review.md` 평가 1의 소스 문제 1
3. review의 테스트 적절성 등급표에 결과물인 마크다운만 바꾸고 tasks 결정이 본문을 읽는 확인을 정한 경우를 댈 칸을 둔다 (근거: 실패 5). 갈래: plate 자체
   - 이슈 제목: review: 결과물인 마크다운만 바꾼 tasks의 테스트 적절성이 늘 E가 된다
   - 이슈 본문: 결과물인 마크다운 절로 스킬 본문 같은 `.md`를 바뀐 코드 파일에 넣으면서, 그런 파일만 바꾸는 tasks는 시험할 실행 경로가 없어 테스트 적절성이 늘 E가 된다. tasks 결정이 "확인은 본문을 읽어 한다"고 정하고 완료 조건의 읽는 확인이 모두 통과해도 등급표에 그것을 댈 칸이 없어, 등급이 하네스를 고칠지 정하는 데 쓰이지 못한다. 원인: review 스킬 5번 등급표의 테스트 적절성 칸이 실행되는 코드의 테스트만 본다. 해결책: 바뀐 코드 파일이 결과물인 마크다운뿐이면 테스트 적절성을 "판단 못함 — 시험할 실행 경로가 없다"로 두거나, 완료 조건의 읽는 확인이 바뀐 규칙마다 있는지를 근거로 매기는 칸을 더한다. 근거: `eval-fixes`, `1efe490` `docs/tasks/review.md` 평가 1의 테스트 적절성과 "하네스에서 걸린 것"

   - 이슈 제목: eval: run이 정해 둔 "커밋하지 않은 변경" 물음을 멈춤으로 센다
   - 이슈 본문: run은 시작 조건(1번)에서 커밋하지 않은 변경이 있으면 진행할지 묻고 RUNLOG의 물은 자리 `커밋하지 않은 변경`으로 적는데, eval 스킬의 낱말 "정해 둔 물음"은 실행 방식, task 회고 뒤의 물음, 고칠지, PR을 열지, 합칠지만 들어 이 줄을 멈춤으로 센다. 그래서 하네스가 막히지 않았는데도 사람 개입률이 오르고(이번에는 A 대신 C), 실패로도 하나 더 잡힌다. 원인: eval 스킬의 낱말 "정해 둔 물음"과 run 스킬의 RUNLOG 물은 자리 목록(`실행 방식`, `커밋하지 않은 변경`, `고칠 phase`, `다음 task`, `멈춤`, `고칠지`)이 맞지 않는다. 해결책: eval의 "정해 둔 물음"을 run의 물은 자리로 정의해 `멈춤` 말고는 모두 정해 둔 물음으로 보고, `고칠 phase`와 `다음 task`도 함께 넣는다. 근거: `eval-fixes`, `3c27142` `docs/tasks/RUNLOG.md` 1줄

   - 이슈 본문: plan은 브랜치를 바꾸지 않고 지금 브랜치에 커밋하므로, 기본 브랜치에서 계획하면 계획의 커밋이 로컬 기본 브랜치에만 들어가 원격보다 앞선다. run은 그 뒤에 tasks 브랜치를 만들고, 코드 평가는 갈라진 곳을 로컬과 원격 가운데 어느 것으로 잡을지 스스로 골라야 했다(이번에는 계획의 커밋이 `docs/tasks/`만 바꿔 결과가 같았다). 원인: plan 스킬 절대 규칙 4(브랜치를 바꾸지 않는다)와 run의 "tasks/<이름> 브랜치" 시작, review의 낱말 "갈라진 곳"이 계획의 커밋이 기본 브랜치에만 있는 경우를 다루지 않는다. 해결책: review의 낱말 "갈라진 곳"과 run의 낱말 "작업 트리의 스킬 줄"에 갈라진 곳을 로컬 기본 브랜치의 `git merge-base <기본 브랜치> HEAD`로 잡는다고 적고, run이 tasks 브랜치를 만들 때 계획의 커밋이 로컬 기본 브랜치에만 있으면 그것을 알리고 기본 브랜치를 원격으로 되돌릴지 묻는 자리를 둔다. 근거: `eval-fixes`, `c71d3ac`, `docs/tasks/review.md` 평가 1의 "하네스에서 걸린 것"
