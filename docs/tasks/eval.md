**하네스 고칠 거리**
1. plan이 통과 조건과 읽을 것에 적는 사실과 명령을 지금 저장소에 대어 보지 않은 채 쓴다: 읽기만 하는 확인 명령을 돌려 보지 않았고(plan 절대 규칙 3이 이미 시킨다), 읽을 것의 줄 수를 같은 줄의 되풀이 없이 셌고, 상태를 남기는 확인이 새 시험 레포에서 도는지 적지 않았다 (근거: 실패 1, 2, 3). 갈래: plate 자체
   - 기준: eval에만 — 피해를 넘지 않는다. 셋 모두 수행이 그 자리에서 알아채고 적힌 결과대로 다시 돌리거나 고쳐 통과했고, 확인을 지나간 결함, 다시 수행, 멈춤, 사람 개입이 없었다. 실패 3은 수행이 계획 밖의 줄을 더했으나 "계획과 달라진 점"에 적었고 확인과 회고가 그 변경을 보고 통과시켰다
2. 완료 조건과 통과 조건의 확인이 입력 하나의 예만 돌려, 같은 이름이 tasks마다 되풀이되는 경우(지난 tasks의 같은 task 이름·phase 번호의 커밋)와 입력이 여럿인 경우(새 파일 둘 이상)의 결함이 확인과 회고를 지나 코드 평가에서야 잡혔다. 회고는 기록의 "남은 것"이 그 꼴을 적었는데도 "결정이 정한 대로"로 문제 아님 판정했다 (근거: 실패 4, 5). 갈래: plate 자체
   - 기준: 넘음 — 피해: 결함 둘이 phase의 확인과 task의 회고를 지나갔다. 일반성: plate는 tasks가 끝나면 `docs/tasks/`를 비우고 다음 tasks가 `001-…`부터 다시 쓰므로 task 이름·phase 번호로 커밋이나 파일을 찾는 동작은 어느 프로젝트에서도 되풀이된 이름을 만나고, 파일·입력이 여럿인 경우는 평범한 tasks에서 흔하다. 고침의 꼴: "확인은 그 동작이 다루는 식별자가 tasks를 넘어 되풀이되는 경우와 입력이 여럿인 경우를 한 번씩 덮는다"와 "결정이 정한 동작이라도 그런 경우에 목표를 해치면 '결정대로'로 넘기지 않고 경계 밖으로 올린다"는 원리로 적을 수 있다
   - 처리: 규칙을 더하거나 고친다 — plan의 "스킬·훅·양식의 동작을 바꾸는 완료 조건" 규칙은 명령 예에만 "규칙이 다루는 경우마다" 돌리라고 하고 동작 일반의 되풀이·여럿 경우는 말하지 않으며, retro의 "남은 것" 판정은 결정이 정한 동작이면 문제 아님으로 닫게 둔다. 같은 꼴이 확인을 지나면 대상 프로젝트의 훅·스킬 동작이 조용히 틀린 채 나가므로 고치는 값이 더 작다
   - 문턱: 넘음 — 실패 4, 5(잡힌 곳 tasks 끝)
   - 이슈 제목: plan과 retro가 되풀이되는 이름과 여러 입력의 경우를 확인하지 않아 결함이 코드 평가까지 간다
   - 이슈 본문: tasks 끝의 코드 평가가 신뢰성 문제 둘을 찾았다. 하나는 tasks마다 되풀이되는 식별자(task 폴더 이름과 phase 번호로 된 커밋 제목)로 전체 git 역사를 찾아, 지난 tasks의 같은 이름 커밋 때문에 이번 phase의 판정이 틀리는 동작이다. 다른 하나는 파일 하나의 경우만 돌려 본 명령 예가 파일이 여럿일 때 깨지는 것이다. 둘 다 phase의 확인과 task 회고를 통과했다. 첫째는 수행 기록의 "남은 것"이 그 꼴을 적었는데 회고가 "결정이 정한 대로"라며 문제 아님으로 판정했다. 원인: plan 스킬의 "스킬·훅·양식의 동작을 바꾸는 완료 조건" 규칙이 "규칙이 다루는 경우마다 돌린다"를 본문의 명령 예에만 대고, 동작이 쓰는 식별자가 tasks를 넘어 되풀이되는 경우나 입력이 여럿인 경우를 확인에 넣으라고 하지 않는다. retro 스킬의 4번(남은 것 판정)은 결정이나 완료 조건이 정한 동작이면 문제 아님으로 닫게 두어, 결정 자체의 빈틈을 경계 밖으로 올리지 않는다. 해결책: plan의 그 규칙을 동작 일반으로 넓혀, 동작이 이름·번호로 무언가를 찾으면 지난 tasks의 같은 이름이 남은 경우를, 입력(파일, 줄, 항목)을 받으면 둘 이상인 경우를 확인 하나씩으로 덮게 한다. retro 4번에 "결정이 정한 동작이라도 되풀이된 이름이나 여러 입력에서 목표를 해치면 문제 아님으로 닫지 않고 `FRICTION.md`에 경계 밖으로 적는다"를 더한다. 근거: `cleanup-findings`, `acd4985` `docs/tasks/001-hook-fixes/done-phase-2.md`, `edfd104` `docs/tasks/001-hook-fixes/retro.md`, `1a788b8` `docs/tasks/003-skill-fixes/done-phase-3.md`, `24dd38e` `docs/tasks/review.md`
