**하네스 고칠 거리**
1. 멈춘 phase를 계획 수정 뒤에 다시 수행할 때 앞 시도의 기록을 어떻게 남길지 정하고, 멈춘 수행의 기록이 계획 수정 커밋에 섞이지 않게 한다 (근거: 실패 2, 규칙 준수의 근거 `bb1c0c6`). 갈래: plate 자체
   - 이슈 제목: 계획 수정 뒤 다시 수행하는 phase의 앞 시도 기록이 지워지고 계획 수정 커밋에 섞인다
   - 이슈 본문: 계획이 틀림으로 멈춘 phase를 계획 수정 뒤에 다시 수행하면, `phase-N.md`의 TODO는 비어 있는데 첫 시도의 기록 다섯 절이 남아 있어 수행 쪽이 다섯 절을 고쳐 쓰고 첫 시도를 한 줄로 줄였다. 멈춘 수행은 자기 기록을 커밋하지 않아, 그 기록이 `plan: NNN-slug 수정` 커밋에 계획 다섯 항목과 함께 들어갔다. 원인: phase 스킬에 멈출 때 기록을 커밋하는 규칙과 다시 수행할 때 앞 기록을 다루는 규칙이 없고, run 스킬의 계획 수정 절과 plan 스킬이 고칠 `phase-N.md`의 남은 기록을 어떻게 할지 정하지 않는다. 해결책: phase 스킬은 멈출 때도 기록을 `NNN-slug: phase N 멈춤`으로 커밋한다. run 스킬은 계획을 고칠 때 앞 시도의 기록 다섯 절을 `## 시도 1` 같은 절 아래로 옮겨 두고, 다시 수행하는 쪽은 그 절을 고치지 않고 새 기록을 쓴다. 근거: `workflow-guard`, `bb1c0c6` `docs/tasks/001-ruleset-probe/done-phase-2.md`
2. 계획과 기록이 기대는 근거를 저장소 안에 둔다 (근거: 실패 3). 갈래: plate 자체
   - 이슈 제목: 계획 수정의 근거가 세션 scratchpad에만 있어 세션 뒤에 다시 볼 수 없다
   - 이슈 본문: 멈춤을 푸는 해결 에이전트가 조사한 기록과 API 응답을 세션 scratchpad에 두었고, 고친 계획의 "읽을 것"과 맥락 문서의 근거가 그 경로를 가리켰다. 세션이 끝나면 사라져 회고와 eval이 근거를 다시 볼 수 없다. 원인: run 스킬의 멈춤 처리와 plan 스킬의 "읽을 것" 규칙이 저장소 밖 경로를 막지 않는다. 해결책: plan 스킬은 "읽을 것"에 저장소 안 경로만 적게 하고, run 스킬은 멈춤을 풀며 나온 조사 기록을 `docs/tasks/` 아래(예: task 폴더의 `investigation.md`, 문서 지도의 tasks 행에 더함)에 커밋하게 한다. 근거: `workflow-guard`, `bb1c0c6` `docs/tasks/001-ruleset-probe/done-phase-2.md`, `docs/tasks/FRICTION.md`
3. 계획의 확인이 같은 task가 고치는 문서를 줄 번호 대신 항목 이름으로 가리키게 한다 (근거: 실패 5). 갈래: plate 자체
   - 이슈 제목: 계획의 확인이 고쳐질 문서를 줄 번호로 가리켜 확인과 회고가 옛 파일과 견줘야 한다
   - 이슈 본문: task가 고치는 맥락 문서를 완료 조건과 통과 조건이 "17·20·23줄(계획 커밋 시점 기준)"처럼 줄 번호로 가리켜, 확인과 회고가 계획 커밋의 파일을 꺼내 같은 항목인지부터 봐야 했다. 원인: plan 스킬의 확인 글 규칙이 위치를 가리키는 꼴을 정하지 않는다. 해결책: plan 스킬에 "그 task나 앞 task가 고치는 파일은 줄 번호가 아니라 절 이름이나 항목 이름으로 가리킨다"를 더한다. 근거: `workflow-guard`, `807bfc6` `docs/tasks/002-guard-setup/plan.md`, `docs/tasks/002-guard-setup/retro.md`
4. 수행이 "남은 것"에 적은 위험을 확인과 회고가 판정에서 다루게 한다 (근거: 실패 6). 갈래: plate 자체
