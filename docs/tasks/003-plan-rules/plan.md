# plan의 TODO·조건·경계 규칙을 고친다

## 목표
plan이 규칙이나 동작을 바꾸는 TODO에 그것을 적은 맥락 문서의 줄을 모두 가리키고, ADR을 더하는 TODO에 결정과 이유를 적는다(#7). 완료 조건의 절마다 그것을 보는 확인이 있는지 초안 전에 대어 보고, 여러 대상이나 경우를 보는 확인에는 읽는 법과 경우마다의 기대를 적는다(#6). 입력의 꼴이 열린 기능이면 약속하는 꼴의 경계를 결정으로 묻는다(#5).

## 범위 밖
- retro가 경계 밖의 꼴을 다루는 규칙. `004-retro-phase`에서 한다
- plan의 절차 순서(0~9번)와 계획 파일의 양식을 바꾸는 것

## 완료 조건
1. tasks 완료 조건 9가 참이다.
   - 확인: `plugins/plate/skills/plan/SKILL.md`를 읽어 셋을 하나씩 찾는다. 첫째, 입력의 꼴이 열린 기능(셸 글이나 사용자 글을 읽는 것)이면 약속하는 꼴의 경계를 결정으로 묻는 규칙. 둘째, 초안 전에 완료 조건의 절마다 확인을 대어 보는 규칙과, 여러 대상이나 경우를 보는 확인에 대상마다인지 합쳐서인지와 경우마다의 기대를 적는 규칙. 셋째, 규칙이나 동작을 바꾸는 TODO가 그것을 적은 맥락 문서의 줄을 모두 가리키는 규칙과, ADR을 더하는 TODO에 결정과 이유를 적는 규칙
2. `docs/ARCHITECTURE.md`와 `docs/PRD.md`에서 plan을 적은 줄이 바뀐 plan과 어긋나지 않는다.
   - 확인: `grep -n '계획' docs/ARCHITECTURE.md docs/PRD.md`가 낸 줄을 하나씩 읽어 바뀐 plan과 어긋나는 줄이 없다
