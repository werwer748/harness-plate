# plan 본문의 정리 점검 발견을 고친다

## 목표
정리 점검 `docs/cleanup/2026-10-28.md`에서 plan 쪽으로 넘긴 발견 9건이 plan 본문과 그 테스트, 맥락 문서에서 고쳐진다. 결과는 세 가지다.
- 진행 중인 tasks에 task를 더하는 경우가 평가를 건너뛰지 않고, 앞 task가 바꿀 글을 알 수 있다.
- 6번 목록과 적는 규칙이 되풀이 없이 읽힌다.
- 기존 규칙이 기존 줄과의 충돌과 명령 예의 동작까지 덮고, run과 나눠 가진 정의가 어긋나면 테스트가 잡는다.

## 범위 밖
- 6번에 초안 점검 줄을 새로 더하는 것(tasks 결정: #59·#62는 기존 규칙만 넓힌다)
- 보고서에서 버린 유지보수성-1, 유지보수성-3(6번 점검과 적는 규칙의 짝, 승인 규칙의 되풀이는 그대로 둔다)
- 맥락 문서를 모두 읽는 2번의 규칙을 바꾸는 것
- 001-tools-doc이 **조건**에 더한 시험 실행 기록 규칙을 고치는 것
- run 본문을 고치는 것. 유지보수성-6의 복사된 정의는 두 본문 그대로 두고 테스트만 더한다

## 완료 조건
1. 더하는 경우가 이렇게 바뀐다. (신뢰성-4, 신뢰성-5)
   - 1번은 `docs/tasks/review.md`나 `docs/tasks/eval.md`가 있으면 tasks 끝의 평가가 이미 시작됐다고 알리고, task로 더할지 묻지 않고 아무것도 쓰지 않고 끝난다.
   - 더하는 경우에는 이미 있는 task 폴더마다 task 머리(`plan.md`)를 읽고, phase 파일은 읽지 않는다. 그래서 앞 task가 바꿀 글을 바뀐 뒤의 꼴로 인용하라는 규칙(**결정**과 6번의 task 사이 맞물림 점검)을 따를 수 있다.
   - 확인: `python3 -m unittest discover -s tests`가 `OK`로 끝난다. 그 안에 다음을 단언하는 테스트가 있다:
     - 1번에 `review.md`·`eval.md`가 있을 때 더하지 않고 끝나는 글이 있다
     - 1번의 더하는 경우에 task 머리를 읽는다는 글이 있고 "내용은 읽지 않는다"가 없다
     - 기존 `test_57_quote_earlier_task_text_as_changed`가 그대로 통과한다
   - 확인: `docs/ARCHITECTURE.md` `## 데이터 흐름`의 계획 단계 줄("tasks가 진행 중이면 새 요청을 지금 tasks에 task로 더할지 묻는다")을 읽는다. 더할지 묻는 갈래와, 평가가 시작된 tasks면 더하지 않는 갈래가 둘 다 있다
   - 돌리지 않음: plan은 사용자에게 묻고 승인받아야 쓰는 스킬이라 더하는 경우를 임시 폴더에서 끝까지 돌릴 수 없다
2. 6번 목록과 적는 규칙이 되풀이 없이 읽힌다. (유지보수성-2, 유지보수성-4, 유지보수성-5, 유지보수성-12)
   - 6번 목록이 둘로 나뉜다. 하나는 초안을 보여 주기 전의 점검이고 머리말 "초안을 보여 주기 전에"를 목록 머리에 한 번 적는다. 다른 하나는 초안을 보여 준 뒤의 규칙(미리 받은 승인, 고칠 곳, 분명하지 않은 답, 마지막 task까지 7번으로 가지 않음)이다.
   - `**그 밖**` 절이 지워지고, 2번은 지도에 적힌 경로의 문서를 읽는다는 글을 지킨다.
   - **조건**의 남은 결과 항목은 본문 해시로 견주는 규칙과 커밋 시각을 쓰지 않는 까닭만 남긴다. `HEAD`에 그 phase의 변경이 없다는 설명은 다시 하지 않고, 작업 트리에서 돈다는 항목을 가리킨다.
   - 양식을 읽는 법 세 문장은 낱말 절에 한 번 있고, `## 계획 파일의 양식`은 그 낱말을 가리키는 짧은 줄을 남긴다.
   - 확인: `python3 -m unittest discover -s tests`가 `OK`로 끝난다. 그 안에 다음을 단언하는 테스트가 있다:
     - 6번의 앞 목록 머리에 "초안을 보여 주기 전에"가 한 번 있고, 두 목록이 나뉘어 있다
     - plan 본문에 `**그 밖**`이 없다
     - 남은 결과 항목에 `아래 규칙대로 통과 조건은 커밋 전의 작업 트리에서 돌아`가 없다
     - "블록을 여닫는 줄은 옮기지 않는다"가 plan 본문에 한 번만 있고, 그것이 `## 낱말`에 있으며, `## 계획 파일의 양식`이 그 낱말을 가리킨다
     - 기존 `test_37_draft_check`, `test_41_conditions_from_earlier_phase_output`, `test_46_rerun_results_compared_by_body_hash`, `test_53_draft_check_for_run_scenes`, `test_55_checks_run_on_uncommitted_worktree`, `test_57_quote_earlier_task_text_as_changed`가 그대로 통과한다
   - 확인: plan `## 2. 맥락 문서를 읽는다`의 첫 문단을 읽어 "문서 지도에 적힌 위치의 맥락 문서를 모두 읽는다"가 그대로 있다
   - 돌리지 않음: plan의 초안 흐름은 사용자 승인이 있어야 돈다. 바뀐 것은 목록의 나눔과 글의 자리다
3. 기존 규칙이 넓어지고, 나눠 가진 정의가 어긋나면 테스트가 잡는다. (기존 작업 정합성-1, 기존 작업 정합성-2, 유지보수성-6)
   - **TODO**의 "규칙이나 동작을 바꾸는 TODO" 항목은 맥락 문서의 줄과 함께, 같은 대상(명령, 낱말)을 다루는 스킬 본문과 코드의 기존 줄도 찾아 읽을 것에 넣는다. 그리고 그 줄들과 새 규칙이 같은 것을 시키는지 보는 확인을 두게 한다.
   - **조건**의 동작을 돌리는 확인 항목은 본문에 넣는 명령 예도 동작으로 친다. 명령 예를 넣는 TODO의 통과 조건에는 그 예를 규칙이 다루는 경우마다 돌리는 확인을 두거나, 예를 빼게 한다. plan은 그 확인을 미리 돌리지 않는다.
   - run과 plan의 같은 정의 셋(테스트가 있는 프로젝트, 테스트 먼저의 기준, task 폴더 번호)이 같은지 테스트가 본다.
   - 확인: `python3 -m unittest discover -s tests`가 `OK`로 끝난다. 그 안에 다음을 단언하는 테스트가 있다:
     - **TODO**에 스킬 본문과 코드의 기존 줄을 찾는 글이 있다
     - **조건**에 명령 예를 동작으로 치는 글이 있다
     - `test_shared_definitions_match`: 두 본문의 `**테스트가 있는 프로젝트**` 낱말 줄이 글자까지 같고, 테스트 먼저의 기준과 task 폴더 번호의 핵심 글이 두 본문에 다 있다
   - 확인: `mktemp -d`로 만든 `<임시>`에 `cp -R`로 작업 트리를 `<임시>/repo`에 베낀다. 사본의 run 본문 `## 낱말`의 `**테스트가 있는 프로젝트**` 줄에서 `__tests__/`를 `spec/`으로 바꾸고, 사본에서 `python3 -m unittest tests.test_skill_rules`를 돌린다. `test_shared_definitions_match`가 실패한다
   - 돌리지 않음: plan은 사용자에게 묻고 승인받아야 계획을 쓰는 스킬이라, 넓힌 규칙대로 읽을 것과 확인을 쓰는지 임시 폴더에서 돌릴 수 없다
4. 앞 task가 이룬 tasks 완료 조건 1과 3이 이 task의 마지막 커밋에서도 참이다.
   - 확인: `python3 -m unittest discover -s tests`가 `OK`로 끝난다
   - 확인: `git grep -n 'TOOLS.md' -- plugins/`가 아무것도 내지 않는다

## 결정
- 평가가 시작된 tasks(`review.md`나 `eval.md`가 있다)에는 task를 더하지 않고 끝난다. 평가를 다시 하게 하지 않는다. 이유: 보고서 신뢰성-4의 고치는 방향(평가를 다시 하는 것보다 싸다)
- 더하는 경우에 읽는 것은 task 머리뿐이다. 이유: 보고서 신뢰성-5의 2라운드(점검을 빼는 쪽은 #57과 어긋난다)
- 양식을 읽는 법의 낱말 이름은 run `## 낱말`에 앞 task(002-run-rules의 phase 4)가 더한 낱말과 같은 이름으로 한다. 이유: 두 본문이 같은 것을 같은 이름으로 부르게 한다(추천안으로 정함)
