# FRICTION

- `001-plan-rules` 문제: phase 2의 읽을 것이 phase 1이 같은 파일(`plugins/plate/skills/plan/SKILL.md`)에 줄을 더하기 전의 줄 번호(188줄, 220~232줄, 256~267줄)로 적혀 실제 위치(194줄, 226~238줄, 262~273줄)와 달랐다. plan 스킬의 적는 규칙 "phase의 파일"의 읽을 것 줄은 뒤 phase가 앞 phase의 결과를 쓰면 위치를 경로로 적으라고만 하고, 앞 phase가 고칠 파일을 줄 번호로 가리키지 말고 절 이름으로 가리키라는 줄이 없다
- `002-run-review` 문제: 완료 조건 5의 확인과 phase 1의 읽을 것이 `docs/TOOLS.md`를 83줄로만 가리켜, 바로 뒤 84줄("스킬의 절차를 바꾸는 tasks는 ... 새 세션에서 이어 간다")이 바뀐 run(작업 트리의 스킬 줄)과 맞는지는 확인에 들지 않았다. phase 1이 "남은 것"에 적어 회고가 읽었고 어긋나지 않았지만, plan 스킬의 적는 규칙 "조건"에는 줄 번호로 가리킨 확인이 같은 사실을 잇는 이웃 줄까지 덮는지 대어 보라는 줄이 없다
- `003-release` 없음
- `004-fixes` 문제: task 머리 완료 조건 3이 "tasks 완료 조건 1~8이 참이다"로 번호만 가리키고 그 아래에 확인 글만 옮겨 적어, 확인 글의 "네 점검", "세 줄", "위의 것"이 무엇인지 task 머리만으로 알 수 없었다. phase를 수행한 쪽과 확인한 쪽이 둘 다 "하네스에서 걸린 것"에 적고 `docs/tasks/review.md`나 `docs/tasks/plan.md`에서 뜻을 찾았다(`done-phase-1.md`). plan 스킬의 적는 규칙 "조건"은 tasks 완료 조건을 번호로 가리키라고 하면서, 확인 글을 옮길 때 그 확인이 기대는 조건의 글도 함께 옮기라는 줄이 없다
- `004-fixes` 문제: phase 1의 TODO가 작업 트리의 스킬 줄의 꼴을 바꾸면서 그 꼴을 그대로 옮겨 적은 `docs/TOOLS.md:84`를 가리키지 않아, 수행한 쪽이 "계획과 달라진 점"에 적고 고쳤다. plan 스킬의 "TODO" 규칙(규칙이나 동작을 바꾸는 TODO는 그것을 적은 맥락 문서의 줄을 모두 가리킨다)이 고침 task의 계획에서 지켜지지 않았다
- `004-fixes` 문제: task 머리의 범위 밖이 "plate 자체의 하네스 고칠 거리를 고치는 것"을 빼는데, 완료 조건 1은 `docs/tasks/eval.md`의 하네스 고칠 거리 2(갈래: plate 자체)를 고친다. 이 저장소가 plate 자신이라 고친 것은 맞지만, 계획의 범위 밖과 완료 조건이 서로 어긋난 채 쓰였다(`docs/tasks/004-fixes/plan.md`)
