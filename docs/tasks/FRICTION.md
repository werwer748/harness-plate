# FRICTION

- `001-run-rules` 문제: task 머리 완료 조건 2와 phase 1 통과 조건의 확인 "`mktemp -d`에 `git archive HEAD`를 풀어 …"는, plate의 phase 스킬이 바꾼 것과 기록을 phase 끝에 한 커밋으로 넣는 차례와 맞지 않는다(커밋 전에는 HEAD에 바뀐 것이 없다). 수행 쪽이 스테이지한 트리(`git archive $(git write-tree)`)로 대신했고, 확인 쪽은 커밋 뒤라 그대로 돌렸다. plan 스킬이 수행 쪽이 돌릴 확인에 `HEAD`를 적지 않게(또는 "커밋할 트리"로 적게) 할지 볼 거리다
- `001-run-rules` 문제: phase 1 확인 1의 "하네스에서 걸린 것"에 `남은 것:` 줄 "고친 run의 동작(8번의 시각·해시 판정, 결정 줄 점검, 두 단계 명령의 헤드리스 통과)은 돌려 보지 않았다"가 있다. 이번 회고는 이 줄을 "문제 아님"(task 머리의 `돌리지 않음`)으로 판정했다. 지금 retro 스킬 5번 "문제" 갈래가 확인 절의 "하네스에서 걸린 것"을 판정과 상관없이 모으라고 해서 옮긴 것이다(#49, 003에서 고칠 규칙)
- `001-run-rules` 문제: phase 1 확인 1의 "하네스에서 걸린 것"에 `남은 것:` 줄 "테스트는 규칙 글이 제 절에 있는지만 본다. 글을 다른 말로 고치면 같은 뜻이어도 실패한다"가 있다. 이번 회고는 이 줄을 "문제 아님"(tasks 머리의 결정이 고른 방식)으로 판정했다. 옮긴 까닭은 위 줄과 같다(#49)
- `002-plan-rules` 문제: task 머리 완료 조건 2와 phase 1 통과 조건의 확인 "`mktemp -d`에 `git archive HEAD`를 풀어 …"가 001과 같은 꼴로, plate의 phase 스킬이 통과 조건을 돌린 뒤 한 커밋으로 넣는 차례와 맞지 않았다. 수행 쪽이 작업 트리 스냅숏(`git stash create`)으로 대신했다(phase 1 기록의 "하네스에서 걸린 것"). plate의 plan 스킬이 수행 쪽이 돌릴 확인에 `HEAD`를 쓰지 않게 하는 규칙이 없어 같은 tasks의 두 task에서 되풀이됐다
- `002-plan-rules` 문제: phase 1 확인 1의 "하네스에서 걸린 것"에 `남은 것:` 줄 "plan이 초안 점검에서 실제로 새 규칙대로 하는지는 돌려 보지 않았다"가 있다. 이번 회고는 이 줄을 "문제 아님"(task 머리의 `돌리지 않음`)으로 판정했다. 지금 retro 스킬 5번 "문제" 갈래가 확인 절의 "하네스에서 걸린 것"을 판정과 상관없이 모으라고 해서 옮긴 것이다(#49, 003에서 고칠 규칙)
- `003-agent-rules` 문제: phase 1 수행과 확인을 맡긴 글에 `부른 쪽: plate:run` 줄이 없었다(수행은 task 폴더와 phase 두 줄, 확인은 작업 트리의 스킬 줄만). tasks 일괄에서 run 세션이 띄울 때의 run 본문(001이 표지 줄을 더하기 전)으로 맡긴 것이라, tasks 머리의 결정대로 작업 트리의 스킬 줄로 가를 수 있었지만 그 줄도 없던 phase 1 수행은 고치기 전의 phase 6번에 기대어 다섯 줄만 돌려줬다(phase 1 기록과 확인 1의 "하네스에서 걸린 것")
- `003-agent-rules` 문제: task 머리 완료 조건 3과 phase 1 통과 조건의 확인 "`mktemp -d`에 `git archive HEAD`를 풀어 …"가 001, 002와 같은 꼴로 plate의 phase 스킬이 확인을 돌린 뒤 한 커밋으로 넣는 차례와 맞지 않아, 수행 쪽이 작업 트리를 `rsync`로 복사해 대신했다(phase 1 "계획과 달라진 점"). 이 tasks의 세 task에서 모두 되풀이됐다. plate의 plan 스킬이 수행 쪽이 돌릴 확인에 `HEAD`를 쓰지 않게 하는 규칙이 없다
- `003-agent-rules` 문제: task 머리 결정의 장면 R 프롬프트 "run 7번의 맡기는 글에 task 폴더를 넣은 세 줄과 `부른 쪽: plate:run`"이, 001이 이미 `부른 쪽: plate:run`을 셋째 줄로 넣은 run 7번 코드 블록과 겹쳐 네 줄로 읽혔다. 수행 쪽이 코드 블록 그대로의 세 줄로 돌렸다(phase 2 "하네스에서 걸린 것"). 계획이 앞 task가 바꾼 글을 다시 덧붙여 적었다
- `003-agent-rules` 문제: phase 2 통과 조건 "돌리기 전과 뒤의 원본 `git status --short`가 같다"가 plate의 phase 스킬 2번의 TODO 체크(`- [x]`로 바꾸기)가 장면 앞에 원본을 바꾸는 것과 맞물려, "전"을 잰 값이 아니라 추론으로 적게 했다(phase 2 "하네스에서 걸린 것", 확인 1의 `남은 것:` 줄). 계획이 원본에서 바뀌지 않아야 할 것을 phase 파일까지 포함한 `git status --short` 전체로 잡았다
