- `001-hook-fixes` 스킬 후보: 셋업된 시험 레포(`mktemp -d`, `AGENTS.md`의 docs-map 줄, 커밋된 테스트·구현 파일, 테스트 먼저 "예"인 `phase-1.md`)를 만들고 훅에 편집 JSON을 넣어 종료 코드를 보는 손일이 phase 1~3의 수행·확인과 회고에서 되풀이됐다. 시험 레포를 만들고 훅을 부르는 도우미 스크립트를 두면 확인마다 다시 짜는 셸이 줄고 레포 재사용 실수(위 문제)도 사라진다
- `001-hook-fixes` 경계 밖: 편집 훅의 테스트 변경 셈에서 `AD`(스테이지한 뒤 작업 트리에서 지움)는 실제로 남은 테스트가 없는데도 테스트 변경으로 센다. 완료 조건 4는 "상태가 삭제뿐인" 것만 정해 경계 밖이다. 작업 트리에 파일이 없는 항목을 빼는 것으로 약속을 넓힐지 볼 까닭이 있다
- `001-hook-fixes` 경계 밖: 정리 점검의 신뢰성-5는 "잠금 없이 읽고 쓰고, 깨진 파일을 삼킨다"도 적었으나 완료 조건 3은 바꿔 넣기와 쓰기 실패만 정했다. 깨진 세는 파일을 비우는 것과 잠금 없음은 남았다. 신뢰성-5를 다 고친 것으로 칠지, BACKLOG로 미룰지 볼 까닭이 있다
- `001-hook-fixes` 경계 밖: `.md` 갈래가 경로 글의 끝만 보아 `.md` 이름의 심볼릭 링크가 코드 파일을 가리키면 통과한다(전에는 실제 경로로 갈랐다). ADR-027은 `.md`를 이름으로 뺀다고만 적어, 링크를 실제 경로로 가를지 약속에 넣을지 볼 까닭이 있다

- `003-skill-fixes` 문제: 프로젝트의 규칙을 따름: AGENTS.md의 스킬 본문 규칙대로 phase 3은 세션에 실린 판의 `plate:phase`로 수행했고, 고친 phase 본문의 동작은 그 본문을 따라 돈 것으로 보지 않고 시험 레포에서 명령 예를 돌려 봤다(`done-phase-3.md`의 기록과 확인 1의 "하네스에서 걸린 것")
- `003-skill-fixes` 경계 밖: run 낱말의 "결과 없이 돌아온 에이전트"는 수행의 결과를 `## 한 일` 유무로만 봐, 기록 절이 이미 있는 고칠 문제 수행이 아무것도 바꾸지 않고 돌아오면 잡지 못한다(확인의 세 번 실패로 늦게 멈춘다). 고칠 문제 수행은 기록 절이 바뀌었는지(커밋이나 내용)로 볼지 약속에 넣을 까닭이 있다
- `003-skill-fixes` 경계 밖: 세션을 끊고 run 3번 표로 같은 자리를 다시 맡길 때 그 줄에 `| 다시 띄움: 결과 없음`을 달지 정하지 않아, 끊고 다시 부를 때마다 결과 없음의 셈이 처음부터 다시 갈 수 있다. "세션을 끊어도 남는다"는 결정의 까닭과 맞추려면 3번의 다시 맡김도 셈에 넣을지 볼 까닭이 있다
- `003-skill-fixes` 경계 밖: run 1번이 계획 커밋을 tasks 브랜치 뒤로 옮겨, 커밋하지 않은 계획 파일과 같은 경로의 추적 파일이 있는 기존 `tasks/<이름>`으로 `git switch`하면 실패하고 본문은 그 갈래를 다루지 않는다. 옛 계획이나 손으로 쓴 계획에서만 나지만 막힘으로 멈출지 적을 까닭이 있다
- `003-skill-fixes` 경계 밖: phase의 실패 출력 얻기에서 Python 구현 파일을 되돌려도 크기·시각이 같으면 `sys.pycache_prefix`의 낡은 바이트코드가 읽혀 실패가 나지 않을 수 있다(phase 3 수행의 첫 시도에서 재현, `-B`로 피함). 본문에 바이트코드 캐시를 끄는 갈래를 넣을지 볼 까닭이 있다
- `004-test-tidy` 문제: `docs/tasks/004-test-tidy/plan.md` 완료 조건 2와 `phase-1.md` 통과 조건의 `python3 -m unittest tests.test_edit_guard.HooksJsonCommandTest tests.test_push_guard.HooksJsonTest`가 계획 때 돌려 보지 않은 명령이었다. 저장소 루트에서 돌면 `tests/`가 `sys.path`에 없어 고치기 전부터 `test_push_guard`의 `from test_edit_guard import …`가 `ModuleNotFoundError`로 실패했고, phase 1 수행이 계획에 없던 `sys.path.insert` 줄을 세 시험 모듈에 더해 돌게 했다(`done-phase-1.md`의 "계획과 달라진 점"과 "하네스에서 걸린 것"). plan의 초안 점검이 읽기만 하는 확인 명령을 돌려 볼 때 `tests.모듈` 꼴의 unittest 명령도 지금 저장소에서 돌려 봤어야 한다
