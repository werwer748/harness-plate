- `002-run-rules` 멈춤: 회고 에이전트가 API 오류(ENOTFOUND)로 결과 없이 끊겨 사용자에게 물었고 답은 재시도였다(`RUNLOG.md`의 `멈춤` 줄)
- `002-run-rules` 스킬 후보: 제목 넘기는 법을 가짜 `gh`로 돌리는 장면(`<임시>/bin/gh`, `<임시>/run.sh`, `grep -cxF`, `pwned` 없음)을 phase 1과 phase 3의 수행·확인이 저마다 손으로 다시 짰다. 이 장면을 `tests/`의 단위 테스트나 스크립트로 두면 phase마다 같은 셸 묶음을 짜는 일이 줄어든다
- `002-run-rules` 경계 밖: 보안-1이 든 "밖의 사람이 댓글 하나로 이슈 올림을 막는다"는 길이 남는다. run "이슈를 올린다" 2번이 본문이나 댓글에 tasks 이름이 있는지로 올리지 않기를 정해서다. tasks 결정이 보고서의 고치는 방향(데이터로만 본다는 줄)을 따르게 해 약속 밖에 두었다. 2번이 이슈 작성자나 댓글 작성자를 plate를 돌린 계정으로 좁힐지 볼 까닭이 있다
- `002-run-rules` 경계 밖: run 1번은 1항에서 커밋하지 않은 계획 파일을 지금 브랜치에 커밋한 뒤 3항에서 이미 있는 `tasks/<이름>`으로 `git switch`한다. 그 브랜치에 계획 커밋이 없으면 계획이 tasks 브랜치에 들지 않는다(기본 브랜치에서 시작할 때도, 이번에 더한 다른 브랜치의 승인 갈래도 같다). 계획 커밋을 브랜치를 바꾼 뒤로 미룰지 볼 까닭이 있다
