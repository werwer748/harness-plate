# retro와 phase의 기록 규칙을 고친다

## 목표
retro가 문서와 코드의 어긋남을 문제로 적을 때 task 머리와 tasks 머리의 목표와 결정에 비춰 어느 쪽을 고칠지 적는다(#4). 결정이나 맥락 문서가 약속하는 꼴의 경계를 정했으면, retro는 그 경계 밖에서 찾은 꼴을 문제로 적지 않고 `FRICTION.md`에 볼 거리로 적는다(#5). phase는 수행이 아는 부작용과 한계를 "남은 것"에 적고, retro는 `done-phase-N.md`의 "남은 것"을 4번 점검에 대어 본다(#9).

## 범위 밖
- run이 쓰는 고칠 phase의 통과 조건. `002-run-rules`에서 한다
- plan이 경계를 묻는 규칙. `003-plan-rules`에서 한다
- check 스킬이 "남은 것"을 읽는 규칙
- eval의 등급 기준과 3번 표. `005-eval-rules`에서 한다

## 완료 조건
1. tasks 완료 조건 8이 참이다.
   - 확인: `plugins/plate/skills/retro/SKILL.md`를 읽어 셋을 하나씩 찾는다. 첫째, 어긋남을 문제로 적을 때 고칠 쪽(문서 | 코드)과 그 근거가 된 목표나 결정을 적는 규칙(4번과 회고 절 양식의 "문제" 줄 둘 다). 둘째, 결정이나 맥락 문서가 정한 경계 밖의 꼴을 문제로 적지 않고 `FRICTION.md`에 `경계 밖` 줄로 적는 규칙(4번, 5번, `FRICTION.md` 줄 양식 셋 다). 셋째, `done-phase-N.md`의 "남은 것"을 4번 점검에 대어 보는 규칙
   - 확인: `plugins/plate/skills/phase/SKILL.md`의 적는 규칙과 기록 양식의 "남은 것"을 읽어, 수행이 아는 부작용과 한계를 "남은 것"에 적는 규칙이 둘 다에 있다
2. `FRICTION.md`의 갈래를 적은 다른 곳이 새 갈래와 어긋나지 않는다.
   - 확인: `grep -rn '스킬 후보' plugins/plate/skills docs/ARCHITECTURE.md`가 낸 줄마다 `경계 밖`이 함께 적혀 있거나, 그 줄이 갈래 하나만 가리켜 넷을 늘어놓지 않는다
3. `docs/ARCHITECTURE.md`에서 회고와 phase 기록을 적은 줄이 바뀐 두 스킬과 어긋나지 않는다.
   - 확인: `grep -n '회고\|남은 것\|FRICTION' docs/ARCHITECTURE.md`가 낸 줄을 하나씩 읽어 어긋나는 줄이 없다

## 결정
- 경계 밖의 꼴은 `FRICTION.md`에 새 갈래 `경계 밖`으로 적는다. 이유: "문제" 줄은 하네스나 계획이 걸린 곳이고, 경계 밖의 꼴은 약속을 넓힐지 사람이 볼 거리라 갈래를 나눠야 eval이 실패로 세지 않는다 (추천안으로 정함)
- 경계가 없는데 열린 입력에서 결함을 찾으면 지금처럼 "결함"으로 적는다. 경계를 정하는 일은 plan(003)이 맡는다
