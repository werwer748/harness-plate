# 계획의 커밋이 로컬 기본 브랜치에만 있을 때를 다룬다

## 목표
run이 tasks 브랜치를 만들거나 바꾼 뒤 로컬 기본 브랜치에 origin의 기본 브랜치에 없는 커밋이 있으면, 그 커밋이 모두 tasks 브랜치에 있을 때는 그 커밋을 보여 주고 로컬 기본 브랜치를 origin의 것으로 되돌릴지 묻고, tasks 브랜치에 없는 커밋이 있으면 묻지 않고 그대로 둔다고 알리고, run과 review가 갈라진 곳을 로컬 기본 브랜치의 merge-base로 적는다(#29).

## 범위 밖
- plan이 브랜치를 만들거나 바꾸게 하는 것. plan의 절대 규칙 4는 그대로다
- 되돌리기 전에 `git fetch`로 원격을 새로 받는 것
- eval의 "정해 둔 물음"을 고치는 것. `004-review-eval`이 한다
- 버전. `005-release`가 한다

## 완료 조건
1. run 1번의 tasks 브랜치 항목은 브랜치를 만들거나 바꾼 뒤, origin과 그 기본 브랜치의 원격 추적 ref(`origin/<기본 브랜치>`)가 있고 로컬 기본 브랜치에 거기 없는 커밋이 있고 그 커밋이 모두 `tasks/<이름>`에 있으면, 그 커밋을 보여 주고 로컬 기본 브랜치를 `origin/<기본 브랜치>`로 되돌릴지 묻는다. 승인하면 되돌리고, 거절하면 그대로 두고 잇는다. `tasks/<이름>`에 없는 커밋이 있으면 묻지 않고 되돌리지 않고 알린다. 커밋은 tasks 브랜치에 남는다. 알아보는 명령과 되돌리는 명령이 본문에 적혀 있다.
   - 확인: `mktemp -d` 안에 bare 원격과 그 복제본을 만들고, 복제본의 기본 브랜치에 원격에 없는 커밋 하나를 더한 뒤 run 1번에 적힌 브랜치 만들기, 알아보기, 되돌리기 명령을 적힌 그대로 돌린다. 되돌리기 전에는 알아보기가 커밋 1개를, 되돌린 뒤에는 0개를 내고, 되돌린 뒤 `git merge-base <기본 브랜치> tasks/<이름>`이 원격 기본 브랜치의 끝이고, `git log tasks/<이름>`에 그 커밋이 있다. 하나라도 다르면 실패. 임시 디렉터리는 지운다
   - 확인: `mktemp -d` 안에 bare 원격과 그 복제본을 만들고, 복제본에서 `git branch tasks/y`로 브랜치를 먼저 만든 뒤 기본 브랜치에 원격에 없는 커밋 하나를 더하고 `git switch tasks/y`로 바꾼 다음 run 1번에 적힌 두 알아보기 명령을 적힌 그대로 돌린다. `refs/remotes/origin/<기본 브랜치>..<기본 브랜치>`와 `tasks/y..<기본 브랜치>`가 둘 다 커밋 1개를 내서 묻지 않는 갈래이고, 그 뒤에도 기본 브랜치에 그 커밋이 있다. 하나라도 다르면 실패. 임시 디렉터리는 지운다
2. run의 `RUNLOG.md` 절의 물은 자리 목록에 `기본 브랜치`가 있고, task에 걸리지 않는 물음으로 task 이름 자리에 "없음"을 적는다.
   - 확인: `plugins/plate/skills/run/SKILL.md`의 `RUNLOG.md` 절을 읽어 물은 자리 목록과 task에 걸리지 않는 물음의 목록에 저마다 `기본 브랜치`가 있다
3. run의 낱말 "작업 트리의 스킬 줄"과 review의 낱말 "갈라진 곳"이 로컬 기본 브랜치의 `git merge-base <기본 브랜치> HEAD`라고 적는다.
   - 확인: 두 스킬의 그 낱말을 읽어 둘 다 원격 추적 ref가 아니라 로컬 기본 브랜치라고 적는다. 하나라도 없으면 실패
4. `docs/ARCHITECTURE.md`와 `README.md`가 run의 새 물음과 맞는다.
   - 확인: `docs/ARCHITECTURE.md`의 "패턴과 규칙"에서 "run은 기본 브랜치"로 시작하는 항목과 "데이터 흐름"의 실행 줄, `README.md`의 표의 `run` 행을 하나씩 읽어 새 물음과 어긋나지 않는다

## 결정
- 계획의 커밋이 로컬 기본 브랜치에만 있으면 run은 tasks 브랜치를 만든 뒤 그 커밋을 보여 주고 로컬 기본 브랜치를 origin의 것으로 되돌릴지 묻는다. 새 물은 자리 `기본 브랜치`는 eval이 정해 둔 물음으로 본다. 이유: 이슈가 제안한 안이고, 커밋은 tasks 브랜치에 남는다
- 앞선 커밋은 원격 추적 ref(`origin/<기본 브랜치>`)와 견줘 찾고 `git fetch`는 하지 않는다. origin이나 그 ref가 없으면 묻지 않는다. 이유: 시작 조건이 네트워크에 기대지 않고, 원격이 없는 저장소에서는 견줄 것이 없다 (추천안으로 정함)
- 이 task의 확인은 run 본문의 명령을 `mktemp -d`에서 실제로 돌린다. 에이전트가 묻고 답하는 부분은 돌리지 않는다. 이유: 셸로 재현되는 것만 돌리기로 한 tasks의 결정
- 회고 1에 따라 물음을 앞선 커밋이 모두 tasks 브랜치에 있을 때로 좁혔다. 이유: 이미 있던 tasks 브랜치로 바꾼 갈래에서 되돌리면 그 커밋이 어느 브랜치에도 남지 않는다
