## 배경

1단계의 셋업 스킬은 문서 양식을 `docs/`에 놓고 칸을 비워 둔다. 2단계의 결과물은 그 칸을 채우는 스킬 `plate:context`다. 채우는 방식은 1단계에서 정해 두었다: 스캔과 질문 라운드로 채우고 추측으로 적지 않는다(1단계 원장 12).

2단계의 질문 라운드는 2026-10-06에 열었다. 정한 것은 이 문서 끝의 결정 원장에 있다.

## 맥락 스킬 규격

**쓰는 방식**: 셋업 스킬과 같다. 한국어로 쓰고, 도구 이름 대신 동작으로 쓰고, 판정 기준은 본문에 목록으로 적어 도구마다 결과가 갈리지 않게 한다.

### 낱말

- **남은 칸**: 양식의 `{…}` 안내 글, 또는 `{확인 필요}`. `docs/DESIGN.md`의 토큰 참조(`{colors.primary}`처럼 영문 범주와 이름을 점으로 이은 것)는 남은 칸이 아니다.
- **대상 문서**: 문서 지도의 표준 위치(`docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/ADR.md`, 지도에 행이 있으면 `docs/DESIGN.md`)에 있고 남은 칸이 있는 문서. 남은 칸이 없는 문서, 지도에 다른 경로로 적힌 문서, 폴더로 된 문서는 대상이 아니다.
- **적힌 사실**: 파일에 그대로 적혀 있는 것. 의존성 이름과 버전, 폴더 이름, 설정 값, README 문장, 토큰 이름과 값.
- **해석**: 파일을 읽고 에이전트가 정리한 것. 폴더의 역할, 패턴과 규칙, 데이터 흐름, 코드에서 드러나는 결정.
- **의도**: 어디에도 적혀 있지 않은 것. 목표, 사용자, 범위 밖, 결정의 이유와 트레이드오프, 화면의 분위기.

### 절차

0. **셋업이 됐는지 본다.** `AGENTS.md`에 문서 지도 구간(`<!-- plate:docs-map:start -->`)이 없으면 셋업을 먼저 할지 묻는다.
   - 승인하면 plate의 setup 스킬을 이름으로 불러 그 절차를 끝까지 따르고 돌아온다. 이때 setup의 끝 물음(이어서 채울지)은 하지 않는다.
   - 거절하면 아무것도 쓰지 않고 끝난다.
1. **대상 문서를 정한다.** 지도에서 네 문서의 위치를 읽고 남은 칸을 센다. 대상 문서가 없으면 채울 것이 없다고 보고하고 끝난다.
2. **스캔한다.** 아래 목록만 읽는다. 목록 밖의 소스 파일은 해석을 확인하는 데 필요한 것만 연다. 빈 프로젝트는 스캔할 것이 없다.
   - `README`, 빌드 매니페스트, 최상위와 한 단계 아래의 폴더 목록, 진입점 파일, 설정 파일, `AGENTS.md`, 최근 커밋 제목 30개
   - 지도에 `docs/DESIGN.md` 행이 있으면 토큰 파일(CSS 변수, `@theme`, tailwind 설정)
3. **문서를 하나씩 채운다.** 순서는 PRD → ARCHITECTURE → ADR → DESIGN이고 대상 문서만 한다. 문서 하나마다:
   1. 적힌 사실로 채울 칸은 출처 경로와 함께 초안에 넣는다.
   2. 해석으로 채울 칸은 절 단위로 묶어 보여 주고 맞는지 묻는다. 고칠 곳을 말하면 고쳐서 다시 보여 준다. 확인받은 것만 초안에 남긴다.
   3. 의도를 묻는 칸은 질문을 하나씩 낸다. 저장소에 근거가 있으면 추천안을 붙이고 근거 경로를 적는다. 근거가 없으면 추천안 없이 묻는다. 고를 수 있는 답은 선택지로 낸다.
   4. 문서의 초안 전체를 보여 주고 승인받는다. 고칠 곳을 말하면 고쳐서 다시 보여 준다. 승인받은 뒤에 파일에 쓴다.
4. **보고한다.** 쓴 문서, 남은 칸과 그 위치, 대상이 아니었던 문서.

### 답을 적는 규칙

- 사용자의 답은 뜻을 바꾸지 않는 범위에서 문서 문체(평서문)로 다듬는다. 답에 없는 내용은 더하지 않는다.
- 사용자가 미룬 칸(모른다, 아직 안 정했다)은 `{확인 필요}`로 적는다. 둘을 구분하지 않는다.
- 사용자가 없다고 답한 칸은 "없음"으로 적는다. ADR에 적을 결정이 없으면 철학만 남기고 항목 자리에 "아직 적은 결정이 없다"를 적는다.
- 목록 칸(핵심 기능, 범위 밖, 기술 스택, ADR 항목)의 개수는 답에 맞춘다. 양식의 개수는 예시다. 절 제목과 순서는 바꾸지 않는다.
- 스캔으로 적은 사실에만 출처 경로를 괄호로 붙인다(예: `- Kotlin 2.0, JVM 21 (build.gradle.kts)`). `docs/DESIGN.md`의 앞머리는 YAML이라 출처를 주석으로 적는다.
- ADR 번호는 있는 번호 뒤에 잇는다.
- 요청에 이미 답이 적혀 있는 물음은 다시 묻지 않는다.
- 다시 불렀을 때는 남은 칸만 묻는다. 적힌 내용은 묻지도 고치지도 않는다.
- 도중에 사용자가 그만하자고 하면, 그 문서는 답한 칸까지 초안을 보여 주고 승인받아 쓴다. 아직 묻지 않은 칸은 양식의 `{…}` 그대로 둔다. 뒤 문서로 가지 않고 보고한다.

### 칸의 분류

| 문서 | 칸 | 얻는 방법 |
|---|---|---|
| PRD | 프로젝트명 | 질문. `README` 제목이나 매니페스트의 이름이 있으면 추천안 |
| PRD | 목표, 사용자, 핵심 기능, 범위 밖 | 질문. `README`에 적혀 있으면 추천안 |
| ARCHITECTURE | 기술 스택 | 적힌 사실 (빌드 매니페스트) |
| ARCHITECTURE | 디렉터리 구조 | 폴더 이름은 적힌 사실, 역할은 해석 |
| ARCHITECTURE | 패턴과 규칙 | 해석. 규칙의 이유는 질문 |
| ARCHITECTURE | 데이터 흐름 | 해석 |
| ADR | 철학 | 질문 |
| ADR | 항목 | 다섯 범주의 후보를 보여 주고 남길 것을 고르게 한 뒤, 이 밖에 적어 둘 결정이 있는지 한 번 묻는다 |
| ADR | 항목의 이유, 트레이드오프 | 질문. `README`, 커밋 제목, 주석에 적혀 있으면 추천안 |
| DESIGN | 앞머리의 토큰 | 토큰 파일에 있으면 적힌 사실. 없으면 양식의 키대로 질문 |
| DESIGN | 앞머리의 `name`, `description` | `name`은 PRD의 프로젝트명, `description`은 질문 |
| DESIGN | 본문의 절 | 질문 |

**ADR 후보의 범주**: 언어와 런타임, 프레임워크, 저장소(DB), 외부 서비스, 빌드·배포 방식. 이 다섯 범주 밖에서는 후보를 내지 않는다.

**DESIGN의 토큰**: 토큰 파일에 적힌 이름과 값을 규격의 범주(`colors`, `typography`, `rounded`, `spacing`)에 그대로 옮긴다. 양식의 예시 키(`primary`, `secondary` 등)는 쓰지 않는다. 빈 프로젝트처럼 토큰이 코드에 없으면 양식의 키대로 하나씩 묻는다.

### 절대 규칙

1. 확인이나 답을 받지 않은 해석과 의도를 문서에 적지 않는다.
2. 승인받지 않은 초안을 파일에 쓰지 않는다.
3. 남은 칸이 아닌 곳은 고치지 않는다. 대상이 아닌 문서는 열어 보기만 하고 건드리지 않는다.
4. 커밋하지 않는다. 스테이징도 하지 않는다.

## 셋업 스킬 수정

1. **재실행 물음** (원장 49). 빈 프로젝트라도 `AGENTS.md`에 문서 지도 구간이 이미 있으면 화면이 있는 프로젝트인지 묻지 않는다. 구간에 `docs/DESIGN.md` 행이 있으면 UI 프로젝트로 본다. 고칠 곳은 "1. 현재 상태를 본다"의 UI 프로젝트 판정과 "2."의 물음 표다.
2. **끝 물음** (원장 61). 보고 뒤에 남은 칸이 있는 문서가 있으면 이어서 채울지 묻는다. 승인하면 plate의 context 스킬을 이름으로 불러 따른다. 아래 경우에는 묻지 않는다.
   - 남은 칸이 있는 문서가 없다.
   - context 스킬이 setup을 부른 것이다.
   - 요청에 이미 답이 적혀 있다.

절대 규칙 2번("양식의 `{…}` 칸을 채우지 않는다")은 그대로 둔다. 채우는 것은 context 스킬이다.

**두 도구가 같다는 기준** (원장 66)
- 기계로 본다: 바뀐 파일 목록, 절 제목과 순서, 남은 `{…}` 안내 글이 없음, `{확인 필요}`가 있는 칸, 목록 칸의 항목 수, 출처 경로의 집합. 두 도구에서 같아야 한다.
- 읽어서 본다: 두 결과를 답 파일과 나란히 놓고, 답에 없는 내용이 더해졌는지와 빠진 답이 있는지를 표로 적어 사용자에게 보여 준다.

**셋업 스킬을 고친 뒤 다시 돌릴 1단계 판정**: D1, D2, D4, D5, D6. 끝 물음에는 "채우지 않는다"를 답으로 미리 준다. 빈 폴더의 결과는 전과 같이 두 도구에서 한 글자도 다르지 않아야 한다.
