# plan의 이슈 셋을 고친다

## 목표
plan 본문에서 #46의 plan 쪽(돌려 본 결과의 새로움을 본문 해시로 견준다), #52(앞 task의 변경에 기대는 읽을 것에 절 이름과 바뀐 글을 적는다), #53(초안 점검이 돌려 보는 확인의 차림·기대·결정과 TODO의 맞물림을 본다)을 고치고, 그 규칙 글이 빠지면 실패하는 테스트를 더한다.

## 범위 밖
- run, phase, check, retro, review, eval 본문을 고치는 것
- plan의 description을 고치는 것
- plan의 고친 동작을 헤드리스로 돌리는 것

## 완료 조건
1. tasks 완료 조건 2가 참이다
   - 확인: `plugins/plate/skills/plan/SKILL.md`를 읽어 세 이슈의 해결이 저마다 적혀 있다. #46: 적는 규칙 "조건"에 돌려 본 결과가 지금 본문의 것인지를 커밋 시각이 아니라 돌릴 때 적은 본문 해시(`git hash-object`)와 `git rev-parse HEAD:<경로>`로 견준다는 글이 있다. #52: 적는 규칙 "phase의 파일"의 읽을 것 항목에, 앞 task의 변경에 기대면 이슈 번호만 적지 않고 그 파일의 절 이름과 바뀐 글을 찾을 수 있게 적는다는 글이 있다. #53: "6. 초안을 보여 주고 승인받는다"의 점검에, 돌려 보는 확인마다 차림이 앞 단계를 지나 기대한 자리에 닿는지, 기대가 해결 방식이 아니라 관찰할 결과로 적혔는지, 결정과 TODO가 같은 멈출 자리를 말하는지 본다는 글이 있다. 하나라도 없으면 실패
   - 돌리지 않음: plan은 사람에게 묻고 초안마다 승인을 받는 스킬이라, 초안 점검의 동작은 여러 턴의 답을 이어야 닿는다
2. 1의 규칙마다 글이 빠지면 실패하는 테스트가 `tests/test_skill_rules.py`에 있고, 이 task의 마지막 커밋에서 모든 테스트(001이 더한 run 테스트도)가 통과한다
   - 확인: `python3 -m unittest discover -s tests`의 마지막 줄이 `OK`
   - 확인: `mktemp -d`에 `git archive HEAD`를 풀어 plan 본문 6번에서 #53의 점검 글을 지우고 돌리면 실패한다. 다시 풀어 "조건"에서 #46의 해시 글을 지우고 돌리면 실패한다
3. tasks 완료 조건 5의 plan 쪽이 참이다: 이 task의 마지막 커밋에서 맥락 문서와 README가 1이 바꾼 동작과 001이 맞춘 run 줄에 어긋나지 않는다
   - 확인: `docs/ARCHITECTURE.md` 디렉터리 구조의 `test_skill_rules.py` 줄을 읽어 001의 run 규칙(#46, #47, #48, #51)과 이 task의 plan 규칙(#46, #52, #53)을 모두 담는다. `docs/PRD.md`의 3과 `README.md`의 `plan` 행을 읽어 1의 세 규칙과 어긋나는 줄이 없다(두 곳은 plan을 요약만 해서 세 규칙을 새로 적지 않아도 된다). 하나라도 어긋나면 실패
