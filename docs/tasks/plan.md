# 정리 점검 2026-10-28의 발견과 TOOLS.md를 정리한다

**이름**: cleanup-fixes

## 요청
정리 점검 보고서 `docs/cleanup/2026-10-28.md`의 발견 보안-1, 보안-2, 보안-3, 보안-4, 성능-1, 성능-2, 성능-3, 성능-4, 성능-5, 신뢰성-1, 신뢰성-2, 신뢰성-3, 신뢰성-4, 신뢰성-5, 신뢰성-6, 신뢰성-7, 신뢰성-8, 유지보수성-2, 유지보수성-4, 유지보수성-5, 유지보수성-6, 유지보수성-8, 유지보수성-10, 유지보수성-12, 기존 작업 정합성-1, 기존 작업 정합성-2, 기존 작업 정합성-3, 기존 작업 정합성-4, 기존 작업 정합성-5을 고친다. 발견마다의 근거, 심각도, 고치는 방향, 2라운드 판정은 보고서에 있다. 충돌이 적힌 발견은 어느 쪽으로 고칠지 정해야 한다.

함께 정한 것(사용자와 논의해 정함): `docs/TOOLS.md`를 줄여서 남긴다. (1) 계속 쓰이는 도구 사실(권한 모드와 플러그인 폴더 편집, 명령 치환·`git -C`가 막힘, 헤드리스 실행법과 허용 목록, CODEOWNERS·ruleset 동작, Codex 멈춘 지점과 도구를 넓힐 때 할 것)만 확인한 버전과 함께 남겨 약 10~15KB로 줄이고, 시험 실행 기록(장면을 돌려 본 것, 판정에서 본 것의 임시 경로·해시·커밋 id)은 지운다. (2) 시험 실행 기록은 더는 TOOLS.md에 적지 않고 phase 기록에만 둔다(plan의 확인·TODO 양식에서 TOOLS.md에 더하게 하지 않는다). (3) run의 "사용량이 돌아오지 않은 까닭을 TOOLS.md에 적는다" 규칙을 지우고 까닭은 RUNLOG와 보고에만 적는다. 그에 걸린 run의 괄호 글 7곳, eval 규칙 준수 표의 두 줄, 관련 테스트를 함께 고친다. (4) 새 사실은 다음 계획이 알아야 할 도구 동작일 때만 한 줄로 더한다. 이 결정으로 성능-1·성능-2의 TOOLS.md 비용은 대부분 풀리니, 두 발견은 이 결정에 맞춰 고친다. 열린 이슈 #59, #60, #61, #62는 기존 작업 정합성-1~4로 이 tasks에서 고친다.

## 목표

## 완료 조건
1. 단위 테스트가 모두 통과한다.
   - 확인: `python3 -m unittest discover -s tests`가 `OK`로 끝난다
2. `docs/TOOLS.md`가 15KB 이하이고, 다른 문서가 가리키는 네 절(`플러그인 폴더의 편집과 권한 모드`, `세션 도중의 스킬 본문 고침`, `ruleset과 CODEOWNERS로 워크플로 PR의 자동 머지를 막는지 본 것`, `도구를 넓힐 때 할 것`)이 남아 있고, 시험 실행 기록이 없다.
   - 확인: `wc -c < docs/TOOLS.md`가 15360 이하다
   - 확인: 네 절 이름마다 `grep -c '<절 이름>' docs/TOOLS.md`가 1 이상이다
   - 확인: `grep -cE '/var/folders/|tmp\.[A-Za-z0-9]{6,}|장면 [A-Z]' docs/TOOLS.md`가 0이다
3. plate 스킬 본문 어디에도 `docs/TOOLS.md`를 쓰거나 커밋하라는 규칙이 없고, 맥락 문서와 README에도 그 규칙을 말하는 줄이 없다.
   - 확인: `git grep -n 'TOOLS.md' -- plugins/`가 아무것도 내지 않는다
   - 확인: `git grep -nE '사용량.*TOOLS\.md|TOOLS\.md.*사용량' -- docs/PRD.md docs/ARCHITECTURE.md docs/ADR.md README.md AGENTS.md`가 아무것도 내지 않는다
4. 보고서에서 `처리: plan으로 넘김`인 발견 29건이 저마다 한 task 머리의 완료 조건에 들고, 그 task의 회고가 통과한다.
   - 확인: `grep -c '처리: plan으로 넘김' docs/cleanup/2026-10-28.md`가 29이고, 세 task 머리의 완료 조건에 적힌 발견 번호를 모으면 그 29건과 같다
   - 확인: 세 task의 `retro.md` 마지막 회고 절의 판정이 저마다 "통과"다

## 결정
- 성능-1·성능-2는 plan과 run이 맥락 문서를 모두 읽는 규칙을 그대로 두고, TOOLS.md를 줄여 갈음한다. 이유: 계획과 고침은 넓게 읽어야 판단이 맞고, 2라운드에서 읽을 것을 줄이면 권한·명령 사실을 놓친다는 지적이 있었다(추천안)
- 신뢰성-2는 run 1번에서 지금 브랜치가 기본 브랜치도 `tasks/<이름>`도 아니면 `tasks/<이름>`으로 바꿀지 묻게 고친다. 이유: 끝의 PR·머지가 늘 같은 이름을 보고, 세션을 다시 불러도 브랜치 이름을 따로 기억할 필요가 없다(추천안)
- #59(기존 작업 정합성-1)와 #62(기존 작업 정합성-2)는 plan의 기존 규칙만 넓히고 6번에 초안 점검 줄을 더하지 않는다. 이유: 본문이 덜 늘어난다(추천안)
- 스킬 동작의 확인은 `tests/test_skill_rules.py`의 단언으로 하고, 명령 단위로 돌려 볼 뜻이 있는 것(따옴표 처리, 상태 판정, 경로 고르기, 비움 뒤 재개를 가르는 git 명령)만 `mktemp -d`의 임시 폴더에서 돌린다. 에이전트를 띄우고 사용자에게 묻는 흐름은 돌리지 않고 까닭을 적는다. 이유: 지난 tasks의 장면 실행 기록이 TOOLS.md를 키웠다(추천안)
- 실행 전에 사용자가 plan 모드를 끄고 `plugins/plate/skills/` 쓰기를 허용한다(auto mode면 bypassPermissions로 바꾸거나 묻는 모드로 두고 편집마다 승인한다). 이유: `AGENTS.md` 작업 규칙과 `docs/TOOLS.md`의 "플러그인 폴더의 편집과 권한 모드"
- 발견마다 보고서의 "고치는 방향"과 2라운드 단서(예: 성능-5는 상한을 30보다 좁히지 않는다, 신뢰성-5는 점검을 빼지 않고 앞 task 머리를 읽게 한다)를 따른다. 이유: 요청이 보고서를 근거로 삼았다
