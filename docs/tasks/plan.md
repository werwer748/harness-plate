정리 점검 보고서 `docs/cleanup/2026-10-29.md`의 발견 보안-4, 성능-2, 성능-4, 성능-5, 성능-6, 성능-7, 신뢰성-1, 신뢰성-2, 신뢰성-3, 신뢰성-4, 신뢰성-5, 신뢰성-7, 신뢰성-8, 신뢰성-10, 유지보수성-1, 유지보수성-2, 유지보수성-3, 유지보수성-4, 유지보수성-5, 유지보수성-6, 기능 적합성-2, 기존 작업 정합성-1, 기존 작업 정합성-5, 기존 작업 정합성-7, 기존 작업 정합성-8을 고친다. 발견마다의 근거, 심각도, 고치는 방향, 2라운드 판정은 보고서에 있다. 충돌이 적힌 발견은 어느 쪽으로 고칠지 정해야 한다.

## 목표
보고서의 발견 24건(기존 작업 정합성-1을 뺀 것)을 훅, 판정 스크립트, CI 워크플로 양식, 스킬 본문, 테스트, 맥락 문서에서 고쳐, 테스트 묶음이 통과하고 바뀐 동작이 맥락 문서와 맞는다.

## 범위 밖
- 기존 작업 정합성-1(열린 이슈 7개 닫기). 계획을 쓴 뒤 tasks 밖에서 사용자 승인을 받아 닫는다.
- plate를 받는 ref(기본 브랜치)를 고정하는 것. ADR-021·022가 감수했다.
- 버전을 1.0.0으로 올리는 것. 별도 릴리스 tasks의 일이다.
- 결과물인 마크다운(스킬 본문)을 편집 훅이 막게 하는 것.

## 완료 조건
1. 테스트 묶음이 모두 통과한다.
   - 확인: `python3 -m unittest discover -s tests` → 마지막 줄이 `OK`
2. 편집 훅과 푸시 훅이 결정대로 돈다: 다시 수행하는 테스트 먼저 phase는 그 phase 커밋의 테스트 변경을 세고, 훅 안의 예외에서 편집 훅은 막고 푸시 훅은 글에 `push`가 있을 때만 막으며, 테스트 파일 삭제만은 테스트 변경으로 세지 않고, `.md` 편집은 git을 부르기 전에 통과한다(신뢰성-1·4·5·10, 성능-5·6, 유지보수성-5).
   - 확인: `docs/tasks/001-hook-fixes/plan.md`의 완료 조건 확인(임시 레포에서 훅에 JSON을 넣어 종료 코드를 보는 것)을 이 tasks의 마지막 커밋에서 다시 돌려 모두 기대대로다
3. 판정 스크립트가 깨진 입력에서 `request`를 내고 0으로 끝나고, CI 워크플로 양식의 액션이 커밋 SHA로 고정되고, 등급 묶음의 꼴 세 곳이 같은지 테스트가 본다(신뢰성-7, 보안-4, 유지보수성-1).
   - 확인: `printf 'not json' | python3 plugins/plate/ci/verdict.py; echo "exit=$?"` → `request`와 `exit=0`
   - 확인: `grep -nE 'uses: [^ ]+@' plugins/plate/skills/setup/SKILL.md` → 모든 줄의 `@` 뒤가 40자리 16진수이고 `# v` 주석이 붙는다
4. run, phase, cleanup, review 본문이 발견대로 고쳐지고 PRD·ARCHITECTURE의 같은 동작 줄과 맞는다(신뢰성-2·3·8, 기존 작업 정합성-5·7·8, 성능-2·4).
   - 확인: `docs/tasks/003-skill-fixes/plan.md`의 완료 조건 확인을 이 tasks의 마지막 커밋에서 다시 돌려 모두 기대대로다
   - 돌리지 않음: run·cleanup·review는 에이전트를 띄우고 사용자에게 묻는 스킬이라 헤드리스로 끝까지 돌리지 않는다. 본문의 명령 예만 시험 저장소에서 돌린다
5. 결과물인 마크다운을 편집 훅이 막지 않는다는 결정이 맥락 문서에 있고, PRD의 약속이 그만큼 좁혀진다(기능 적합성-2).
   - 확인: `grep -n '결과물인 마크다운' docs/ADR.md docs/ARCHITECTURE.md docs/PRD.md` → ADR의 새 항목, ARCHITECTURE의 "막는 장치" 문단, PRD의 목표나 핵심 기능 6에 막지 않는다는 줄이 저마다 하나 이상
6. 스킬 description 열 개가 저마다 400자 이하이고 테스트가 그 상한을 지키며, 테스트 도우미의 중복과 낡은 글이 정리된다(성능-7, 유지보수성-2·3·4·6).
   - 확인: `python3 -m unittest tests.test_skill_rules tests.test_manifests tests.test_cleanup_skill tests.test_edit_guard tests.test_push_guard` → `OK`
   - 확인: `grep -n '^def section' tests/test_cleanup_skill.py` → 아무것도 나오지 않음

## 결정
- 성능-5와 기능 적합성-2의 충돌은 편집 훅이 `.md`를 막지 않는 쪽으로 정하고, 결과물인 마크다운도 훅이 아니라 규칙 구간이 막는다고 ADR·ARCHITECTURE에 적어 PRD의 약속을 좁힌다. 이유: 008-tdd의 결정과 기존 테스트를 뒤집지 않고, 훅이 대상 프로젝트마다 ARCHITECTURE를 읽을 필요가 없다.
- 기존 작업 정합성-1은 tasks에 넣지 않고 계획을 쓴 뒤 이 세션에서 닫을 댓글을 보여 승인받아 닫는다. 이유: 되돌리기 어려운 바깥 일이라 사람이 보고 승인해야 하고, tasks 일괄에서는 에이전트가 묻지 않고 닫게 된다.
- 스킬 본문(`plugins/plate/skills/`)을 고치는 tasks라 run을 시작하기 전에 plan 모드를 끄고 bypassPermissions로 바꾸거나 묻는 모드로 둔다. 이유: AGENTS.md의 작업 규칙과 `docs/TOOLS.md`의 "플러그인 폴더의 편집과 권한 모드" (추천안으로 정함)
