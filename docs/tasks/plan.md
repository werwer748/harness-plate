# 열린 이슈 여섯 개를 고친다

**이름**: issue-sweep

## 요청
열린 GitHub 이슈 전부(#26, #27, #28, #29, #31, #32)를 처리한다

## 목표
plan, check, retro, review, eval, run의 본문이 여섯 이슈의 해결대로 바뀐다. 앞에서 고칠 파일을 줄 번호로 가리키지 않고, 동작을 바꾸는 완료 조건은 돌려 보는 확인이나 돌리지 않은 까닭을 갖고, 수행이 "남은 것"에 적은 결함을 확인과 회고가 판정하고, 계획의 커밋이 로컬 기본 브랜치에만 있으면 run이 알리고 묻고, 결과물인 마크다운만 바꾼 tasks의 테스트 적절성이 완료 조건의 확인으로 매겨지고, eval이 run의 정해 둔 물음을 멈춤으로 세지 않는다. 플러그인 버전은 0.15.0이 된다.

## 범위 밖
- 훅(`edit_guard.py`, `push_guard.py`)과 판정 스크립트(`verdict.py`)를 고치는 것
- 바뀐 스킬을 헤드리스 세션으로 돌려 보는 것. 셸로 재현되는 것만 돌린다
- Codex와 Grok Build에서 확인하는 것(ADR-018)
- GitHub 이슈를 닫는 것. PR이 머지된 뒤 사용자가 닫는다

## 완료 조건
1. (#26) plan의 적는 규칙 "phase의 파일"의 읽을 것 줄과 "조건"에 저마다, 같은 task의 앞 phase나 앞 task가 고칠 파일은 줄 번호 대신 절 이름이나 항목 이름으로 가리킨다는 줄이 있다. 6번의 초안 전 점검에는 줄 번호로 가리킨 읽을 것과 확인이 앞에서 고칠 파일을 가리키지 않는지, 같은 사실을 잇는 이웃 줄을 빠뜨리지 않는지 보는 줄이 있다.
   - 확인: `plugins/plate/skills/plan/SKILL.md`의 "phase의 파일", "조건", 6번을 하나씩 읽어 세 곳이 저마다 위의 것을 적는다. 한 곳이라도 없으면 실패
   - 돌리지 않음: plan은 사용자에게 묻고 승인받는 스킬이라 헤드리스로 돌리지 않는다
2. (#32) plan의 "조건"에, 스킬·훅·양식의 동작을 바꾸는 완료 조건에는 그 동작을 실제로 돌리는 확인(시험 저장소나 `mktemp -d`의 임시 디렉터리)을 두고, 돌릴 수 없으면 확인 줄과 따로 `- 돌리지 않음: {까닭}` 줄을 둔다는 줄이 있다. 6번의 점검과 양식(tasks 머리, task 머리)의 완료 조건도 그와 맞는다.
   - 확인: plan의 "조건", 6번, 양식의 tasks 머리 완료 조건, task 머리 완료 조건을 하나씩 읽어 네 곳이 저마다 위의 것과 맞는다. 한 곳이라도 없으면 실패
   - 돌리지 않음: 1과 같다
3. (#31) check는 기록의 "남은 것" 가운데 동작의 결함이나 돌려 보지 않은 위험을 적은 줄을 보고, 통과 조건이 보는 동작에 걸리면 확인 절의 "실패"로, 걸리지 않으면 "하네스에서 걸린 것"으로 옮긴다. retro는 `done-phase-N.md`마다 "남은 것"의 줄(부작용과 한계, 동작의 결함, 돌려 보지 않은 위험)을 모아 줄마다 문제인지 판정해 회고 절에 적는다.
   - 확인: `plugins/plate/skills/check/SKILL.md`의 절대 규칙 3, 절차, 확인 절의 양식, 적는 규칙을 읽어 위의 것이 서로 어긋나지 않게 적혀 있다
   - 확인: `plugins/plate/skills/retro/SKILL.md`의 4번과 회고 절의 양식을 읽어 위의 것이 적혀 있다
   - 확인: eval의 낱말 `done-phase-N.md`와 `retro.md`를 읽어 바뀐 확인 절과 회고 절의 꼴과 어긋나지 않는다
   - 돌리지 않음: check와 retro는 에이전트가 기록을 읽고 판정하는 스킬이라 헤드리스로 돌리지 않는다
4. (#29) run은 tasks 브랜치를 만들거나 바꾼 뒤 로컬 기본 브랜치에 origin의 기본 브랜치에 없는 커밋이 있으면, 그 커밋이 모두 tasks 브랜치에 있을 때는 그 커밋을 보여 주고 로컬 기본 브랜치를 origin의 것으로 되돌릴지 묻고(물은 자리 `기본 브랜치`) 승인하면 되돌리고, tasks 브랜치에 없는 커밋이 있으면 묻지 않고 그대로 둔다고 알린다. run의 낱말 "작업 트리의 스킬 줄"과 review의 낱말 "갈라진 곳"은 로컬 기본 브랜치의 `git merge-base <기본 브랜치> HEAD`라고 적는다.
   - 확인: `mktemp -d` 안에 bare 원격과 그 복제본을 만들고, 복제본의 기본 브랜치에 원격에 없는 커밋 하나를 더한 뒤 run 1번에 적힌 브랜치 만들기, 앞선 커밋 알아보기, 되돌리기 명령을 적힌 그대로 돌린다. 되돌리기 전에는 알아보기가 커밋 1개를, 되돌린 뒤에는 0개를 내고, 되돌린 뒤 `git merge-base <기본 브랜치> tasks/<이름>`이 원격 기본 브랜치의 끝이고, tasks 브랜치에 그 커밋이 남는다. 하나라도 다르면 실패. 임시 디렉터리는 지운다
   - 확인: run의 낱말 "작업 트리의 스킬 줄"과 review의 낱말 "갈라진 곳"을 읽어 둘 다 로컬 기본 브랜치의 merge-base라고 적는다
   - 확인: run의 `RUNLOG.md` 절의 물은 자리 목록에 `기본 브랜치`가 있다
5. (#27) review는 바뀐 코드 파일이 결과물인 마크다운뿐이면 테스트 적절성을 tasks 머리와 task 머리의 완료 조건이 바뀐 동작마다 돌려 보는 확인을 두었는지로 매기고, 등급표에 그 칸이 있다. 읽기만 하는 확인과 `돌리지 않음` 줄은 돌려 보는 확인보다 낮은 칸에 든다. PR 모드에서는 이 경우 판단 못함이다.
   - 확인: `plugins/plate/skills/review/SKILL.md`의 4번, 5번의 등급표와 그 아래 줄, PR 모드 절을 하나씩 읽어 위의 것이 적혀 있다
   - 돌리지 않음: review는 에이전트가 판단하는 스킬이라 헤드리스로 돌리지 않는다
6. (#28) eval의 낱말 "정해 둔 물음"은 run의 `RUNLOG.md` 절의 물은 자리 가운데 `멈춤` 말고 모두이고, "멈춤"은 물은 자리가 `멈춤`인 줄이다. retro 5번의 "멈춤"도 그와 맞는다.
   - 확인: run의 `RUNLOG.md` 절의 물은 자리 목록과 eval의 낱말 "정해 둔 물음"을 견줘, `멈춤`을 뺀 목록이 같다. 다르면 실패
   - 확인: retro 5번의 "멈춤" 줄을 읽어 eval의 낱말과 어긋나지 않는다
   - 돌리지 않음: eval은 에이전트가 기록을 세는 스킬이라 헤드리스로 돌리지 않는다
7. 두 매니페스트의 버전이 0.15.0이고, 마켓플레이스가 유효하고, 테스트가 통과하고, 맥락 문서와 README가 바뀐 동작과 맞는다.
   - 확인: `grep -h '"version"' plugins/plate/.claude-plugin/plugin.json plugins/plate/.codex-plugin/plugin.json`의 두 줄이 모두 `0.15.0`
   - 확인: `claude plugin validate .`의 마지막 줄이 `✔ Validation passed`
   - 확인: `python3 -m unittest discover -s tests`의 마지막 줄이 `OK`
   - 확인: `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/ADR.md`, `docs/TOOLS.md`, `README.md`를 문서마다 따로 읽어, 이 tasks가 바꾼 동작(완료 조건 1~6)과 어긋나는 줄이 없다

## 결정
- 결과물인 마크다운만 바꾼 tasks의 테스트 적절성은 완료 조건이 바뀐 동작마다 돌려 보는 확인을 두었는지로 매긴다. 이유: 등급이 하네스를 고칠지 정하는 데 쓰이고 #32와 맞물린다
- check는 "남은 것"의 결함·위험 줄이 통과 조건이 보는 동작에 걸리면 실패로, 걸리지 않으면 "하네스에서 걸린 것"으로 옮긴다. 이유: 적힌 것만 판정에 넣는다는 check의 규칙을 지키면서 결함을 그 자리에서 잡는다
- 계획의 커밋이 로컬 기본 브랜치에만 있으면 run은 tasks 브랜치를 만든 뒤 그 커밋을 보여 주고 로컬 기본 브랜치를 origin의 것으로 되돌릴지 묻는다. 새 물은 자리 `기본 브랜치`는 정해 둔 물음이다. 이유: 이슈가 제안한 안이고, 커밋은 tasks 브랜치에 남는다
- 돌릴 수 없는 완료 조건은 확인 줄과 따로 `- 돌리지 않음: {까닭}` 줄을 둔다. 이유: check와 retro의 "돌리지 않은 확인은 통과가 아니다"와 부딪히지 않고, review가 이 줄을 테스트 적절성의 근거로 읽는다
- 이 tasks의 확인은 본문을 읽어서 하고, 셸로 재현되는 것(#29의 git 장면)만 `mktemp -d`에서 실제로 돌린다. 에이전트가 도는 동작은 완료 조건에 `돌리지 않음`과 까닭을 적는다. 이유: #32가 만드는 규칙을 이 tasks가 먼저 따른다
- 버전은 0.15.0이다. 이유: 동작이 바뀌어 tasks마다 마이너를 올린다 (추천안으로 정함)
- `003-base-branch`의 회고 1에 따라 물음을 앞선 커밋이 모두 tasks 브랜치에 있을 때로 좁혔다. 이유: 이미 있던 tasks 브랜치로 바꾼 갈래에서 되돌리면 그 커밋이 어느 브랜치에도 남지 않는다
