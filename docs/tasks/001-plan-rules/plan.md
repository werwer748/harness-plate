# plan에 줄 번호 규칙과 돌려 보는 확인 규칙을 더한다

## 목표
plan 스킬이 앞에서 고칠 파일을 줄 번호 대신 절 이름이나 항목 이름으로 가리키게 하고(#26), 스킬·훅·양식의 동작을 바꾸는 완료 조건에 그 동작을 실제로 돌리는 확인을 두거나 돌리지 않은 까닭을 적게 한다(#32).

## 범위 밖
- plan 밖의 스킬을 고치는 것. check, retro, review는 뒤 task가 고친다
- 버전과 README. `005-release`가 한다

## 완료 조건
1. plan의 적는 규칙 "phase의 파일"의 읽을 것 줄과 "조건"에 저마다, 같은 task의 앞 phase나 앞 task가 고칠 파일은 줄 번호 대신 절 이름이나 항목 이름으로 가리킨다는 줄이 있다. 6번의 초안 전 점검에는 줄 번호로 가리킨 읽을 것과 확인이 앞에서 고칠 파일을 가리키지 않는지, 같은 사실을 잇는 이웃 줄을 빠뜨리지 않는지 보는 줄이 있다.
   - 확인: `plugins/plate/skills/plan/SKILL.md`의 "phase의 파일", "조건", 6번을 하나씩 읽어 세 곳이 저마다 위의 것을 적는다. 한 곳이라도 없으면 실패
   - 돌리지 않음: plan은 사용자에게 묻고 승인받는 스킬이라 헤드리스로 돌리지 않는다
2. plan의 "조건"에, 스킬·훅·양식의 동작을 바꾸는 완료 조건에는 그 동작을 실제로 돌리는 확인(시험 저장소나 `mktemp -d`의 임시 디렉터리)을 두고, 돌릴 수 없으면 확인 줄과 따로 `- 돌리지 않음: {까닭}` 줄을 둔다는 줄이 있다. 6번의 점검과 양식(tasks 머리, task 머리)의 완료 조건도 그와 맞는다.
   - 확인: plan의 "조건", 6번, 양식의 tasks 머리 완료 조건, task 머리 완료 조건을 하나씩 읽어 네 곳이 저마다 위의 것과 맞는다. 한 곳이라도 없으면 실패
   - 돌리지 않음: 1과 같다

## 결정
- 돌릴 수 없는 완료 조건은 확인 줄과 따로 `- 돌리지 않음: {까닭}` 줄을 둔다. 이 줄은 확인이 아니므로 "조건마다 `확인:` 줄을 하나 이상 붙인다"는 그대로다. 이유: check와 retro의 "돌리지 않은 확인은 통과가 아니다"와 부딪히지 않고, review가 이 줄을 테스트 적절성의 근거로 읽는다
