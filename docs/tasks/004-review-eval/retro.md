# 회고

## 회고 1

**확인**
- 1. review는 바뀐 코드 파일이 결과물인 마크다운뿐이면 테스트 적절성을 완료 조건이 바뀐 동작마다 돌려 보는 확인을 두었는지로 매기고, 등급표에 그 경우의 칸이 있다. 읽기만 하는 확인과 `돌리지 않음` 줄은 돌려 보는 확인보다 낮은 칸에 든다. PR 모드에서는 판단 못함이다.
  - `plugins/plate/skills/review/SKILL.md` 4번의 표(테스트 적절성 행), 5번의 등급표 아래 줄과 표 "결과물인 마크다운만 바뀐 경우의 테스트 적절성", PR 모드 절의 "등급을 매긴다"를 읽음 → 4번에 결과물인 마크다운뿐이면 tasks 머리와 task 머리의 완료 조건이 바뀐 동작마다 돌려 보는 확인을 두었는가를 보고 읽기만 하는 확인과 `돌리지 않음` 줄은 돌려 보는 확인이 아니라고 적혀 있다. 5번 아래 줄이 이 경우 커버리지 대신 새 표로 매긴다고 적고, 새 표는 A~E로 나뉘며 주된 동작에 읽기만 하는 확인이나 `돌리지 않음` 줄만 있으면 C·D로 돌려 보는 확인이 있는 A·B보다 낮다. PR 모드는 "판단 못함 — 완료 조건이 없다"다. 통과
- 2. eval의 "정해 둔 물음"은 run의 물은 자리 가운데 `멈춤` 말고 모두이고, "멈춤"은 물은 자리가 `멈춤`인 줄이다. eval 3번의 사람 개입률과 retro 5번의 "멈춤"도 그와 맞는다.
  - `plugins/plate/skills/run/SKILL.md` `RUNLOG.md` 절의 물은 자리(`실행 방식`, `커밋하지 않은 변경`, `기본 브랜치`, `고칠 phase`, `다음 task`, `멈춤`, `고칠지`)와 `plugins/plate/skills/eval/SKILL.md` 낱말 "정해 둔 물음"의 목록(`실행 방식`, `커밋하지 않은 변경`, `기본 브랜치`, `고칠 phase`, `다음 task`, `고칠지`)을 견줌 → `멈춤`을 뺀 여섯이 같다. 통과
  - eval 3번 사람 개입률("물은 자리가 `멈춤`이면 멈춤이고, 그 밖은 정해 둔 물음"), 2번 표의 "`RUNLOG.md`의 물은 줄 가운데 멈춤", `plugins/plate/skills/retro/SKILL.md` 5번의 "멈춤"(물은 자리가 `멈춤`인 줄에서 모으고 그 밖의 물은 자리는 멈춤이 아니다)을 읽음 → eval의 낱말과 어긋나지 않는다. 통과
- 3. `docs/ADR.md`의 ADR-024가 바뀐 테스트 적절성과 어긋나지 않는다.
  - ADR-024 트레이드오프를 읽음 → "테스트 적절성은 판단으로만 매긴다(바뀐 코드 파일이 결과물인 마크다운뿐이면 커버리지와 상관없이 완료 조건이 바뀐 동작마다 돌려 보는 확인을 두었는지로 매긴다)"로 그 경우와 어긋나지 않는다. 통과
- 4. tasks 완료 조건 3과 4 가운데 이 task가 고친 파일에 걸리는 것이 그대로 참이다.
  - `plugins/plate/skills/retro/SKILL.md` 4번과 회고 절의 양식, 적는 규칙을 읽음 → `done-phase-N.md`마다 "남은 것"의 줄(부작용과 한계, 동작의 결함, 돌려 보지 않은 위험)을 모아 줄마다 문제인지 판정해 회고 절의 "남은 것"에 적는다고 있다. 통과
  - eval 낱말 `done-phase-N.md`(확인 절에 "남은 것", "실패", "하네스에서 걸린 것", "판정")와 `retro.md`("확인", "남은 것", "문제", "판정")를 `plugins/plate/skills/check/SKILL.md`의 확인 절 양식(통과 조건, 명령, 테스트 먼저 기록, 남은 것, 실패, 하네스에서 걸린 것, 판정)과 retro의 회고 절 양식(확인, 남은 것, 문제, 판정)에 견줌 → 어긋나지 않는다. 통과
  - review 낱말 "갈라진 곳"을 읽음 → `git merge-base <기본 브랜치> HEAD`이고 `<기본 브랜치>`는 원격 추적 ref가 아닌 로컬 기본 브랜치라고 적혀 있다. 통과

**남은 것**
- phase 1: review의 새 테스트 적절성 표는 확인이 돌려 보는 것인지 읽기만 하는 것인지를 review 에이전트의 판단으로 가른다. 확인 줄의 글이 애매하면 칸이 갈릴 수 있다 → 문제 아님 (tasks 머리와 task 머리의 결정이 "완료 조건이 바뀐 동작마다 돌려 보는 확인을 두었는지로 매긴다"고 판단으로 매기기를 정했고, 4번의 표가 읽기만 하는 확인과 `돌리지 않음` 줄은 돌려 보는 확인이 아니라고 가르는 기준을 적어 동작이 틀리지 않는다)
- phase 1: 완료 조건 1과 2의 확인은 읽기만 하는 확인이고 review와 eval을 실제로 돌려 보지 않았다 → 문제 아님 (tasks 머리의 범위 밖 "바뀐 스킬을 헤드리스 세션으로 돌려 보는 것"과 결정 "에이전트가 도는 동작은 완료 조건에 `돌리지 않음`과 까닭을 적는다"대로이고, task 머리 완료 조건 1·2에 `돌리지 않음` 줄이 있다)
- phase 1: PR 모드의 등급 묶음 JSON에는 테스트 적절성 키가 없어 PR 모드의 "판단 못함"은 평가서 파일에만 드러난다 → 문제 아님 (review의 등급 묶음 표는 키를 `build`, `lint`, `test`, `coverage`, `reliability`, `security`, `maintainability`로 정하고 테스트 적절성은 처음부터 판정에 들지 않는다. 완료 조건 1은 PR 모드 절에 판단 못함이 적혀 있기를 요구하고 그렇게 적혀 있다. 판정 스크립트는 tasks 머리의 범위 밖이다)
