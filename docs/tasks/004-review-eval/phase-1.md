## 한 일
- review 4번의 표에서 테스트 적절성이 보는 것에, 바뀐 코드 파일이 결과물인 마크다운뿐이면 tasks 머리와 task 머리의 완료 조건이 바뀐 동작마다 돌려 보는 확인을 두었는지를 본다는 것이 더해진다: 테스트 적절성 행의 "보는 것"에 그 경우와, 읽기만 하는 확인과 `- 돌리지 않음: {까닭}` 줄은 돌려 보는 확인이 아니라는 것을 더했다 (`plugins/plate/skills/review/SKILL.md`)
- review 5번에 결과물인 마크다운만 바뀐 경우의 테스트 적절성 칸(A~E)이 더해진다: 등급표 아래 줄에 이 경우 커버리지 대신 새 표로 매기고 읽기만 하는 확인과 `돌리지 않음` 줄은 돌려 보는 확인보다 낮은 칸에 든다는 줄을 더하고, 표 "결과물인 마크다운만 바뀐 경우의 테스트 적절성"(A 바뀐 동작마다 돌려 보는 확인, B 빠진 것은 엣지케이스뿐, C 주된 동작 가운데 읽기만/돌리지 않음뿐인 것이 있음, D 절반 넘게 없거나 돌려 보는 확인이 하나도 없음, E 확인이 하나도 없음)을 더했다 (`plugins/plate/skills/review/SKILL.md`)
- review의 PR 모드 절에 바뀐 코드 파일이 결과물인 마크다운뿐이면 테스트 적절성이 판단 못함(완료 조건이 없다)이라는 줄이 더해진다: "등급을 매긴다" 줄에 "판단 못함 — 완료 조건이 없다"와 그 까닭을 더했다 (`plugins/plate/skills/review/SKILL.md`)
- eval의 낱말 "정해 둔 물음"이 run의 `RUNLOG.md` 절의 물은 자리 가운데 `멈춤` 말고 모두로, "멈춤"이 물은 자리가 `멈춤`인 줄로 바뀌고, 3번의 사람 개입률이 그와 맞게 바뀐다: 두 낱말을 물은 자리로 정의하고(목록 `실행 방식`, `커밋하지 않은 변경`, `기본 브랜치`, `고칠 phase`, `다음 task`, `고칠지`), 사람 개입률의 가르는 줄을 물은 자리로 가른다고 고쳤다 (`plugins/plate/skills/eval/SKILL.md`)
- retro 5번의 "멈춤" 줄이 eval의 낱말과 맞게 바뀐다: 물은 자리가 `멈춤`인 줄에서 모으고 그 밖의 물은 자리는 멈춤이 아니라고 고쳤다 (`plugins/plate/skills/retro/SKILL.md`)
- ADR-024의 트레이드오프에서 테스트 적절성을 말하는 문장이 결과물인 마크다운만 바뀐 경우와 어긋나면 맞게 바뀐다: "테스트 적절성은 판단으로만 매긴다" 뒤에 결과물인 마크다운뿐이면 완료 조건의 돌려 보는 확인으로 매긴다는 괄호를 더했다 (`docs/ADR.md`)

## 남은 것
- review의 새 테스트 적절성 표는 완료 조건이 그 동작을 "돌려 보는" 확인인지 "읽기만 하는" 확인인지를 review 에이전트의 판단으로 가른다. 확인 줄의 글이 애매하면 칸이 갈릴 수 있다
- 이 phase의 완료 조건 1과 2의 확인은 읽기만 하는 확인이고 review와 eval을 실제로 돌려 보지 않았다(계획의 `돌리지 않음` 줄대로). 새 칸으로 매긴 등급이 실제 평가에서 어떻게 나오는지는 돌려 보지 않은 위험이다
- PR 모드의 등급 묶음 JSON에는 테스트 적절성 키가 없어, PR 모드의 "판단 못함"은 평가서 파일에만 드러난다
