# context 스킬에 칸 규칙과 저장소 밖 규칙을 더한다

## 요청
context 스킬(plugins/plate/skills/context/SKILL.md)에 규칙 둘을 더한다. 첫째, 칸이 문장 중간에 있거나 한 칸이 여럿을 물을 때의 규칙. 2단계의 자기 
  적용에서 본 것은 셋이다: 칸 앞에 쉼표가 더해졌다, "없음" 답이 끊긴 문장이 됐다, 일부만 답한 칸이 닫혔다. 둘째, 스캔 목록 밖의 파일(레포 밖의 메모리 파일)을 읽지 않게
  하는 규칙.

## 목표
context 스킬 본문에 문장 중간에 있는 칸과 여럿을 묻는 칸을 적는 규칙, 저장소 밖의 파일을 열지도 근거로 쓰지도 않는 절대 규칙이 생긴다. 2단계 자기 적용 직전의 문서를 고친 본문으로 다시 채웠을 때 그때 본 것(더해진 쉼표, 끊긴 "없음", 닫힌 칸, 저장소 밖의 파일 읽기)이 다시 나오지 않는다.

## 범위 밖
- `docs/ADR.md`에 이미 적힌 두 문장(ADR-018의 "멈춘 이유는 없음", ADR-019의 "…뺀 이유는, 앞의 것은 없음이고 …")을 고치는 것
- 시험 폴더에 대응하는 도구의 메모 위치에 메모 파일을 만들어 두고 시험하는 것
- Codex에서 같은 결과를 확인하는 것(ADR-018)
- 플러그인의 버전을 올리는 것. 버전은 단계마다 정한다(ADR-020, ADR-032)

## 완료 조건
1. 본문의 "답을 적는 규칙"에 문장 중간에 있는 칸의 규칙이 있다. 칸 자리의 글만 바꾸고 칸 앞뒤의 글자는 더하지도 빼지도 않는다. 답은 앞뒤 글에 이어져 한 문장으로 읽히게 다듬는다. 없다고 답한 것도 이어지는 문장으로 적고, 줄 전체가 칸이면 지금처럼 "없음"으로 적는다.
   - 확인: `grep -c '문장 중간' plugins/plate/skills/context/SKILL.md` → 1 이상
   - 확인: 본문의 "답을 적는 규칙" 절을 읽어 위 네 가지가 모두 적혀 있는지 본다
2. 본문에 한 칸이 여럿을 물을 때의 규칙이 있다. 질문은 칸마다 하나로 낸다. 답에 빠진 갈래가 있으면 그 갈래만 한 번 더 묻는다. 그래도 답을 받지 못한 갈래는 그 자리에 `{확인 필요}`로 남겨 칸을 닫지 않는다.
   - 확인: `grep -c '여럿' plugins/plate/skills/context/SKILL.md` → 1 이상
   - 확인: 본문에서 "여럿"이 나온 곳을 읽어 위 세 가지가 모두 적혀 있는지 본다
3. 본문의 절대 규칙에 다섯째 항목이 있다. 저장소 밖의 파일을 열지 않는다. 도구가 세션에 이미 실어 둔 저장소 밖의 내용도 칸의 내용이나 추천안의 근거로 쓰지 않는다. 2번 "스캔한다"의 글이 이 규칙과 어긋나지 않고, 본문에 도구 이름이 없다.
   - 확인: `grep -c '^5\. \*\*.*저장소 밖' plugins/plate/skills/context/SKILL.md` → 1
   - 확인: `grep -ciE 'claude|codex|grok' plugins/plate/skills/context/SKILL.md` → 0
   - 확인: 본문의 절대 규칙 5와 2번 절을 읽어 여는 것과 근거로 쓰는 것이 둘 다 적혀 있는지, 2번 절이 목록 밖에서 열 수 있는 것을 저장소 안의 소스 파일로만 두는지 본다
4. 고친 본문으로 `~/plate-rail-test/ctx-cells`(이 레포를 커밋 `7c37c9b`로 맞춘 복제본)에서 맥락 채우기를 돌린 결과에 2단계 자기 적용에서 본 넷이 없다. 답은 세 칸(ADR-010, ADR-018, ADR-019의 문장 중간 칸)에만 주고 그 밖의 칸은 모두 미룬 실행이다.
   - 확인: `git -C ~/plate-rail-test/ctx-cells status --short` → ` M docs/ADR.md` 한 줄
   - 확인: `git -C ~/plate-rail-test/ctx-cells diff --numstat -- docs/ADR.md` → `3	3	docs/ADR.md`(더한 줄 3, 뺀 줄 3)
   - 확인(쉼표): `git -C ~/plate-rail-test/ctx-cells diff -U0 -- docs/ADR.md | grep '^+' | grep -c '이유는,'` → 0
   - 확인(쉼표): `grep -c '판정하는 이유는 특정 프로젝트' ~/plate-rail-test/ctx-cells/docs/ADR.md` → 1
   - 확인(끊긴 "없음"): `grep -c '멈춘 이유는 없음' ~/plate-rail-test/ctx-cells/docs/ADR.md` → 0
   - 확인(끊긴 "없음"): `grep -c '멈춘 이유는 [^{]*\.$' ~/plate-rail-test/ctx-cells/docs/ADR.md` → 1
   - 확인(닫힌 칸): `grep -c '뺀 이유는 .*{확인 필요}' ~/plate-rail-test/ctx-cells/docs/ADR.md` → 1

   - 확인: `grep -c '(ADR-034로 바뀜)' docs/ADR.md` → 1
   - 확인: `docs/ADR.md` 첫머리의 원장 설명을 읽어, 작업에서 나온 결정은 원장 줄에 작업 폴더를 적는다는 문장이 있는지 본다

## 결정
- 문장 중간에 있는 칸은 칸 자리의 글만 바꾸고 칸 앞뒤의 글자는 더하지도 빼지도 않는다. 이유: context 스킬의 절대 규칙 3(남은 칸이 아닌 곳은 고치지 않는다) 그대로다. (추천안으로 정함)
- 문장 중간에 있는 칸에 없다고 답하면 앞 글에 이어지는 문장으로 적는다(`멈춘 이유는 {확인 필요}`에 "없음"이면 `멈춘 이유는 없다.`). 줄 전체가 칸이면 지금처럼 "없음"으로 적는다. 다른 안은 "'없음'을 두고 문장만 닫는다", "칸이 든 문장을 다시 쓴다"였다. 이유: 답은 뜻을 바꾸지 않는 범위에서 문서 문체로 다듬는다는 지금 규칙과 절대 규칙 3에 맞고, "없음"만 예외로 두지 않고 중간 칸의 모든 답에 같은 규칙을 쓸 수 있다.
- 한 칸이 여럿을 물으면 질문은 칸마다 하나로 내고, 답에 빠진 갈래가 있으면 그 갈래만 한 번 더 묻는다. 그래도 답을 받지 못한 갈래는 그 자리에 `{확인 필요}`로 남긴다. 추천안은 "갈래마다 따로 묻는다"였고, 다른 안은 "하나라도 비면 칸 전체를 남긴다"였다. 이유: 사용자가 말하지 않았다.
- 저장소 밖 규칙은 여는 것과 근거로 쓰는 것을 둘 다 막는다. 다른 안은 "여는 것만", "저장소 안의 목록 밖 파일까지"였다. 이유: 추천안은 저장소에 근거가 있을 때만 붙인다는 결정(ADR-013)과 같은 방향이고, 열지 않게만 하면 세션에 이미 실린 메모는 막지 못한다.
- 그 규칙은 절대 규칙의 다섯째 항목으로 두고, 2번 "스캔한다"의 글은 그 규칙과 맞게만 고친다. 다른 안은 "2번 절에만 둔다", "절대 규칙 3에 문장으로 붙인다"였다. 이유: 2번 절에 "아래 목록만 읽는다"가 있었는데도 자기 적용에서 지켜지지 않았다. 계획 스킬도 판정에서 본 것을 절대 규칙에 넣었다(ADR-030).
- 확인은 본문을 보는 것과 실제 실행 둘로 한다. 시험 문서는 2단계 자기 적용 직전(커밋 `7c37c9b`)의 이 레포다. 다른 안은 "메모 파일을 미끼로 둔다", "본문만 본다"였다. 이유: 완성은 실제 실행으로 판정하고(ADR-010), 고친 곳에 걸리는 것만 다시 돌린 전례가 있고, 시험 폴더는 `~/plate-rail-test`다(ADR-019).
- 이미 적힌 두 문장은 고치지 않는다. 이유: 요청은 스킬 본문에 규칙을 더하는 것이고, ADR-019의 닫힌 칸은 답하지 않은 갈래의 답이 있어야 고칠 수 있다.
- ADR-034의 원장 줄에는 작업 폴더를 적고, `docs/ADR.md` 첫머리의 원장 설명에 그 문장을 더한다. 다른 안은 "원장 줄을 두지 않는다", "'원장: 없음'으로 적는다"였다. 이유: 원장 줄은 결정이 나온 곳을 가리키는 줄이고, 검증까지 통과한 작업의 폴더에는 머리만 남은 `plan.md`가 남아(ADR-022) 가리킬 곳이 있다.
