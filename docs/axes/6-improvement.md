# 6축. 개선 — 단순화

> [HANDOFF.md](../../HANDOFF.md)에서 나눈 6축 문서다. 표시(기본값·결정·보류·남음)의 뜻과 기호(J, R, M1–M4)는 HANDOFF.md에 있다. 결정을 확정하거나 바꾸면 아래 표와 [결정 기록](../decisions.md)을 함께 고친다.

**다루는 질문**: 하네스를 어떻게 키우고, 무엇을 **덜어내는가**.

| | 레퍼런스와 내 자산 |
|---|---|
| 루프 | **R** `evolve`: 델타 수집 → 분류·매핑표 → 일반화 → 변경 이력 → 검증([부록 C](../references.md))<br>**J**: 개선 메커니즘이 없다(커밋 6개, 머지된 PR 0개) |
| 근거 | **M2**: 리뷰어 속도를 A/B로 측정했다(401s/17턴 → 207s/6턴)<br>**M4**: 훅 타이밍과 시간 분포<br>matcher 버그로 한 번도 발동하지 않은 훅을 발견했다 |
| 버전 | **R**: SemVer, CHANGELOG, `plugin.json` = `marketplace.json` = README 뱃지 버전 일치 검사 |

**결정과 처리**

| # | 결정 | 처리 |
|---|---|---|
| 1 | 교훈이 흐르는 경로: 프로젝트에서 기록 → 하네스에 반영. 누가, 언제, 어디에 적는지 | **기본값**: 매 작업 회고는 하지 않는다. 같은 피드백·실패가 2회 이상이거나, 모델을 바꾸거나, 사용자가 요청할 때만 반영한다. 반영은 일반화해서 한 번에 하나씩 한다(R evolve의 이 두 원칙은 유지한다) |
| 2 | **제거 기준**: 발동하지 않은 훅, 쓰이지 않는 스킬, 효과를 측정하지 못한 규칙을 어떻게 찾아 지울지 | **결정**: 장치를 더할 때 그 파일 안(훅 머리 주석, 스킬·규칙 본문)에 "어떤 실패를 막는지"를 한 줄로 적는다. 모델을 바꾸거나 장치가 작업을 방해했을 때 꺼 보고 다시 판단한다. 발동하지 않았다는 사실만으로 지우지 않는다(대상 작업이 없었는지, 배선이 틀렸는지, 드물지만 중요한 실패를 막는지 구분한다) |
| 3 | 측정 수단: M4를 개선 루프의 증거 수집기로 삼을지 | **결정**: M4를 증거 수집기로 삼고 토큰 합산을 추가한다. 세션 기록(jsonl)의 메시지별 `usage`를 메인과 서브에이전트(`<세션>/subagents/`)별로 합산한다. 같은 메시지가 여러 줄에 반복되므로 message id로 중복을 없앤다. 지난 세션에도 소급 적용된다. 사용자 개입 횟수와 완료 뒤 발견한 결함은 작업당 한 줄로 수기 기록한다. `/usage`와 `/insights`는 보조로 쓴다. 2026-10-04에 구현했다: 세션별 토큰 줄, 요약의 토큰 열, 모든 프로젝트를 훑는 `--all` |
| 4 | 버전·릴리스 정책과 회고 주기 | **기본값**(2026-10-04): 버전은 `plugins/plate/.claude-plugin/plugin.json`에만 둔다(0.1.0에서 시작). 플러그인 파일이 바뀌는 PR마다 올린다(설치본은 캐시라 버전이 올라가야 반영된다. M2의 함정). CHANGELOG는 두지 않고 git 기록을 쓴다. 회고 주기는 따로 두지 않고 1번을 따른다 |
| 5 | v0.1 범위 | **결정**: 기본 흐름과 기록이다. 6축 결정을 모두 마치는 것을 선행 조건으로 삼지 않는다 |
