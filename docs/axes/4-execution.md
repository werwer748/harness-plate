# 4축. 실행하기 — 혼자 / Subagent / Team / Ralph Loop

> [HANDOFF.md](../../HANDOFF.md)에서 나눈 6축 문서다. 표시(기본값·결정·보류·남음)의 뜻과 기호(J, R, M1–M4)는 HANDOFF.md에 있다. 결정을 확정하거나 바꾸면 아래 표와 [결정 기록](../decisions.md)을 함께 고친다.

**다루는 질문**: 이 일을 누가, 몇 명이, 몇 번 반복해서 하는가.

| 모드 | 레퍼런스와 내 자산 |
|---|---|
| 혼자 | 메인 세션이 직접 한다 |
| Subagent | 일회성으로 결과만 돌려받는다. **R**: 전문가 풀. **M1**: 백그라운드 리뷰어·러너 |
| Team | **R** v2의 지속형 에이전트(`SendMessage`, `TaskCreate`)와 Workflow(`pipeline`/`parallel`). 패턴 6개는 [부록 B](../references.md) |
| Ralph Loop | **J** `execute.py`: step마다 새 세션을 열고 최대 3회 재시도하며 summary를 이월한다. Claude Code `/loop`도 있다 |

**결정과 처리**

| # | 결정 | 처리 |
|---|---|---|
| 1 | 모드 선택 기준표. **R**의 결정 순서는 "코드로 표현 가능 → 워크플로, 대화 필요 → 지속형, 결과만 필요 → 서브에이전트"이다. 이걸 그대로 쓸지 내 기준으로 바꿀지 | **기본값**: 혼자가 기본이다. R의 결정 순서는 위임이 필요하다고 판단한 뒤에만 쓴다. 위임 조건은 셋이다: 탐색·긴 출력의 격리, 서로 독립인 작업의 분담, 새 컨텍스트 리뷰. 워크플로는 사용자가 명시적으로 요청한 대규모 작업에만 쓰고, 에이전트 팀은 v0.1에서 뺀다 |
| 2 | 모델 티어 정책(fable/opus/sonnet)을 역할별로 고정할지 | **보류.** 서브에이전트를 실제로 쓰게 된 뒤에 정한다. 그 전에는 세션 모델을 상속한다 |
| 3 | 재시도 상한을 **한 층에만** 둘 것(M3: 3×3=9회 이중 재시도) | **기본값(유지)**: 플랫폼 상한을 그 한 층으로 쓴다. 스킬이나 프롬프트에 "N회 시도" 문구를 따로 넣지 않는다 |
| 4 | 격리 수단: 워크트리, 설정 소스 제한, 비용·시간 상한 | **보류.** 무인 실행이나 병렬 수정을 켤 때 정한다 |
| 5 | 커밋 주체를 하나로 할 것(M3: 모델과 executor가 둘 다 커밋했다) | **기본값(유지)**: 상호작용 세션에서는 사용자가 요청할 때 메인이 커밋한다. 무인 실행에서는 executor만 커밋한다 |
| 6 | (2026-10-04 추가) Ralph Loop를 v0.1에 넣을지 | **결정**: v0.1에서 뺀다. 자리를 비우고 싶을 때는 `/goal`과 auto mode를 그때그때 쓴다. 실제 작업에서 내장 기능이 두 번 부족하면 다시 연다. 그때도 `execute.py`를 만들기 전에 `/goal`과 `claude -p`로 먼저 해 보고, step마다 새 세션을 여는 방식은 기본으로 삼지 않는다 |
| 7 | (2026-10-04 추가) 작업을 어느 브랜치에서 하는가 | **결정**: 새 작업이나 phase를 시작할 때 브랜치를 만들지 사용자에게 묻는다. 기본 브랜치(main·master)에서의 파일 수정과 `git commit`은 플러그인 `plate`의 PreToolUse 훅 `plugins/plate/hooks/branch-guard.sh`로 막고, 사용자가 기본 브랜치에서 하겠다고 한 세션에서만 푼다(`<git-dir>/plate-main-ok`에 세션 ID). 플러그인을 켠 곳에서 돈다. 테스트는 `tests/test-branch-guard.sh`다. 셸로 파일을 쓰는 것은 막지 않는다 |
