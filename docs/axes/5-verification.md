# 5축. 검증하기 — Generator/Evaluator 분리 / 모델 교차검증

> [HANDOFF.md](../../HANDOFF.md)에서 나눈 6축 문서다. 표시(기본값·결정·보류·남음)의 뜻과 기호(J, R, M1–M4)는 HANDOFF.md에 있다. 결정을 확정하거나 바꾸면 아래 표와 [결정 기록](../decisions.md)을 함께 고친다.

**다루는 질문**: "끝났다"를 누가, 무엇을 근거로 판정하는가.

| | 레퍼런스와 내 자산 |
|---|---|
| 결정적 검증 | **J**: Stop 훅의 lint/build/test(`exit 1`이라 모델에 전달되지 않는다)<br>**M2**: `check.sh` 불변식 lint, TDD 게이트(새 파일 생성 시점), `tdd-red`, 래칫 2개 |
| 분리 | **R**: 생성·검증 패턴, QA 에이전트는 Explore로 두지 않는다, 생산자·소비자 교차 확인<br>**M1**: 읽기 전용 리뷰어를 강제하고, 판정 줄을 파싱하고, `unknown`은 통과로 치지 않는다 |
| 교차검증 | **R**: 적대적 검증, 심사위원단, 과반 `confirmed`만 통과<br>모델 교차(다른 티어나 다른 CLI)는 두 레퍼런스 모두 정식으로 쓰지 않는다 |
| 게이트 | **M1**: Stop `exit 2` 게이트와 탈출구 3개, `harness_touched` 표시 |

**결정과 처리**

| # | 결정 | 처리 |
|---|---|---|
| 1 | 검증 층위: 결정적(명령) → 판단(리뷰어) → 사람. 층마다 무엇을 맡길지 | **기본값**: 결정적 검사는 항상 한다. 리뷰어는 조건이 있을 때 1명만 붙인다(고위험 변경, 검사로 확인하기 어려운 품질, 무인 실행). 생성과 평가를 분리한다는 원칙은 유지한다. 과반 판정, 심사위원단, loop-until-dry는 v0.1에서 뺀다 |
| 2 | 완료 판정 주체: 모델의 자기보고를 없애고 하네스(훅·executor)가 판정할지 | **기본값**: 검사마다 실행 책임자를 하나만 둔다. 상호작용 세션에서는 작업자가 검사를 돌려 증거를 보이고 사람이 판정한다. 무인 실행에서는 하네스가 판정한다(M3 #3). 검사 대상이 바뀌지 않았으면 결과를 재사용하고, 같은 검사를 다른 주체가 다시 돌리지 않는다 |
| 3 | 교차검증에 쓸 조합: 같은 모델의 다른 컨텍스트 / 다른 티어 / 다른 벤더 | **보류.** 기본 리뷰는 같은 모델의 새 컨텍스트다. 다른 티어나 벤더는 리뷰어가 놓친 결함이 기록된 뒤에 검토한다 |
| 4 | 판정 형식 표준: 기계가 읽을 수 있는 verdict 줄 | **보류.** 훅이 리뷰 결과를 파싱하게 될 때 정한다. M1의 "`unknown`은 통과가 아니다"는 그대로 가져온다 |
| 5 | 게이트 강도: 차단(block) / 확인 요청(ask) / 보고만(report) 중 무엇으로 할지 | **기본값**: 보고다. 차단은 옵트인한 사이클과 무인 실행에서만 건다(M1: `.cycle-state`가 없으면 훅은 아무 일도 하지 않는다). 코드가 바뀌지 않은 턴에서는 Stop 검사를 돌리지 않는다(M3 #2) |
