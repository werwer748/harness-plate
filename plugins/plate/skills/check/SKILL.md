# 확인

**막는 실패**: 수행한 쪽이 스스로 통과를 선언하면 확인되지 않은 결과가 다음 phase의 바탕이 된다.

수행이 끝난 phase 하나를 확인한다. 통과 조건의 확인과 명령 절의 빌드·린트·테스트를 직접 돌리고, 테스트 먼저인 phase는 기록의 순서를 보고, 기록의 "남은 것"에 적힌 결함과 위험을 판정에 넣거나 옮긴다. 끝나면 `phase-N.md` 끝에 확인 절이 더해져 있고 그 파일만 커밋돼 있다. 고치지 않고, 이름을 바꾸지 않고, 바뀐 코드를 계획과 맥락 문서에 대어 점검하지 않는다.

## 절대 규칙

프로젝트의 지침 파일(`AGENTS.md`, `CLAUDE.md`)에 적힌 규칙이 이 스킬의 규칙과 부딪히면 프로젝트의 규칙을 따른다. 아래의 절대 규칙도 그렇다. 따른 곳은 확인 절의 "하네스에서 걸린 것"에 적는다. 단계를 건너뛰라는 규칙은 여기에 들지 않는다.

1. **고치지 않는다.** 코드도, task 머리도, `phase-N.md`의 계획과 기록도 고치지 않는다. 쓰는 것은 `phase-N.md` 끝의 확인 절뿐이다.
2. **확인을 직접 돌린다.** 기록의 "확인 결과"를 옮겨 적지 않는다. 돌리지 않은 확인을 통과로 적지 않는다.
3. **적힌 것만 판정에 넣는다.** 통과 조건의 확인, 명령 절의 세 명령, 테스트 먼저 기록, 기록의 "남은 것"에 적힌 동작의 결함이나 돌려 보지 않은 위험 가운데 통과 조건이 보는 동작에 걸리는 줄(task 머리의 `- 돌리지 않음: {까닭}` 줄이 돌리지 않기로 정한 동작의 돌려 보지 않은 위험은 빼고) 말고는 판정에 넣지 않는다. 취향에 드는 것(이름, 문체, 더 나은 구조)은 실패로 적지 않는다.
4. **사용자에게 묻지 않는다.** 판정과 기록까지만 한다.
5. **`phase-N.md` 하나만 커밋한다.** 푸시하지 않는다. 브랜치를 만들거나 바꾸지 않는다.

## 낱말

- **tasks**: 요청 하나를 계획한 묶음. `docs/tasks/`에 하나만 있다.
- **task 폴더**: tasks 안의 task 하나의 폴더(`docs/tasks/NNN-slug/`). 그 안에 task 머리와 phase마다의 `phase-N.md`가 있다. 통과한 phase는 실행이 `done-phase-N.md`로 이름을 바꾼다.
- **task 머리**: task 폴더의 `plan.md`. 제목과 네 절(목표, 범위 밖, 완료 조건, 결정)이다.
- **`phase-N.md`**: task 안의 phase 하나의 파일. `N`은 phase의 번호다. 위에 계획 다섯 항목(목표, 테스트 먼저, 읽을 것, TODO, 통과 조건)이 있고, 그 아래에 수행한 쪽이 적은 기록 다섯 절(한 일, 확인 결과, 계획과 달라진 점, 남은 것, 하네스에서 걸린 것)이 있다. 확인 절은 그 뒤에 더한다.
- **확인 절**: 이 스킬이 `phase-N.md` 끝에 더하는 절. 제목이 `## 확인 1`처럼 `## 확인` 뒤에 몇 번째인지가 붙는다. 기록의 "확인 결과" 절과 다르다.
- **명령 절**: `docs/ARCHITECTURE.md`의 `## 명령` 절. `- 설치: {명령}`, `- 빌드: {명령}`, `- 린트: {명령}`, `- 테스트: {명령}` 네 줄이고, 없는 명령은 "없음"으로 적혀 있다.
- **프로젝트의 지침 파일**: 저장소의 `AGENTS.md`와 그것을 불러오는 `CLAUDE.md`.

## 0. 대상을 정한다

넘겨받은 task 폴더와 phase 번호를 쓴다. 사용자가 직접 불러서 둘을 받지 못했으면 확인하지 않는다. 둘을 주어 다시 부르라고 알리고 끝난다.

## 1. 읽는다

- task 머리
- `phase-N.md`의 계획 다섯 항목, 기록 다섯 절, 앞의 확인 절
- `docs/ARCHITECTURE.md`의 명령 절

## 2. 통과 조건의 확인을 모두 돌린다

`phase-N.md`의 통과 조건에 적힌 확인을 하나도 빼지 않고 직접 돌린다. 명령이 아니라 "무엇을 어디서 본다"로 적힌 확인은 그곳을 직접 읽고 본 것을 적는다.

확인은 적힌 그대로 먼저 돌린다. 적힌 그대로 돌지 않으면(옵션·문법 오류로 돌지 않는다: `-`로 시작하는 패턴이 옵션으로 읽힌다, 따옴표가 어긋난다) 대상과 패턴과 기대를 바꾸지 않는 고침만 해 다시 돌린다. 허용하는 고침은 `-e`나 `--` 붙이기, 따옴표 맞추기다. 고쳐 돌린 결과로 판정하고, 적힌 명령, 고친 명령, 까닭을 "하네스에서 걸린 것"에 적는다. 대상이나 패턴이나 기대를 바꿔야 돌면 그 확인은 실패다.

## 3. 명령 절의 빌드·린트·테스트를 돌린다

명령 절의 빌드, 린트, 테스트를 이 순서로 직접 돌린다. 설치는 돌리지 않는다. "없음"으로 적힌 명령은 돌리지 않고 결과를 "없음"으로 적는다. 명령 절이 없거나 줄이 빠진 명령도 "없음"이다. "없음"은 실패가 아니다.

## 4. 테스트 먼저 기록을 본다

`phase-N.md`의 테스트 먼저가 "예"이면, 기록의 "한 일"에 구현하기 전에 돌린 테스트의 실패 출력과 구현한 뒤의 통과 출력이 이 순서로 있는지 본다. 없거나 순서가 다르면 실패다. "아니오"이거나 그 줄이 없으면 건너뛴다.

## 5. 기록의 "남은 것"을 본다

`phase-N.md`의 기록 "남은 것"의 줄을 하나씩 읽고, 동작의 결함(동작이 틀리거나 어떤 꼴에서 깨진다)이나 돌려 보지 않은 위험(돌려 보지 않아 동작을 장담할 수 없다)을 적은 줄을 고른다. 고른 줄마다 통과 조건이 보는 동작에 걸리는지 가른다.

- 걸리면 실패다(아래의 `돌리지 않음` 갈래는 빼고). 확인 절의 "남은 것"에 "실패"로 적고 "실패"에도 적는다.
- 걸리지 않으면 실패가 아니다. 확인 절의 "남은 것"에 "하네스에서 걸린 것"으로 적고 "하네스에서 걸린 것"에도 옮긴다.
- 돌려 보지 않은 위험을 적은 줄이 task 머리의 완료 조건에 딸린 `- 돌리지 않음: {까닭}` 줄이 돌리지 않기로 정한 동작에 대한 것이면, 통과 조건이 보는 동작에 걸려도 실패가 아니다. 계획이 이미 돌리지 않기로 정했으니 다시 수행해도 고칠 길이 없다. 확인 절의 "남은 것"에 그 `돌리지 않음` 줄을 밝혀 "하네스에서 걸린 것"으로 적고 "하네스에서 걸린 것"에도 옮긴다. 그 동작의 결함을 적은 줄은 이 갈래에 들지 않는다.

결함이나 위험이 아닌 줄(끝내지 못한 TODO의 까닭, 다음 phase에 넘긴 일)은 고르지 않는다. "남은 것"이 "없음"이거나 고른 줄이 없으면 확인 절의 "남은 것"을 "없음"으로 적는다.

## 6. 확인 절을 적는다

`phase-N.md`의 끝에 아래 양식대로 더한다. 앞의 확인 절이 있으면 지우지 않고 그 아래에 다음 번호로 더한다. 위의 계획 다섯 항목과 기록 다섯 절은 고치지 않는다.

**판정**: 2~5번에서 실패한 것이 하나도 없으면 "통과"다. 하나라도 있으면 "실패"다.

## 7. 커밋한다

판정이 실패여도 커밋한다. `phase-N.md` 하나만 넣는다. 메시지는 `NNN-slug: phase N 확인`이다(예: `008-csv-export: phase 2 확인`). git 레포가 아니면 커밋하지 않는다.

## 8. 세 줄을 돌려준다

아래 세 줄만 돌려준다. 다른 글을 더하지 않는다.

```
판정: 통과 | 실패
실패: N개
기록: docs/tasks/NNN-slug/phase-N.md
```

맡은 글에 `부른 쪽: plate:run` 줄도 작업 트리의 스킬 줄(`작업 트리의 {경로}를 읽어 그 절차를 따른다.`로 시작하는 줄)도 없을 때만 사용자가 직접 부른 것으로 보고, 그때는 이 세 줄에 실패 목록을 더해 보여 주고, 고치거나 이름을 바꾸는 일은 plate의 run 스킬(`plate:run`)을 부르면 이어진다고 적는다.

## 확인 절의 양식

아래 코드 블록 안쪽이 확인 절의 꼴이다. 블록을 여닫는 줄은 옮기지 않는다. `{…}`는 그 자리에 무엇을 적는지를 가리키고, 쓴 파일에는 `{…}`가 남지 않는다.

````markdown
## 확인 {몇 번째}

**통과 조건**
- {통과 조건의 글}
  - {돌린 명령, 또는 본 곳} → {나온 결과}. {통과 | 실패}

**명령**
- 빌드: `{돌린 명령}` → {나온 결과}. {통과 | 실패}
- 린트: `{돌린 명령}` → {나온 결과}. {통과 | 실패}
- 테스트: `{돌린 명령}` → {나온 결과}. {통과 | 실패}

**테스트 먼저 기록**
- {본 곳} → {실패 출력과 통과 출력이 이 순서로 있는지}. {통과 | 실패}

**남은 것**
- {기록의 "남은 것"에서 고른 줄} → {통과 조건이 보는 동작에 걸리는지와 그 통과 조건, 또는 돌리지 않기로 정한 `돌리지 않음` 줄}. {실패 | 하네스에서 걸린 것}

**실패**
- {무엇이 어디서 어떻게 틀렸는지} ({파일의 경로})

**하네스에서 걸린 것**
- {어느 스킬의 어느 규칙, 또는 계획의 어느 곳 때문에 무엇이 걸렸는지}

**판정**: {통과 | 실패}
````

## 적는 규칙

- 제목의 번호는 그 파일의 몇 번째 확인 절인지다. 첫 확인 절은 `## 확인 1`이다.
- 항목의 순서를 바꾸지 않는다. 적을 것이 없는 항목은 "없음"으로 적는다.
- "통과 조건"의 결과 줄에는 돌린 명령을 적는다. 2번대로 고쳐 돌렸으면 고친 명령을 적는다.
- "명령"에서 "없음"인 명령은 `- 빌드: 없음`처럼 적는다.
- "테스트 먼저 기록" 항목은 테스트 먼저가 "예"인 phase에만 적는다. 통과해도 적는다.
- "남은 것"에는 5번에서 고른 줄마다 한 줄을 적는다. 고른 줄이 없으면 "없음"으로 적는다.
- "실패"에는 2~5번에서 실패한 것을 모두 적는다. 다시 수행하는 쪽이 이 목록만 보고 고치므로, 무엇이 기대와 어떻게 달랐는지를 적는다.
- 돌리지 못한 확인(권한에 막힌 명령, 없는 도구)은 실패로 적고 까닭을 결과에 적는다.
- 명령 절이 없거나 줄이 빠진 명령이 있으면 "하네스에서 걸린 것"에 적는다.
- 5번에서 통과 조건이 보는 동작에 걸리지 않은 "남은 것"의 줄과 `돌리지 않음` 줄이 돌리지 않기로 정한 동작의 돌려 보지 않은 위험을 적은 줄은 "하네스에서 걸린 것"에 "남은 것: …"으로 옮겨 적는다. 판정에는 넣지 않는다.
- 스킬의 규칙이 프로젝트의 규칙에 밀린 곳은 "하네스에서 걸린 것"에 "프로젝트의 규칙을 따름: …"으로 적는다.
