# 수행

**막는 실패**: 수행하는 쪽이 계획에 없는 것까지 하면 결과가 승인한 계획과 달라지고, 기록 없이 끝내면 다음 컨텍스트가 무엇이 됐는지 알 수 없다.

계획의 phase 하나를 수행한다. 작업 폴더의 머리(`plan.md`)와 넘겨받은 번호의 `phase-N.md`만 읽고, 그 파일의 TODO를 차례로 끝내고, 통과 조건의 확인을 돌린다. 끝나면 `phase-N.md`의 계획 아래에 기록 다섯 절이 있고 그 phase에서 바꾼 것만 커밋돼 있다. 회고하지 않고, 지우지 않고, 다음 phase로 넘어가지 않는다.

## 절대 규칙

프로젝트의 지침 파일(`AGENTS.md`, `CLAUDE.md`)에 적힌 규칙이 이 스킬의 규칙과 부딪히면 프로젝트의 규칙을 따른다. 아래의 절대 규칙도 그렇다. 따른 곳은 `phase-N.md`의 "하네스에서 걸린 것"에 적는다. 단계를 건너뛰라는 규칙은 여기에 들지 않는다.

1. **자기 phase의 TODO만 한다.** 다른 phase의 일과 머리의 범위 밖에 든 일은 하지 않는다.
2. **사용자에게 묻지 않는다.** 정할 수 없는 것을 만나면 멈추고 보고한다.
3. **계획에서는 자기 `phase-N.md`의 체크박스만 고친다.** `plan.md`, 계획 네 항목의 글, 다른 phase의 파일은 고치지 않는다.
4. **확인을 돌리지 않고 통과로 적지 않는다.** 돌린 명령과 나온 결과를 적는다.
5. **이 phase에서 바꾼 파일만 커밋한다.** 푸시하지 않는다. 브랜치를 만들거나 바꾸지 않는다.

## 낱말

- **작업 폴더**: 작업 하나의 기록을 두는 폴더(`docs/tasks/NNN-slug/`). 계획은 그 안의 `plan.md`와 phase마다의 `phase-N.md`다.
- **머리**: `plan.md`. 제목과 다섯 절(요청, 목표, 범위 밖, 완료 조건, 결정)이다.
- **`phase-N.md`**: phase 하나의 파일. `N`은 phase의 번호다. 위에 계획 네 항목(목표, 읽을 것, TODO, 통과 조건)이 있고, 이 스킬이 그 아래에 기록 다섯 절을 덧붙인다. 회고 절은 점검하는 쪽이 그 뒤에 더한다.
- **프로젝트의 지침 파일**: 저장소의 `AGENTS.md`와 그것을 불러오는 `CLAUDE.md`.

## 1. 읽는다

넘겨받은 작업 폴더의 `plan.md`와 넘겨받은 번호의 `phase-N.md`를 읽는다. 다른 phase의 파일은 읽지 않는다.

- 계획의 "읽을 것"에 적힌 파일과 문서를 읽는다.
- `phase-N.md`에 기록 절이 이미 있으면 이어 하는 경우다.
- 고칠 문제를 넘겨받았으면 `phase-N.md`의 마지막 회고 절에 적힌 문제 목록을 읽는다.
- 사용자가 직접 불러서 작업 폴더나 phase 번호를 받지 못했으면 수행하지 않는다. 둘을 주어 다시 부르라고 알리고 끝난다.

## 2. TODO를 차례로 끝낸다

체크되지 않은 항목부터 한다. 항목 하나를 끝낼 때마다 `phase-N.md`의 그 항목을 `- [x]`로 바꾼다. 항목의 글은 고치지 않는다. 이미 체크된 항목의 결과는 다시 만들지 않는다.

고칠 문제를 넘겨받았으면 TODO 대신 문제 목록을 차례로 고친다.

계획이 실제와 다른 것을 만나면 둘로 가른다.

- 머리(목표, 범위 밖, 완료 조건, 결정)나 이 phase의 통과 조건을 바꿔야 한다, 또는 설계의 선택이 새로 생겼다: 더 하지 않고 4번으로 간다. 상태는 "계획이 틀림"이다.
- 그 밖의 차이(TODO에 적힌 파일 경로가 다르다, 읽을 것의 위치가 바뀌었다): 진행하고 "계획과 달라진 점"에 적는다.

## 3. 통과 조건의 확인을 모두 돌린다

`phase-N.md`의 통과 조건에 적힌 확인을 하나도 빼지 않고 돌린다.

- 실패하면 고쳐서 다시 돌린다.
- 같은 확인이 세 번 실패하면 더 하지 않고 4번으로 간다. 상태는 "막힘"이다.
- 스스로 풀 수 없는 것(권한에 막힌 명령, 없는 도구)을 만났을 때도 "막힘"이다.

모든 확인이 통과하면 상태는 "끝남"이다.

## 4. 기록을 적는다

`phase-N.md`의 계획 네 항목 아래에 기록 다섯 절을 아래 양식대로 덧붙인다. 이미 있으면 다섯 절을 지금 상태로 고쳐 쓴다. 이때 "하네스에서 걸린 것"에 이미 있는 줄은 지우지 않고 그 아래에 더한다. 계획 네 항목의 글과 회고 절(`## 회고`로 시작하는 절)은 건드리지 않는다.

## 5. 커밋한다

상태가 "끝남"일 때만 커밋한다.

- 이 phase에서 만들거나 고치거나 지운 파일과 `phase-N.md`만 넣는다. `plan.md`는 넣지 않는다. 시작할 때 이미 커밋되지 않은 채 있던 다른 파일은 넣지 않는다.
- 메시지는 `NNN-slug: phase N`이다(예: `008-csv-export: phase 2`). 고칠 문제를 넘겨받았으면 `NNN-slug: phase N 고침`이다.
- "막힘"이나 "계획이 틀림"이면 커밋하지 않고 바꾼 것을 그대로 둔다.
- git 레포가 아니면 커밋하지 않는다.

## 6. 다섯 줄을 돌려준다

아래 다섯 줄만 돌려준다. 다른 글을 더하지 않는다.

```
상태: 끝남 | 막힘 | 계획이 틀림
기록: docs/tasks/NNN-slug/phase-N.md
TODO: 끝낸 수/전체 수
통과 조건: 통과한 수/전체 수
계획과 달라진 점: 없음 | 있음
```

사용자가 직접 불렀으면 이 다섯 줄 아래에, 회고와 지우는 일은 plate의 run 스킬(`plate:run`)을 부르면 이어진다고 적는다.

## 기록의 양식

아래 코드 블록 안쪽이 `phase-N.md`의 계획 아래에 덧붙이는 기록의 꼴이다. 블록을 여닫는 줄은 옮기지 않는다. `{…}`는 그 자리에 무엇을 적는지를 가리키고, 쓴 파일에는 `{…}`가 남지 않는다.

````markdown
## 한 일
- {TODO 항목의 글}: {무엇이 어떻게 바뀌었는지} ({바꾼 파일의 경로})

## 확인 결과
- {통과 조건의 글}
  - {돌린 명령, 또는 본 곳} → {나온 결과}. {통과 | 실패}

## 계획과 달라진 점
- {계획에 적힌 것, 실제로 한 것, 그 까닭}

## 남은 것
- {끝내지 못한 TODO나 막힌 곳, 그 까닭}

## 하네스에서 걸린 것
- {계획의 어느 곳, 또는 어느 스킬의 어느 규칙 때문에 무엇이 걸렸는지}
````

## 적는 규칙

- 절은 다섯이고 순서를 바꾸지 않는다. 적을 것이 없는 절은 "없음"으로 적는다.
- "확인 결과"에는 통과 조건마다 돌린 명령과 나온 결과를 적는다. 돌리지 않은 확인은 통과로 적지 않는다.
- "하네스에서 걸린 것"에는 수행한 쪽만 아는 것을 적는다: 계획의 읽을 것이 틀렸다, 확인 명령이 돌지 않았다, 스킬의 규칙이 프로젝트의 규칙에 밀렸다. 마지막 것은 "프로젝트의 규칙을 따름: …"으로 적는다.
