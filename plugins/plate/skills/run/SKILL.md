# 실행

**막는 실패**: 한 세션이 계획부터 끝까지 다 하면 컨텍스트가 불어나고, 수행한 쪽이 스스로 끝났다고 하면 확인되지 않은 결과가 다음 phase의 바탕이 된다.

계획된 tasks를 실행한다. 이 스킬을 따르는 세션은 조율만 한다: 묻고, 승인받고, 에이전트를 띄우고, 통과한 phase의 이름을 바꾸고, 다음 phase와 다음 task로 잇고, `RUNLOG.md`에 적는다. 수행은 새 에이전트가 plate의 phase 스킬(`plate:phase`)로, phase의 확인은 다른 새 에이전트가 plate의 check 스킬(`plate:check`)로, task 회고는 또 다른 새 에이전트가 plate의 retro 스킬(`plate:retro`)로 한다. 상태는 모두 파일(`phase-N.md`의 체크박스와 기록 절과 확인 절, `done-phase-N.md`, `retro.md`의 회고 절, `RUNLOG.md`, 커밋)에 있어서, 세션을 끊고 다시 불러도 파일만 보고 잇는다.

## 절대 규칙

프로젝트의 지침 파일(`AGENTS.md`, `CLAUDE.md`)에 적힌 규칙이 이 스킬의 규칙과 부딪히면 프로젝트의 규칙을 따른다. 아래의 절대 규칙도 그렇다. 따른 곳은 보고에 적는다. 단계를 건너뛰라는 규칙은 여기에 들지 않는다.

1. **수행도 확인도 회고도 직접 하지 않는다.** phase의 TODO를 하지 않고 통과 조건과 완료 조건의 확인을 돌리지 않는다. 수행은 수행 에이전트에게, phase의 확인은 확인 에이전트에게, task 회고는 회고 에이전트에게 맡긴다.
2. **맡길 때마다 에이전트를 새로 띄운다.** 앞서 띄운 에이전트를 이어 쓰지 않는다. 수행한 에이전트에게 확인을 맡기지 않고, 그 task의 phase를 수행하거나 확인한 에이전트에게 회고를 맡기지 않는다.
3. **마지막 확인 절의 판정이 "통과"가 아닌 phase는 이름을 바꾸지 않는다.**
4. **계획(tasks 머리, task 머리, `phase-N.md`의 계획 다섯 항목)은 승인 없이 고치거나 더하지 않는다.** 고치거나 더할 안을 답글로 보여 준 뒤에 받은 답만 승인이다. tasks 일괄에서 회고의 문제를 고칠 phase를 더할 때만 묻지 않는다.
5. **직접 고치는 파일은 계획 파일, 이름을 바꾸는 `phase-N.md`(`done-phase-N.md`가 된다), `docs/tasks/RUNLOG.md`뿐이다.** `FRICTION.md`, `retro.md`, 확인 절, 기록 절은 그것을 쓰는 스킬의 몫이다. 커밋에는 자기가 고친 파일만 넣는다. 푸시하지 않는다.

## 낱말

- **tasks**: 요청 하나를 계획한 묶음. `docs/tasks/`에 하나만 있다. 그 기록은 `docs/tasks/` 바로 아래의 `plan.md`(tasks 머리), `FRICTION.md`, `RUNLOG.md`, `review.md`, `eval.md`와 task 폴더들이다.
- **tasks 머리**: `docs/tasks/plan.md`. 제목, 이름(`**이름**:` 줄), 여섯 절(요청, 목표, 범위 밖, 완료 조건, 결정, task 목록)이다. 이름은 브랜치 `tasks/<이름>`에 쓴다. task 목록에는 task 폴더의 이름이 실행할 차례대로 있다.
- **task**: tasks 안의 `NNN-slug/` 폴더 하나(task 폴더). 그 안에 `plan.md`(task 머리), `phase-N.md`, `done-phase-N.md`, `retro.md`가 있다. task 이름은 폴더 이름(`NNN-slug`)이다.
- **task 머리**: task 폴더의 `plan.md`. 제목과 네 절(목표, 범위 밖, 완료 조건, 결정)이다.
- **phase**: task 안의 `phase-N.md` 하나. `N`은 phase의 번호다. 위에 계획 다섯 항목(목표, 테스트 먼저, 읽을 것, TODO, 통과 조건)이 있고, 그 아래에 수행 에이전트가 기록 다섯 절을, 확인 에이전트가 확인 절(`## 확인 1`처럼 번호가 붙은 절)을 덧붙인다.
- **`done-phase-N.md`**: 확인이 통과한 phase. 이 스킬이 `phase-N.md`의 이름을 바꾼 것이고, tasks가 끝날 때까지 남는다.
- **`retro.md`**: task 회고의 기록. 회고 에이전트가 `## 회고 1`처럼 번호가 붙은 회고 절을 더하고, 마지막 회고 절의 판정이 task의 상태다.
- **계획 파일**: tasks 머리, task 머리, `phase-N.md`의 계획 다섯 항목.
- **남은 task**: task 목록의 task 가운데 `phase-N.md`가 하나라도 있거나, `retro.md`가 없거나, 마지막 회고 절의 판정이 "통과"가 아닌 것.
- **지금 task**: 남은 task 가운데 task 목록에서 가장 앞의 것.
- **남은 첫 phase**: 지금 task의 `phase-N.md` 가운데 번호가 가장 작은 것.
- **실행 방식**: task 하나씩, 또는 tasks 일괄. 2번에서 정한다.
- **수행 에이전트**: phase 하나의 수행을 맡기려고 새로 띄운 에이전트. `plate:phase`를 불러 따른다.
- **확인 에이전트**: phase 하나의 확인을 맡기려고 새로 띄운 에이전트. `plate:check`를 불러 따른다.
- **회고 에이전트**: task 하나의 회고를 맡기려고 새로 띄운 에이전트. `plate:retro`를 불러 따른다.
- **기본 브랜치**: 원격 `origin`의 HEAD가 가리키는 브랜치(`git symbolic-ref --short refs/remotes/origin/HEAD`에서 `origin/`을 뺀 것). 그것이 없으면 `main`, `main`도 없으면 `master`다.
- **맥락 문서**: `AGENTS.md`의 문서 지도에 적힌 문서 가운데 `docs/tasks/` 행을 뺀 것.
- **테스트가 있는 프로젝트**: 테스트 파일이 있거나, `package.json`의 `scripts.test`(npm이 처음 넣는 자리표시 글 `no test specified`는 빼고)나 `Makefile`의 `test` 대상이 있는 프로젝트. 테스트 파일은 `.md`가 아닌 파일 가운데 `tests/`, `test/`, `__tests__/` 아래에 있거나 이름이 `test_*`, `*_test.*`, `*.test.*`, `*.spec.*` 꼴인 것이다.
- **프로젝트의 지침 파일**: 저장소의 `AGENTS.md`와 그것을 불러오는 `CLAUDE.md`.

## 0. tasks를 본다

`docs/tasks/plan.md`(tasks 머리)가 없으면 실행할 계획이 없다고 알리고, plate의 plan 스킬(`plate:plan`)로 계획부터 하라고 안내한 뒤 끝난다. 셋업이 안 된 프로젝트도 같다. 이때는 파일을 만들지도 고치지도 않고 에이전트를 띄우지 않는다.

있으면 그 tasks가 대상이다. task는 task 목록의 차례대로 실행한다.

## 1. 시작 조건을 본다

git 레포가 아니면 커밋하지 않는다고 알리고 2번으로 간다. 아래 셋은 건너뛴다.

1. **계획의 커밋.** 계획 파일 가운데 한 번도 커밋되지 않은 것이 있으면 그 파일들만 커밋한다. 메시지는 `plan: <이름>`이다(`<이름>`은 tasks 머리의 이름).
2. **커밋하지 않은 변경.** 남은 첫 phase의 `phase-N.md`와 `docs/tasks/RUNLOG.md`는 세지 않는다. `phase-N.md`는 앞 수행이 커밋하지 않고 남긴 기록이고, 다음 수행이 그 위에 이어 적어 그 phase의 커밋에 넣는다. `RUNLOG.md`는 이 스킬이 뒤의 커밋에 넣는다. 그 밖의 변경이 있으면 파일 목록을 보여 주고 그대로 진행할지 묻는다. 진행하면 그 변경은 건드리지 않고 어느 커밋에도 넣지 않는다. 거절하면 `RUNLOG.md`에 그 물음의 줄만 더하고 끝난다.
3. **tasks 브랜치.** 지금 브랜치가 기본 브랜치이면 `git switch -c tasks/<이름>`으로 브랜치를 만들어 바꾼다. 그 브랜치가 이미 있으면 `git switch tasks/<이름>`으로 바꾼다. 기본 브랜치가 아니면 만들지 않고 지금 브랜치에서 실행한다. 끝의 평가와 보고까지 가지 않은 tasks가 기본 브랜치에 들어가지 않게 하는 것이다.

## 2. 실행 방식을 정한다

`RUNLOG.md`에 물은 자리가 `실행 방식`인 줄이 있으면 묻지 않고 그 가운데 마지막 줄의 답으로 잇는다. 세션을 끊고 다시 불러도 처음에 고른 방식으로 가게 하는 것이다.

없으면 두 방식을 보여 주고 어느 것으로 할지 묻는다.

- **task 하나씩**: task 회고가 끝날 때마다 멈춘다. 회고에 문제가 있으면 고칠 phase의 안을 보여 승인받고, 통과하면 다음 task로 갈지 묻는다.
- **tasks 일괄**: 묻지 않고 모든 task를 처리한다. 회고에 문제가 있으면 묻지 않고 고칠 phase를 더해 고친다.

두 방식 모두 phase 사이에서는 묻지 않고, "멈춘다"의 자리에서는 멈추고, 모든 task의 회고가 통과하면 "tasks 끝"으로 간다.

## 3. 갈 곳을 정한다

파일만 보고 정한다. 앞 세션에서 어디까지 했는지를 기억이나 대화에서 찾지 않는다.

남은 task가 없으면 "tasks 끝"으로 간다.

지금 task에 `phase-N.md`가 있으면 남은 첫 phase를 아래 표에 위에서부터 대어, 처음 맞는 줄의 갈 곳으로 간다.

| 남은 첫 phase의 상태 | 갈 곳 |
|---|---|
| 기록 절(`## 한 일`)이 없거나, 체크되지 않은 TODO가 있거나, `phase-N.md`에 커밋하지 않은 변경이 있다 | 4번 |
| 확인 절이 없다 | 5번 |
| 마지막 확인 절의 판정이 "통과"다 | 6번 |
| 마지막 확인 절의 판정이 "실패"이고, `phase-N.md`를 마지막으로 바꾼 커밋(`git log -1 --format=%s -- <그 파일>`)이 `NNN-slug: phase N 고침`이다 | 5번 |
| 마지막 확인 절의 판정이 "실패"이고, 확인 절이 셋 이상이다 | "멈춘다" |
| 마지막 확인 절의 판정이 "실패"다 | 4번 |

지금 task에 `phase-N.md`가 없으면 지금 task를 아래 표에 같은 방법으로 대어 간다.

| 지금 task의 상태 | 갈 곳 |
|---|---|
| `retro.md`가 없다 | 7번 |
| 마지막 회고 절이 `## 회고 K`이고, 제목이 `# Phase M: 회고 K의 문제를 고친다`인 `done-phase-M.md`가 있다 | 7번 |
| 회고 절이 셋 이상이다 | "멈춘다" |
| 그 밖(마지막 판정이 "문제 있음"이다) | 8번 |

git 레포가 아니면 커밋을 보는 조건은 맞지 않는 것으로 본다.

## 4. 수행을 맡긴다

새 에이전트를 띄워 아래 글을 그대로 넘긴다. `NNN-slug`와 `N`만 대상의 것으로 바꾸고 다른 글을 더하지 않는다. 넷째 줄은 `phase-N.md`의 TODO가 모두 체크됐고 마지막 확인 절의 판정이 "실패"일 때만 붙인다.

```
plate의 phase 스킬(`plate:phase`)을 불러 그 절차를 따른다.
task 폴더: docs/tasks/NNN-slug
phase: N
고칠 문제: phase-N.md의 마지막 확인 절의 실패
```

돌아오면 `RUNLOG.md`에 그 에이전트의 줄을 더한다. 돌아온 다섯 줄은 바로 이어 멈출 때만 그대로 보이고, 그 밖에는 10번의 보고에 적는다. `phase-N.md`는 필요할 때만 연다.

- 상태가 "끝남"이면 5번으로 간다.
- "막힘"이나 "계획이 틀림"이면 "멈춘다"로 간다. 훅이 테스트 먼저 때문에 세 번째 막은 것도 "막힘"으로 돌아온다.

## 5. 확인을 맡긴다

그 phase를 수행한 에이전트와 다른 새 에이전트를 띄워 아래 글을 그대로 넘긴다. `NNN-slug`와 `N`만 바꾸고 다른 글을 더하지 않는다.

```
plate의 check 스킬(`plate:check`)을 불러 그 절차를 따른다.
task 폴더: docs/tasks/NNN-slug
phase: N
```

돌아오면 `RUNLOG.md`에 그 에이전트의 줄을 더한다. 돌아온 세 줄은 바로 이어 멈출 때만 그대로 보이고, 그 밖에는 10번의 보고에 적는다.

- 판정이 "통과"면 6번으로 간다.
- "실패"면 묻지 않고 3번으로 간다. 표대로 실패를 고칠 문제로 새 수행 에이전트에게 맡기고(4번) 다시 확인을 맡기거나(5번), 세 번째 실패면 멈춘다.

## 6. 통과한 phase의 이름을 바꾼다

1. `git mv`로 `phase-N.md`를 같은 폴더의 `done-phase-N.md`로 바꾼다. task 머리와 남은 phase의 파일은 건드리지 않고, 남은 파일의 번호도 다시 매기지 않는다.
2. 이 변경과 `RUNLOG.md`만 한 커밋으로 넣는다. 메시지는 `NNN-slug: phase N 통과`다(예: `001-react-setting: phase 2 통과`).

git 레포가 아니면 이름만 바꾼다. 그다음 3번으로 간다. 다음 phase도 새 에이전트가 수행한다.

## 7. task 회고를 맡긴다

그 task의 phase를 수행하거나 확인한 에이전트와 다른 새 에이전트를 띄워 아래 글을 그대로 넘긴다. `NNN-slug`만 바꾸고 다른 글을 더하지 않는다.

```
plate의 retro 스킬(`plate:retro`)을 불러 그 절차를 따른다.
task 폴더: docs/tasks/NNN-slug
```

돌아오면 `RUNLOG.md`에 그 에이전트의 줄을 더한다. 돌아온 세 줄은 바로 이어 멈추거나 물을 때만 그대로 보이고, 그 밖에는 10번의 보고에 적는다.

- 판정이 "통과"면 9번으로 간다.
- "문제 있음"이면 3번으로 간다. 표대로 고칠 phase를 더하거나(8번), 세 번째 "문제 있음"이면 멈춘다.

## 8. 고칠 phase를 더한다

회고에서 나온 문제를 새 phase 하나로 고친다. 안은 아래 양식대로 쓴다.

- `M`은 이 task에서 쓴 phase 번호 가운데 가장 큰 것의 다음이다. `phase-N.md`와 `done-phase-N.md`의 번호를 모두 센다.
- `K`는 마지막 회고 절의 번호다.
- TODO는 마지막 회고 절의 문제 하나에 항목 하나다. 문제의 글과 파일의 경로를 옮긴다.
- 테스트 먼저는 테스트가 있는 프로젝트에서 고칠 문제 가운데 코드 파일(`.md`가 아닌 파일)의 동작을 바꾸는 것이 있으면 "예"다. 그 밖이면(테스트가 없는 프로젝트, `.md`만 고치는 문제) "아니오"와 그 이유다.
- 읽을 것에는 맥락 문서를 모두 넣는다. 고치는 방법은 수행이 정하므로 맥락 문서에 적힌 사실과 결정을 보고 고르게 하는 것이다.
- 통과 조건에는 task 머리의 완료 조건과 함께 회고 K의 문제가 모두 고쳐졌다는 조건을 둔다. 문제가 완료 조건 밖에서 나오면 완료 조건의 확인만으로는 고친 것을 보지 못한다.

실행 방식에 따라 다르다.

- **task 하나씩**: 안을 답글로 보여 주고 승인할지 묻고, 거기서 멈춰 답을 기다린다. 미리 받은 승인은 승인이 아니다. 고칠 곳을 말하면 고쳐서 다시 보여 준다. 승인받지 못하면 만들지 않고 10번으로 간다.
- **tasks 일괄**: 묻지 않는다.

만들면 보여 준(일괄이면 쓴) 안대로 `phase-M.md`를 만들고 그 파일과 `RUNLOG.md`만 커밋한다. 메시지는 `plan: NNN-slug 수정`이다. 그다음 3번으로 가서 새 에이전트에게 수행을 맡긴다.

아래 코드 블록 안쪽이 고칠 phase의 꼴이다. 블록을 여닫는 줄은 옮기지 않는다. `{…}`는 그 자리에 무엇을 적는지를 가리키고, 쓴 파일에는 `{…}`가 남지 않는다.

````markdown
# Phase {M}: 회고 {K}의 문제를 고친다

**목표**: 회고 {K}에서 나온 문제를 모두 고친다.

**테스트 먼저**: {예, 또는 아니오 — 이유}

**읽을 것**
- `docs/tasks/{NNN-slug}/retro.md`의 `## 회고 {K}` 절
- {문제에 적힌 파일의 경로}
- {맥락 문서의 경로}

**TODO**
- [ ] {문제의 글} ({파일의 경로})

**통과 조건**
- 회고 {K}의 문제가 모두 고쳐졌다.
  - 확인: 문제마다 적힌 곳을 다시 읽거나 돌린다
- task 머리의 완료 조건이 모두 참이다.
  - 확인: 완료 조건의 확인을 모두 돌린다
````

## 9. 다음 task로 잇는다

- 남은 task가 없으면 묻지 않고 "tasks 끝"으로 간다.
- task 하나씩이면 회고가 통과한 task를 알리고, 다음 task(`NNN-slug`와 그 task 머리의 제목)로 갈지 묻는다. 승인하면 3번으로, 거절하면 10번으로 간다.
- tasks 일괄이면 묻지 않고 3번으로 간다.

다음 task의 phase도 새 에이전트가 수행한다.

## 10. 보고한다

- 이번에 이름을 바꾼 phase, 회고가 통과한 task, 남은 task와 그 task의 남은 phase
- 이번에 띄운 에이전트마다 돌아온 상태나 판정
- 이번에 더한 고칠 phase. tasks 일괄에서 묻지 않고 더한 것은 그렇다고 적는다
- 멈췄으면 멈춘 자리와 정한 해결책
- 합칠지 물었으면 합친 브랜치와 합친 곳. 합치지 않았으면 그 까닭(거절, 충돌)
- 커밋. 커밋하지 않았으면 그 까닭
- 프로젝트의 규칙을 따른 곳. 에이전트가 기록에 "프로젝트의 규칙을 따름: …"으로 적은 것도 옮긴다.

보고로 끝난다.

## 멈춘다

실행 방식과 상관없이 아래 자리에서는 그 자리에서 멈춘다.

- 수행이 "막힘"으로 돌아왔다. 훅의 세 번째 막음도 든다.
- 수행이 "계획이 틀림"으로 돌아왔다.
- 같은 phase의 확인이 세 번 실패했다(처음과 고친 뒤 두 번).
- 같은 task의 회고가 세 번 "문제 있음"이었다(처음과 고친 뒤 두 번).

정해 둔 선택지(다시 맡긴다, 멈춘다 같은 목록)를 내지 않는다. 원인과 해결책을 보이고 사용자와 논의한다.

1. **원인을 보인다.** 기록에 적힌 것을 옮긴다. 수행이면 `phase-N.md`의 "계획과 달라진 점", "남은 것", "하네스에서 걸린 것"이고, 확인이면 확인 절마다의 "실패", 회고면 `retro.md`의 회고 절마다의 "문제"다. 돌아온 줄도 그대로 보인다.
2. **해결책을 낸다.** 기록에 해결책이 적혀 있으면(훅의 세 번째 막음이면 수행 에이전트가 적은 원하는 해결책) 그것을, 없으면 원인에서 끌어낸 안을 낸다. 해결책이 계획을 바꾸면 어느 파일의 어느 글을 어떻게 바꾸는지까지 적는다. 막힌 까닭이 권한이면 사용자가 권한을 바꾸기 전에는 다시 맡겨도 같은 곳에서 막힌다고 함께 알린다. 띄운 에이전트는 자기 권한을 바꾸지 못한다.
3. **논의한다.** 거기서 멈춰 답을 기다리고, 사용자와 해결책을 정한다. 답을 받을 때마다 `RUNLOG.md`에 물은 줄을 더한다.
4. **정한 대로 간다.**
   - 계획을 바꾸는 해결책이면 고칠 안을 답글로 보여 주고 거기서 멈춰 답을 기다린다. 논의에서 받은 동의와 미리 받은 승인은 승인이 아니다. 승인받으면 보여 준 안대로 고치고, 고친 것과 까닭을 task 머리의 결정에 한 줄 더한다(tasks 머리를 고쳤으면 tasks 머리의 결정에). `phase-N.md`의 체크박스, 기록 절, 확인 절과 `retro.md`는 건드리지 않는다. 고친 계획 파일과 `RUNLOG.md`만 커밋한다. 메시지는 `plan: NNN-slug 수정`이다. 그다음 아래의 다시 맡기는 길로 간다. 승인받지 못하면 고치지 않고 10번으로 간다.
   - 다시 맡긴다(계획을 고쳤다, 사용자가 권한이나 환경을 고쳤다): 수행이 멈췄으면 4번으로 간다. 확인이나 회고가 세 번 실패했으면 3번으로 가되, 표가 "멈춘다"를 가리키면 이번에는 멈추지 않고 확인이면 4번, 회고면 7번으로 간다. 그 뒤에 같은 자리에서 다시 실패하면 다시 멈춘다.
   - 멈추기로 했으면 10번으로 간다.

## tasks 끝

남은 task가 없을 때 3번과 9번에서 온다.

## 합친다

tasks 끝에서 온다. 합칠 브랜치는 `tasks/<이름>`이고, 합칠 곳은 기본 브랜치다.

1. 합칠 브랜치와 합칠 곳을 보여 주고 합칠지 묻는다. 실행 방식과 상관없이 묻는다. 거절하면 그대로 두고 10번으로 간다.
2. 커밋하지 않은 변경이 있으면 "1. 시작 조건을 본다"의 물음대로 먼저 묻는다.
3. `git switch`로 합칠 곳으로 바꾼다.
4. `git merge tasks/<이름>`으로 합친다. squash하지 않는다. phase의 근거가 이력에 남아야 하기 때문이다.
5. 충돌하면 풀지 않는다. `git merge --abort`로 되돌리고 충돌한 파일을 알린 뒤 10번으로 간다.
6. 합쳐졌으면 `git branch -d tasks/<이름>`으로 브랜치를 지운다. 지우지 못하면 까닭을 보고에 적는다.

## `RUNLOG.md`

`docs/tasks/RUNLOG.md`. 띄운 에이전트가 돌아올 때마다, 사용자에게 물어 답을 받을 때마다 끝에 한 줄을 더한다. 파일이 없으면 첫 줄을 `# RUNLOG`로 만들고 그 아래에 더한다. 이미 있는 줄은 고치거나 지우지 않는다. 더한 줄은 6번, 8번, "멈춘다"의 커밋에 함께 넣는다. 스테이징해 둔 채로 에이전트를 띄우지 않는다.

아래 코드 블록 안쪽이 이 파일의 꼴이다. 블록을 여닫는 줄은 옮기지 않는다. `{…}`는 그 자리에 무엇을 적는지를 가리키고, 쓴 파일에는 `{…}`가 남지 않는다.

````markdown
# RUNLOG

- 에이전트 | {수행 | 확인 | 회고} | `{task 이름}` phase {N} | 토큰 {수} | 도구 호출 {수} | 시간 {초}초
- 물음 | {물은 자리} | `{task 이름}` | {물은 것} | 답: {답}
````

- 에이전트 줄의 토큰, 도구 호출, 시간은 에이전트의 결과와 함께 돌아온 사용량에서 옮긴다. 시간은 초로 적는다. 돌아오지 않은 값은 `모름`으로 적는다.
- 회고 에이전트의 줄은 phase를 적지 않고 `` `{task 이름}` ``만 적는다.
- 물은 자리는 `실행 방식`, `커밋하지 않은 변경`, `고칠 phase`, `다음 task`, `멈춤`, `합칠지` 가운데 하나다. "멈춘다"에서 물은 것은 계획을 고칠 안의 승인까지 모두 `멈춤`이다.
- task에 걸리지 않는 물음(실행 방식, 커밋하지 않은 변경, 합칠지)은 task 이름 자리에 "없음"을 적는다.
- 물은 것과 답은 한 줄로 줄여 적는다. 실행 방식의 답은 `task 하나씩` 또는 `tasks 일괄`로 적는다.
