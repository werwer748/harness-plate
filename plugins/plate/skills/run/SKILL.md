# 실행

**막는 실패**: 한 세션이 계획부터 끝까지 다 하면 컨텍스트가 불어나고, 수행한 쪽이 스스로 끝났다고 하면 확인되지 않은 결과가 다음 phase의 바탕이 된다.

계획된 작업을 phase 하나씩 실행한다. 이 스킬을 따르는 세션은 조율만 한다: 묻고, 승인받고, 에이전트를 띄우고, 통과한 phase를 지우고, 다음 phase로 잇고, 모든 phase가 지워지면 검증을 맡기고, 검증이 닫히면 작업 브랜치를 합칠지 묻는다. 수행은 새 컨텍스트의 에이전트가 plate의 phase 스킬(`plate:phase`)로 하고, 확인과 점검은 다른 새 에이전트가 plate의 retro 스킬(`plate:retro`)로 하고, 작업 전체의 검증은 또 다른 새 에이전트가 plate의 verify 스킬(`plate:verify`)로 한다. 상태는 모두 파일(`phase-N.md`의 체크박스와 기록 절, 회고 절, `verify.md`의 검증 절, 커밋)에 있어서, 세션을 끊고 다시 불러도 파일만 보고 잇는다.

## 절대 규칙

프로젝트의 지침 파일(`AGENTS.md`, `CLAUDE.md`)에 적힌 규칙이 이 스킬의 규칙과 부딪히면 프로젝트의 규칙을 따른다. 아래의 절대 규칙도 그렇다. 따른 곳은 보고에 적는다. 단계를 건너뛰라는 규칙은 여기에 들지 않는다.

1. **수행도 확인도 검증도 직접 하지 않는다.** phase의 TODO를 하지 않고 통과 조건과 완료 조건의 확인을 돌리지 않는다. 수행은 수행 에이전트에게, 확인과 점검은 점검 에이전트에게, 검증은 검증 에이전트에게 맡긴다.
2. **phase마다 에이전트를 새로 띄운다.** 앞 phase를 수행한 에이전트를 이어 쓰지 않는다. 수행한 에이전트에게 점검을 맡기지 않는다. 수행하거나 점검한 에이전트에게 검증을 맡기지 않는다.
3. **판정이 통과가 아닌 phase는 지우지 않는다.** 지우기 전에 그 `phase-N.md`가 커밋돼 있어야 한다.
4. **계획(`plan.md`와 `phase-N.md`의 계획 다섯 항목)은 승인 없이 고치거나 더하지 않는다.** 고치거나 더할 안을 답글로 보여 준 뒤에 받은 답만 승인이다.
5. **직접 고치는 파일은 계획 파일(`plan.md`, `phase-N.md`), `verify.md`의 미룬다는 줄, `docs/LESSONS.md`(옛 셋업에서 사용자가 다른 위치를 정했으면 그 파일), `AGENTS.md`의 문서 지도, `.worktrees/.gitignore`뿐이다.** 커밋에는 자기가 고친 파일만 넣는다. 푸시하지 않는다.

## 낱말

- **작업**: 요청 하나를 계획, 실행, 검증으로 끝내는 단위. 기록은 작업 폴더(`docs/tasks/NNN-slug/`)에 두고, 계획은 그 안의 `plan.md`와 phase마다의 `phase-N.md`다. 검증의 기록은 `verify.md`이고, 검증 에이전트가 그 끝에 `## 검증 N` 절을 더한다.
- **머리**: `plan.md`. 제목과 다섯 절(요청, 목표, 범위 밖, 완료 조건, 결정)이다.
- **`phase-N.md`**: phase 하나의 파일. `N`은 phase의 번호다. 위에 계획 다섯 항목(목표, 테스트 먼저, 읽을 것, TODO, 통과 조건)이 있고, 그 아래에 수행 에이전트가 기록 다섯 절을, 점검 에이전트가 회고 절을 덧붙인다.
- **끝나지 않은 작업**: `phase-N.md`가 하나라도 남아 있는 작업 폴더.
- **닫힌 검증**: 마지막 검증 절의 판정이 "통과"이거나, 그 절 아래에 "사용자가 남은 문제를 나중에 다루기로 했다"가 있는 `verify.md`.
- **검증이 남은 작업**: `phase-N.md`가 하나도 없고, 닫힌 검증도 없는 작업 폴더.
- **남은 첫 phase**: 대상 작업의 `phase-N.md` 가운데 번호가 가장 작은 것.
- **수행 에이전트**: phase 하나의 수행을 맡기려고 새 컨텍스트로 띄운 에이전트. `plate:phase`를 불러 따른다.
- **점검 에이전트**: phase 하나의 회고나 확인을 맡기려고 새 컨텍스트로 띄운 에이전트. `plate:retro`를 불러 따른다. 그 phase를 수행한 에이전트와 다른 에이전트다.
- **검증 에이전트**: 작업 하나의 검증을 맡기려고 새 컨텍스트로 띄운 에이전트. `plate:verify`를 불러 따른다. 그 작업의 phase를 수행하거나 점검한 에이전트와 다른 에이전트다.
- **전체 지시**: 이 스킬을 부른 요청에 든, 남은 phase를 모두 처리하라는 지시.
- **확인만**: 회고 가운데 통과 조건의 확인만 다시 돌리는 방식. 코드 점검과 하네스의 문제점 찾기를 건너뛴다.
- **원래 자리**: worktree가 아닌 주 작업 트리. 저장소의 최상위 폴더(`git rev-parse --show-toplevel`)가 `.worktrees/` 아래에 있지 않으면 원래 자리다.
- **기본 브랜치**: 원격 `origin`의 HEAD가 가리키는 브랜치(`git symbolic-ref --short refs/remotes/origin/HEAD`에서 `origin/`을 뺀 것). 그것이 없으면 `main`, `main`도 없으면 `master`다.
- **프로젝트의 지침 파일**: 저장소의 `AGENTS.md`와 그것을 불러오는 `CLAUDE.md`.

## 0. 대상 작업을 정한다

- 번호나 이름을 받았으면 그 작업 폴더다.
- 받지 않았고 지금 브랜치가 `task/NNN-slug`이면 그 작업이다.
- 그 밖에는 끝나지 않은 작업과 검증이 남은 작업을 찾는다. 하나면 그것이고, 여럿이면 폴더 이름을 보여 주고 묻는다.
- 둘 다 하나도 없으면 실행할 계획이 없다고 알리고, plate의 plan 스킬(`plate:plan`)로 계획부터 하라고 안내한 뒤 끝난다. 셋업이 안 된 프로젝트도, 받은 작업 폴더에 `plan.md`가 없을 때도 같다. 이때는 파일을 만들지도 고치지도 않고 에이전트를 띄우지 않는다.

요청에 남은 phase를 모두 처리하라는 뜻("모든 phase", "전부", "끝까지")이 있으면 전체 지시로 적어 둔다. 분명하지 않으면 전체 지시가 아니다.

대상 작업의 worktree(`.worktrees/NNN-slug`)가 이미 있고 지금 자리가 원래 자리이면 그 안의 작업 폴더를 본다.

- `phase-N.md`가 남아 있지 않고 닫힌 검증이 있으면 그 worktree에서 "통과하면"의 1~3을 한 뒤 "합친다"로 간다. 고치는 파일은 worktree 안의 것이고 커밋도 worktree에서 한다(`git -C .worktrees/NNN-slug`). worktree의 세션이 검증 뒤에 끊겼어도 `docs/LESSONS.md`로 옮기지 않은 채 합치지 않게 하는 것이다.
- 그 밖이면 그 폴더에서 세션을 열어 이 스킬을 부르라고 안내하고 끝난다.

## 1. 시작 조건을 본다

git 레포가 아니면 커밋하지 않고 통과한 phase를 검증이 닫힐 때까지 지우지 않는다고 알리고 2번으로 간다. 아래 넷은 건너뛴다.

1. **계획의 커밋.** 대상 작업의 계획 파일(`plan.md`, `phase-N.md`) 가운데 한 번도 커밋되지 않은 것이 있으면 그 파일들만 커밋한다. 메시지는 `plan: NNN-slug`다.
2. **worktree.** 지금 브랜치가 대상 작업의 `task/NNN-slug`이면 건너뛴다. 아니고, 대상 작업보다 번호가 작은 끝나지 않은 작업이 있으면 worktree를 만들고 끝난다.
   - `.worktrees/.gitignore`가 없으면 `*` 한 줄로 만든다. worktree 폴더가 추적되지 않게 하는 것이다. `.git/info/exclude`와 프로젝트의 `.gitignore`는 고치지 않는다.
   - `git worktree add .worktrees/NNN-slug -b task/NNN-slug`로 만든다. 브랜치는 지금 커밋에서 가른다.
   - 만든 위치와 브랜치를 알리고, 그 폴더에서 세션을 열어 이 스킬을 다시 부르라고 안내한다. 이 세션에서는 실행하지 않는다.
3. **커밋하지 않은 변경.** 대상 작업의 남은 첫 phase의 `phase-N.md`는 세지 않는다. 앞 수행이 커밋하지 않고 남긴 기록이고, 다음 수행이 그 위에 이어 적어 그 phase의 커밋에 넣는다. 그 밖의 변경이 있으면 파일 목록을 보여 주고 그대로 진행할지 묻는다. 진행하면 그 변경은 건드리지 않고 어느 커밋에도 넣지 않는다. 거절하면 아무것도 하지 않고 끝난다.
4. **작업 브랜치.** 지금 브랜치가 기본 브랜치이면 `git switch -c task/NNN-slug`로 브랜치를 만들어 바꾼다. 그 브랜치가 이미 있으면 `git switch task/NNN-slug`로 바꾼다. 기본 브랜치가 아니면 만들지 않고 지금 브랜치에서 실행한다. 검증이 닫히지 않은 작업이 기본 브랜치에 들어가지 않게 하는 것이다.

## 2. 남은 첫 phase의 상태를 본다

파일만 보고 정한다. 앞 세션에서 어디까지 했는지를 기억이나 대화에서 찾지 않는다.

| 상태 | 갈 곳 |
|---|---|
| 기록 절(`## 한 일`)이 없다 | 3번 |
| 체크되지 않은 TODO가 있다 | 3번 (이어 한다) |
| TODO가 모두 체크됐고 회고 절이 없다 | 4번 |
| 마지막 회고 절의 판정이 "문제 있음"이다 | 5번 |
| 마지막 회고 절의 판정이 "통과"다 | 6번 |

남은 phase가 없으면 "검증을 맡긴다"로 간다.

## 3. 수행을 맡긴다

새 컨텍스트의 에이전트를 띄워 아래 글을 그대로 넘긴다. `NNN-slug`와 `N`만 대상의 것으로 바꾸고 다른 글을 더하지 않는다. 넷째 줄은 고칠 문제가 있을 때(5번에서 왔을 때)만 붙인다.

```
plate의 phase 스킬(`plate:phase`)을 불러 그 절차를 따른다.
작업 폴더: docs/tasks/NNN-slug
phase: N
고칠 문제: phase-N.md의 마지막 회고 절에 적힌 문제 목록
```

돌아온 다섯 줄은 바로 이어 멈춰서 물을 때만 그 물음과 함께 그대로 보이고, 그 밖에는 8번의 보고에 적는다. `phase-N.md`는 필요할 때만 연다.

- 상태가 "끝남"이면 4번으로 간다.
- "계획이 틀림"이면 "계획을 고친다"로 간다.
- "막힘"이고 `phase-N.md`의 "남은 것"에 "훅이 테스트 먼저 때문에 세 번째 막음:"으로 시작하는 줄이 있으면 아래의 선택지(새 에이전트에게 다시 맡긴다 / 멈춘다)를 내지 않는다. 막힌 까닭과 수행 에이전트가 적은 해결책을 보여 주고 사용자와 논의한다. 전체 지시여도 멈춘다.
  - 합의한 해결책이 계획을 바꾸는 것이면 고칠 안을 답글로 보여 주고 거기서 멈춰 답을 기다린다. 미리 받은 승인은 승인이 아니다. 승인받으면 "계획을 고친다"의 3번대로 고쳐 커밋하고 새 에이전트에게 맡긴다. 승인받지 못하면 8번으로 간다.
  - 계획을 바꾸지 않는 해결책이면 멈추고 8번으로 간다.
- 그 밖의 "막힘"이면 `phase-N.md`의 "남은 것"을 보여 주고 묻는다: 새 에이전트에게 다시 맡긴다 / 멈춘다. 막힌 까닭이 권한이면 사용자가 권한을 바꾸기 전에는 다시 맡겨도 같은 곳에서 막힌다고 함께 알린다. 띄운 에이전트는 자기 권한을 바꾸지 못한다. 전체 지시여도 묻는다. 멈추면 8번으로 간다.

## 4. 회고나 확인을 맡긴다

방식을 정한다.

- 전체 지시가 아니면 회고할지 묻는다. 승인하면 방식은 "회고", 거절하면 "확인만"이다. phase가 하나뿐인 작업도 같다.
- 전체 지시이면 묻지 않고 "확인만"이다.
- 고친 뒤에 다시 올 때는 묻지 않고 앞의 방식 그대로다. 앞의 방식은 마지막 회고 절의 제목에 적혀 있다.

그 phase를 수행한 에이전트와 다른 새 에이전트를 띄워 아래 글을 그대로 넘긴다. `NNN-slug`, `N`, 방식만 바꾸고 다른 글을 더하지 않는다.

```
plate의 retro 스킬(`plate:retro`)을 불러 그 절차를 따른다.
작업 폴더: docs/tasks/NNN-slug
phase: N
방식: 회고
```

돌아온 세 줄은 바로 이어 멈춰서 물을 때만 그 물음과 함께 그대로 보이고, 그 밖에는 8번의 보고에 적는다. 판정이 "통과"면 6번, "문제 있음"이면 5번으로 간다.

## 5. 문제가 나오면 고치게 한다

사용자에게 묻지 않고 3번으로 가서 문제 목록 전부를 새 수행 에이전트에게 고치게 한 뒤 4번으로 돌아온다. 확인만 방식에서 확인이 실패했을 때도 같다.

`phase-N.md`의 회고 절이 셋 이상이고(처음 한 번, 고친 뒤 두 번) 마지막 판정이 "문제 있음"이면 고치게 하지 않고 멈춘다. 남은 문제를 보여 주고 묻는다. 전체 지시여도 묻는다.

- 한 번 더 고치게 한다
- 남은 문제를 고치지 않기로 하고 지운다. 이 선택지는 실패한 확인이 없을 때만 낸다. 고르면 `phase-N.md`의 마지막 회고 절 아래에 "사용자가 남은 문제를 고치지 않기로 했다"를 적고 그 파일만 커밋한 뒤 6번으로 간다. 메시지는 `NNN-slug: phase N 회고`다.
- 멈춘다. 8번으로 간다.

## 6. 통과한 phase를 지운다

1. `phase-N.md`에 커밋되지 않은 변경이 있으면 그 파일만 먼저 커밋한다. 메시지는 `NNN-slug: phase N 회고`다.
2. `docs/LESSONS.md`로 옮긴다. 옮기는 규칙은 아래 "`docs/LESSONS.md`" 절에 있다.
3. `git rm`으로 `phase-N.md`를 지운다. `plan.md`와 남은 phase의 파일은 건드리지 않고, 남은 파일의 번호도 다시 매기지 않는다.
4. 이 변경(지운 `phase-N.md`, 고쳤으면 `docs/LESSONS.md`와 `AGENTS.md`)만 한 커밋으로 넣는다. 메시지는 `NNN-slug: phase N 통과`다(예: `008-csv-export: phase 2 통과`).

git 레포가 아니면 지우지 않는다. 파일 이름을 `done-phase-N.md`로 바꾼다. 그 이름은 `phase-N.md`의 꼴이 아니므로 끝나지 않은 작업과 남은 첫 phase의 기준이 그대로 통한다. 검증 에이전트가 그 파일을 읽고, 검증이 닫히면 지운다.

## 7. 잇는다

- 남은 phase가 없으면 "검증을 맡긴다"로 간다.
- 전체 지시이면 묻지 않고 2번으로 간다.
- 아니면 지운 phase를 알리고 다음 phase(`Phase M: 이름`)를 이을지 묻는다. 승인하면 2번으로 가고, 거절하면 8번으로 간다.

이을 때도 다음 phase는 새 에이전트가 수행한다.

## 8. 보고한다

- 이번에 지운 phase와 남은 phase
- 이번에 수행한 phase마다 돌아온 상태와 판정
- 검증을 맡겼으면 돌아온 판정과 문제의 수
- 합칠지 물었으면 합친 브랜치와 합친 곳. 합치지 않았으면 그 까닭(거절, 충돌)
- 커밋. 커밋하지 않았으면 그 까닭
- `docs/LESSONS.md`에 옮긴 줄
- 프로젝트의 규칙을 따른 곳. 에이전트가 `phase-N.md`나 `verify.md`에 "프로젝트의 규칙을 따름: …"으로 적은 것도 옮긴다.
- worktree에서 검증이 닫혔으면: 원래 자리에서 이 스킬을 부르면 합칠지 묻는다고 적는다.

보고로 끝난다.

## 검증을 맡긴다

남은 phase가 없을 때 한다. 전체 지시가 아니어도 묻지 않는다.

먼저 작업 폴더의 `verify.md`를 본다.

- 닫힌 검증이면 맡기지 않고 아래 "통과하면"의 1번부터 한다. 앞 세션이 1~3을 이미 했어도 같다. 이미 옮긴 줄은 다시 더하지 않고(아래 "`docs/LESSONS.md`" 절), 지울 파일이나 고친 파일이 없으면 그 번호는 그냥 지나간다.
- 마지막 판정이 "문제 있음"이고 그 검증 뒤에 통과한 phase가 없으면 맡기지 않고 아래 "고칠 phase를 더한다"로 간다. 앞뒤는 git 레포면 커밋의 순서로, 아니면 파일이 바뀐 때로 본다.
- 그 밖이면(`verify.md`가 없거나, 마지막 검증 뒤에 통과한 phase가 있으면) 맡긴다.

그 작업의 phase를 수행하거나 점검한 에이전트와 다른 새 에이전트를 띄워 아래 글을 그대로 넘긴다. `NNN-slug`만 대상의 것으로 바꾸고 다른 글을 더하지 않는다.

```
plate의 verify 스킬(`plate:verify`)을 불러 그 절차를 따른다.
작업 폴더: docs/tasks/NNN-slug
```

돌아온 세 줄은 바로 이어 멈춰서 물을 때만 그 물음과 함께 그대로 보이고, 그 밖에는 8번의 보고에 적는다. 판정이 "통과"면 "통과하면"으로, "문제 있음"이면 "고칠 phase를 더한다"로 간다.

**통과하면**

1. `docs/LESSONS.md`로 옮긴다. 옮기는 규칙은 아래 "`docs/LESSONS.md`" 절에 있다.
2. git 레포가 아니면 작업 폴더의 `done-phase-N.md`를 모두 지운다.
3. 고친 파일(`verify.md`, `docs/LESSONS.md`, `AGENTS.md`)이 있으면 그것만 한 커밋으로 넣는다. 메시지는 `NNN-slug: 검증 통과`다. 미뤘으면 `NNN-slug: 검증 K 미룸`이다(`K`는 마지막 검증 절의 번호).
4. 지금 자리가 원래 자리이고 지금 브랜치가 `task/NNN-slug`이면 "합친다"로 간다. 아니면 8번으로 간다.

**고칠 phase를 더한다**

검증에서 나온 문제는 새 phase로 고치거나, 사용자가 나중에 다루기로 한다. 전체 지시여도 멈춰서 묻는다.

1. 새 `phase-M.md`의 안을 답글로 보여 주고, 승인할지, 문제를 나중에 다룰지, 멈출지 묻고 거기서 멈춰 답을 기다린다. 미리 받은 승인은 승인이 아니다. 안은 아래 양식대로 쓴다.
   - `M`은 이 작업에서 쓴 phase 번호 가운데 가장 큰 것의 다음이다. 지운 `phase-N.md`와 `done-phase-N.md`의 번호도 센다.
   - `K`는 마지막 검증 절의 번호다.
   - TODO는 마지막 검증 절의 문제 하나에 항목 하나다. 문제의 글과 파일의 경로를 옮긴다.
   - 테스트 먼저는 고칠 문제 가운데 동작을 바꾸는 것이 있으면 "예"이고, 없으면 "아니오"와 그 이유다.
2. 승인받으면 보여 준 안대로 `phase-M.md`를 만들고 그 파일만 커밋한다. 메시지는 `plan: NNN-slug 수정`이다. 2번으로 가서 새 에이전트에게 수행을 맡긴다.
3. 나중에 다룬다고 하면 `phase-M.md`를 만들지 않는다. `verify.md`의 마지막 검증 절 아래에 "사용자가 남은 문제를 나중에 다루기로 했다"를 적고 "통과하면"으로 간다. 지난 작업의 폴더에 phase를 더하지 않고, 미룬 문제는 `docs/LESSONS.md`에 남겨 회고 때 다루는 것이다.
4. 그 밖이면 만들지 않고 8번으로 간다.

아래 코드 블록 안쪽이 고칠 phase의 꼴이다. 블록을 여닫는 줄은 옮기지 않는다. `{…}`는 그 자리에 무엇을 적는지를 가리키고, 쓴 파일에는 `{…}`가 남지 않는다.

````markdown
# Phase {M}: 검증 {K}의 문제를 고친다

**목표**: 검증 {K}에서 나온 문제를 모두 고친다.

**테스트 먼저**: {예, 또는 아니오 — 이유}

**읽을 것**
- `docs/tasks/{NNN-slug}/verify.md`의 `## 검증 {K}` 절
- {문제에 적힌 파일의 경로}

**TODO**
- [ ] {문제의 글} ({파일의 경로})

**통과 조건**
- 머리의 완료 조건이 모두 참이다.
  - 확인: 완료 조건의 확인을 모두 돌린다
````

## 계획을 고친다

3번에서 상태가 "계획이 틀림"으로 돌아왔을 때 한다. 전체 지시여도 멈춰서 승인받는다.

1. `phase-N.md`의 "계획과 달라진 점"과 "남은 것"을 읽는다.
2. 틀린 곳과 고칠 안(`plan.md`나 `phase-N.md`의 계획 다섯 항목 가운데 어느 글을 어떻게 바꾸는지)을 답글로 보여 주고, 거기서 멈춰 답을 기다린다. 설계의 선택이 새로 생긴 것이면 선택지와 추천안을 낸다. 미리 받은 승인은 승인이 아니다.
3. 승인받으면 보여 준 안대로 고치고, 머리의 결정에 고친 것과 까닭을 한 줄 더한 뒤 고친 계획 파일만 커밋한다. `phase-N.md`의 체크박스와 기록 절은 건드리지 않는다. 메시지는 `plan: NNN-slug 수정`이다. 3번으로 가서 새 에이전트에게 맡긴다. 새 에이전트는 체크되지 않은 TODO부터 잇는다.
4. 승인받지 못하면 고치지 않고 8번으로 간다.

## 합친다

검증이 닫힌 작업의 브랜치 `task/NNN-slug`를 합친다. 두 곳에서 온다.

- "통과하면"에서: 원래 자리에서 `task/NNN-slug`에 있다. 합칠 곳은 기본 브랜치다.
- 0번에서: 원래 자리에서 불렀고 대상 작업의 worktree에서 검증이 닫혔다. 합칠 곳은 원래 자리에 체크아웃된 브랜치다.

1. 합칠 브랜치와 합칠 곳을 보여 주고 합칠지 묻는다. 전체 지시여도 묻는다. 거절하면 그대로 두고 8번으로 간다.
2. 원래 자리에 커밋하지 않은 변경이 있으면 "1. 시작 조건을 본다"의 물음대로 먼저 묻는다.
3. worktree가 없으면 `git switch`로 합칠 곳으로 바꾼다.
4. `git merge task/NNN-slug`로 합친다. squash하지 않는다. phase의 근거가 이력에 남아야 하기 때문이다.
5. 충돌하면 풀지 않는다. `git merge --abort`로 되돌리고 충돌한 파일을 알린 뒤 8번으로 간다.
6. 합쳐졌으면 worktree가 있으면 `git worktree remove .worktrees/NNN-slug`로 지우고, `git branch -d task/NNN-slug`로 브랜치를 지운다. 치우지 못하면 까닭을 보고에 적는다.

## `docs/LESSONS.md`

회고에서 배운 것, 하네스의 문제점, 미룬 문제를 모으는 문서다. 6번이나 "통과하면"에서 옮길 것이 처음 생기면 만든다. 옮길 것이 없으면 만들지 않는다.

**옮기는 것**

- 회고 방식이면 회고 절마다의 "배운 것"과 "하네스의 문제점"을 옮긴다. 고친 뒤에 통과한 phase는 회고 절이 여럿이다.
- 확인만 방식이면 `phase-N.md`의 "하네스에서 걸린 것"을 하네스의 문제점 절로 옮긴다. 회고 절에 "하네스의 문제점"이 있으면 그것도 옮긴다.
- 검증이 닫히면 `verify.md`의 검증 절마다의 "배운 것"과 "하네스의 문제점"을 옮긴다. 고친 뒤에 닫힌 작업은 검증 절이 여럿이다.
- 미뤘으면 마지막 검증 절의 "문제"를 미룬 문제 절로 옮긴다.
- "없음"은 옮기지 않는다.
- 옮길 줄과 같은 뜻의 줄이 `docs/LESSONS.md`의 같은 절에 이미 있으면 더하지 않는다. 회고 절에서 옮길 때도 검증 절에서 옮길 때도, 이미 있는 줄을 다른 작업에서 옮겼어도 같다.
- 이 작업의 검증 절의 줄(미룬 문제도)을 이미 옮겼으면 옮기지 않는다. 옮긴 뒤 LESSONS에서 지운 줄이 돌아오지 않게 하는 것이다. git 레포면 `git log -S'(NNN-slug, 검증 ' -- docs/LESSONS.md`가 커밋을 하나라도 내면 옮긴 것이다. 그 꼴의 줄은 이 작업의 검증이 닫힐 때만 더해진다. git 레포가 아니면 작업 폴더에 `done-phase-N.md`가 하나도 없으면 옮긴 것이다. "통과하면"의 2번이 1번 뒤에 지운다.

**양식**

아래 코드 블록 안쪽이 `docs/LESSONS.md`의 꼴이다. 블록을 여닫는 줄은 옮기지 않는다.

````markdown
# 회고에서 배운 것

## 프로젝트에서 배운 것
- ({작업 폴더의 이름}, phase {N}) {배운 것 한 줄}

## 하네스의 문제점
- ({작업 폴더의 이름}, phase {N}) {문제점 한 줄}

## 미룬 문제
- ({작업 폴더의 이름}, 검증 {K}) {문제 한 줄}
````

- 항목은 한 줄이다. 앞에 작업과 phase를 괄호로 적는다(예: `- (008-csv-export, phase 2) …`). 검증 절에서 옮긴 항목은 phase 자리에 검증 절의 번호를 적는다(예: `- (008-csv-export, 검증 1) …`). 옮길 때 뜻을 바꾸지 않는다.
- 이미 있는 항목은 고치지 않고 절의 끝에 더한다.
- 옮길 것이 없는 절은 제목만 둔다.

**문서 지도**

문서를 만들 때 `AGENTS.md`의 문서 지도 표에 아래 행을 더한다. `docs/tasks/NNN-slug/` 행의 앞에 넣는다. 이 문서의 위치는 하네스가 정한 것이라 사용자에게 위치를 묻지 않는다. 다만 문서 지도에서 표 위의 글에 "하네스의 스킬이 위치를 정해 둔 기록은 묻지 않고"가 없는 프로젝트(옛 setup으로 셋업됐다)에서는 그 글이 위치를 묻게 하므로, 문서를 처음 만들기 전에 위치를 묻고 거기서 멈춰 답을 기다린다. 전체 지시여도 묻는다. `docs/LESSONS.md`를 추천안으로 내고, plate의 setup 스킬(`plate:setup`)을 다시 돌리면 다음부터 묻지 않는다고 함께 알린다. 사용자가 다른 위치를 정하면 그 위치에 만들고, 아래 행의 위치 칸에 그 위치를 적는다. 그 뒤로는 문서 지도에서 내용 칸이 "회고에서 배운 것, 하네스의 문제점, 미룬 문제"인 행의 위치가 이 문서이고, 이 스킬에 `docs/LESSONS.md`로 적힌 곳(절대 규칙 5, 6번, "통과하면", 위의 "옮기는 것"과 그 `git log -S` 명령의 경로)은 모두 그 위치로 읽는다.

```
| `docs/LESSONS.md` | 회고에서 배운 것, 하네스의 문제점, 미룬 문제 | 작업을 계획하거나 회고할 때 |
```

하네스의 문제점 절의 항목은 사용자가 손으로 하네스의 저장소에 옮겨 계획의 요청 글로 쓴다. 이 스킬은 프로젝트 밖으로 아무것도 보내지 않는다.
