# 프로젝트 문서 세트 만들기

**막는 실패**: 프로젝트가 무엇을 만드는지와 이미 내린 결정이 어디에도 적혀 있지 않으면, 에이전트가 세션마다 같은 탐색을 반복하거나 내린 결정을 뒤집는다.

`docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/ADR.md`를 만들고 `CLAUDE.md`에 이 문서들을 가리키는 절을 더한다. 양식에서 시작해 저장소에서 확인한 칸만 채운다. 빈 프로젝트는 채울 것이 없으므로 양식이 그대로 남는다.

## 1. 현재 상태를 본다

- 파일 목록(`git ls-files`, git 레포가 아니면 `ls -A`)과 `CLAUDE.md`, `docs/`를 본다.
- 세 문서와 같은 역할을 하는 파일이 이미 있는지 찾는다. 이름이 달라도(`SPEC.md`, `docs/architecture.md`, `docs/adr/` 등) 역할이 같으면 있는 것으로 본다. 이미 있는 문서는 덮어쓰지 않고, 같은 역할의 문서를 새로 만들지도 않는다.
- 소스 코드와 빌드 매니페스트(`package.json`, `pyproject.toml`, `build.gradle` 등)가 하나도 없으면 빈 프로젝트다. 2번을 건너뛴다.

## 2. 저장소를 읽는다

README, 빌드 매니페스트, 최상위 폴더 구조와 진입점, 설정 파일, 기존 문서, 최근 커밋 메시지(`git log --oneline -30`)를 읽는다. 문서에 적을 내용을 확인하는 데 필요한 만큼만 읽는다. 파일이 많아 직접 읽기 어려우면 Explore 서브에이전트에 탐색을 맡기고 결론만 받는다.

## 3. 문서를 쓴다

양식은 이 문서 끝의 "양식" 절에 있다. 1번에서 없다고 확인한 문서만 `docs/`에 만든다.

- 양식의 절 구성을 바꾸지 않는다.
- 빈 프로젝트에는 양식을 한 글자도 바꾸지 않고 옮긴다.
- 코드가 있는 프로젝트에서는 저장소에서 확인한 것만 채우고, 확인한 파일 경로를 함께 적는다.
- 확인하지 못한 칸은 양식의 `{…}`를 그대로 둔다. 추측으로 채우지 않는다.
- ADR에는 코드에서 드러나는 결정(프레임워크, 저장소, 구조 선택 등)을 적는다. **이유**와 **트레이드오프**는 README, 커밋 메시지, 주석, 기존 문서에 적혀 있을 때만 옮기고 출처를 적는다. 적힌 곳이 없으면 `{확인 필요}`로 둔다. 코드만 보고 이유를 지어내지 않는다.

## 4. `CLAUDE.md`에 문서를 가리키는 절을 더한다

`CLAUDE.md`에 아래 절이 없을 때만 더한다. 파일이 없으면 이 절만 있는 파일을 만든다. 다른 내용은 건드리지 않는다. 1번에서 같은 역할의 기존 문서를 찾았으면 그 경로를 적는다.

```markdown
## 프로젝트 문서
필요할 때만 읽는다.
- `docs/PRD.md`: 무엇을 왜 만드는지, 범위 밖. 기능을 더하거나 범위를 판단할 때
- `docs/ARCHITECTURE.md`: 기술 스택, 구조, 데이터 흐름. 파일 위치나 모듈 경계를 판단할 때
- `docs/ADR.md`: 이미 내린 결정과 이유. 기술 선택을 바꾸거나 새로 할 때
```

## 5. 보고한다

만든 파일, 건드리지 않은 기존 문서, `{…}`와 `{확인 필요}`로 남아 사용자가 채워야 하는 항목을 알린다.

## 양식

아래 코드 블록 안쪽이 각 파일의 내용이다. 블록을 여닫는 줄은 옮기지 않는다.

### `docs/PRD.md`

````markdown
# PRD: {프로젝트명}

## 목표
{이 프로젝트가 해결하려는 문제를 한두 문장으로}

## 사용자
{누가, 어떤 상황에서 쓰는지}

## 핵심 기능
1. {기능 1}
2. {기능 2}
3. {기능 3}

## 범위 밖
- {만들지 않을 것 1}
- {만들지 않을 것 2}
````

### `docs/ARCHITECTURE.md`

````markdown
# 아키텍처

## 기술 스택
- {언어와 런타임 (예: TypeScript, Node 22)}
- {프레임워크와 주요 라이브러리 (예: Next.js 15, Tailwind CSS)}
- {저장소와 외부 서비스 (예: PostgreSQL, Stripe)}

## 디렉터리 구조
```
{최상위 폴더와 각 폴더의 역할 (예:
src/
├── app/          # 페이지와 API 라우트
├── components/   # UI 컴포넌트
├── lib/          # 유틸리티
└── services/     # 외부 API 래퍼
)}
```

## 패턴과 규칙
- {지켜야 할 구조 규칙과 이유 (예: 외부 API는 services/에서만 호출한다. 이유: 키와 재시도를 한곳에서 관리한다)}
- {쓰는 패턴 (예: Server Component가 기본이고, 상호작용이 필요한 곳만 Client Component로 둔다)}

## 데이터 흐름
```
{데이터가 흐르는 경로 (예: 사용자 입력 → Client Component → API 라우트 → 외부 API → 응답 → 화면 갱신)}
```
````

### `docs/ADR.md`

````markdown
# Architecture Decision Records

## 철학
{결정이 갈릴 때 따르는 우선순위 (예: MVP 속도 최우선. 외부 의존성 최소화. 작동하는 최소 구현을 고른다.)}

---

### ADR-001: {결정 사항 (예: Next.js App Router 선택)}
- **결정**: {무엇을 선택했는지}
- **이유**: {왜 선택했는지}
- **트레이드오프**: {무엇을 포기했는지}
````
