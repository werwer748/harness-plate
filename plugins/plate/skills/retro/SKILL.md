# 회고

**막는 실패**: phase마다의 확인은 그 phase의 통과 조건만 본다. task 전체를 다시 보지 않으면 phase 사이에 걸친 어긋남, 계획이 빠뜨린 문서 고치기가 확인되지 않은 채 task가 끝나고, task에서 걸린 것을 남기지 않으면 tasks 끝에서 같은 문제를 찾을 근거가 없다.

phase가 모두 통과한 task 하나를 회고한다. task 머리의 완료 조건 확인과 명령 절의 빌드·린트·테스트를 직접 돌리고, task의 커밋이 바꾼 것 전부를 task 머리, tasks 머리, 맥락 문서에 대어 점검하고, tasks 끝에 볼 것을 모은다. 끝나면 task 폴더의 `retro.md` 끝에 회고 절이, `docs/tasks/FRICTION.md` 끝에 그 task의 줄이 더해져 있고 그 두 파일만 커밋돼 있다. 마지막 회고 절의 판정이 task의 상태다. 고치지 않는다.

## 절대 규칙

프로젝트의 지침 파일(`AGENTS.md`, `CLAUDE.md`)에 적힌 규칙이 이 스킬의 규칙과 부딪히면 프로젝트의 규칙을 따른다. 아래의 절대 규칙도 그렇다. 따른 곳은 `FRICTION.md`에 한 줄로 적는다. 단계를 건너뛰라는 규칙은 여기에 들지 않는다.

1. **고치지 않는다.** 코드도 계획 파일도 고치지 않는다. 쓰는 것은 `retro.md`와 `FRICTION.md`뿐이다.
2. **확인을 직접 돌린다.** phase의 기록이나 확인 절을 옮겨 적지 않는다. 돌리지 않은 확인을 통과로 적지 않는다.
3. **적힌 기준에 대어 본다.** 취향에 드는 것(이름, 문체, 더 나은 구조)은 문제로 적지 않는다.
4. **사용자에게 묻지 않는다.** 판정과 기록까지만 한다.
5. **`retro.md`와 `FRICTION.md`만 커밋한다.** 푸시하지 않는다. 브랜치를 만들거나 바꾸지 않는다.

## 낱말

- **tasks**: 요청 하나를 계획한 묶음. `docs/tasks/`에 하나만 있고, 그 머리가 `docs/tasks/plan.md`(tasks 머리)다. tasks 머리에는 제목, 이름, 여섯 절(요청, 목표, 범위 밖, 완료 조건, 결정, task 목록)이 있다.
- **task 폴더**: tasks 안의 task 하나의 폴더(`docs/tasks/NNN-slug/`). 그 안에 task 머리, phase마다의 `phase-N.md` 또는 `done-phase-N.md`, 이 스킬이 쓰는 `retro.md`가 있다.
- **task 이름**: task 폴더의 이름(`NNN-slug`).
- **task 머리**: task 폴더의 `plan.md`. 제목과 네 절(목표, 범위 밖, 완료 조건, 결정)이다.
- **`done-phase-N.md`**: 통과한 phase의 파일. 실행이 `phase-N.md`의 이름을 바꾼 것이다. 위에 계획 다섯 항목(목표, 테스트 먼저, 읽을 것, TODO, 통과 조건), 그 아래에 수행한 쪽의 기록 다섯 절(한 일, 확인 결과, 계획과 달라진 점, 남은 것, 하네스에서 걸린 것), 그 뒤에 확인하는 쪽의 확인 절(`## 확인 1`처럼 번호가 붙은 절)이 있다.
- **명령 절**: `docs/ARCHITECTURE.md`의 `## 명령` 절. `- 설치: {명령}`, `- 빌드: {명령}`, `- 린트: {명령}`, `- 테스트: {명령}` 네 줄이고, 없는 명령은 "없음"으로 적혀 있다.
- **맥락 문서**: `AGENTS.md`의 문서 지도에 적힌 문서 가운데 `docs/tasks/` 행을 뺀 것.
- **task의 커밋**: 메시지가 task 이름으로 시작하는 커밋과 task 폴더 안의 파일을 바꾼 커밋. 수행·확인·통과·회고의 커밋은 task 폴더의 파일을 함께 바꾸므로 메시지가 프로젝트의 꼴(예: `[001] …`)이어도 든다. 계획의 커밋(메시지가 `plan:`으로 시작하는 것)과 메시지가 다른 task 이름으로 시작하는 커밋에서는 이 task 폴더의 변경만 본다.
- **`FRICTION.md`**: `docs/tasks/FRICTION.md`. task마다 tasks 끝에 볼 것을 한 줄씩 쌓는 파일이다.
- **`RUNLOG.md`**: `docs/tasks/RUNLOG.md`. 실행이 띄운 에이전트마다, 사용자에게 물은 자리마다 한 줄을 쌓는 파일이다. 이 스킬은 읽기만 한다.
- **프로젝트의 지침 파일**: 저장소의 `AGENTS.md`와 그것을 불러오는 `CLAUDE.md`.

## 0. 대상을 정한다

- 넘겨받은 task 폴더, 또는 사용자가 준 번호나 이름의 task 폴더가 대상이다.
- 받은 것이 없으면 회고하지 않는다. task 폴더를 주어 다시 부르라고 알리고 끝난다.
- 대상에 `plan.md`가 없거나 `phase-N.md`가 남아 있으면 회고하지 않는다. 그 까닭을 알리고 끝난다. 남은 phase는 plate의 run 스킬(`plate:run`)로 실행한다고 적는다.

## 1. 읽는다

- task 머리
- tasks 머리
- `retro.md`가 있으면 그 파일
- task 폴더의 `done-phase-N.md` 모두
- task의 커밋이 바꾼 것 전부. git 레포가 아니면 `done-phase-N.md`마다 "한 일"에 적힌 파일을 읽는다.
- 문서 지도의 맥락 문서. 명령 절도 여기서 읽는다.
- `RUNLOG.md`와 `FRICTION.md`가 있으면 그 파일

## 2. 완료 조건의 확인을 모두 돌린다

task 머리의 완료 조건에 적힌 확인을 하나도 빼지 않고 직접 돌린다. 명령이 아니라 "무엇을 어디서 본다"로 적힌 확인은 그곳을 직접 읽고 본 것을 적는다.

확인은 적힌 그대로 먼저 돌린다. 적힌 그대로 돌지 않으면(옵션·문법 오류로 돌지 않는다: `-`로 시작하는 패턴이 옵션으로 읽힌다, 따옴표가 어긋난다) 대상과 패턴과 기대를 바꾸지 않는 고침만 해 다시 돌린다. 허용하는 고침은 `-e`나 `--` 붙이기, 따옴표 맞추기다. 고쳐 돌린 결과로 판정하고, 적힌 명령, 고친 명령, 까닭을 "확인"의 결과에 적고 5번의 문제로 모은다. 대상이나 패턴이나 기대를 바꿔야 돌면 그 확인은 실패다.

돌리지 못한 확인(권한에 막힌 명령, 없는 도구)은 실패로 적고 결과에 그 까닭을 적는다.

## 3. 명령 절의 빌드·린트·테스트를 돌린다

명령 절의 빌드, 린트, 테스트를 이 순서로 직접 돌린다. 설치는 돌리지 않는다. "없음"으로 적힌 명령은 돌리지 않고 결과를 "없음"으로 적는다. 명령 절이 없거나 줄이 빠진 명령도 "없음"이다. "없음"은 실패가 아니다.

## 4. task의 변경을 점검한다

task의 커밋이 바꾼 것을 모두 모아 넷에 대어 본다. phase 하나씩이 아니라 task 전체를 본다. 한 phase가 만든 것을 뒤의 phase가 깨뜨린 것처럼 여러 phase에 걸쳐서야 드러나는 어긋남도 여기서 찾는다.

- task 머리의 목표와 결정, tasks 머리의 결정대로 됐는가
- task 머리와 tasks 머리의 범위 밖, tasks 머리의 task 목록에 적힌 다른 task의 일을 건드리지 않았는가
- 맥락 문서(ARCHITECTURE의 규칙, ADR의 결정, DESIGN)와 어긋나지 않는가. 바뀐 구조(디렉터리, 모듈, 기술 스택, 데이터 흐름)가 맥락 문서에 빠지지 않았는가
- 동작이 틀리는 결함이 있는가

넷 가운데 하나에 걸리는 것만 문제로 적는다. tasks 머리나 task 머리의 결정, 완료 조건이 바꾸기로 한 맥락 문서의 줄과 어긋나는 것은 문제로 적지 않는다.

문서와 코드(또는 계획과 코드)의 어긋남을 문제로 적을 때는 task 머리와 tasks 머리의 목표와 결정에 비춰 어느 쪽을 고칠지(문서 | 코드)와 그 근거가 된 목표나 결정을 적는다. 목표와 결정으로 가를 수 없으면 "고칠 쪽: 정하지 못함"과 그 까닭을 적는다.

tasks 머리나 task 머리의 결정, 또는 맥락 문서가 약속하는 꼴의 경계를 정했으면 "결함"은 그 경계 안에서만 찾는다. 경계 밖에서 찾은 꼴은 문제로 적지 않고 5번에서 `경계 밖`으로 모은다. 경계를 정한 곳이 없으면 찾은 결함은 "결함"으로 적는다.

결정이나 완료 조건이 정한 동작이라도, 이름이나 번호로 커밋, 파일, 브랜치를 고르거나 찾는 동작이 세 경우(지난 tasks의 같은 이름이 남은 경우, 합쳐지지 않은 다른 브랜치(로컬과 origin)에 같은 이름이 있는 경우, 한 동작이 이름을 둘 이상 만들면 그 이름마다) 가운데 하나에서, 또는 입력(파일, 줄, 항목)이 둘 이상인 경우에 목표를 해치면 "결정이 정한 대로"라는 까닭으로 "문제 아님"으로 닫지 않고 5번에서 `경계 밖`으로 모은다. 기록의 "남은 것"에 그 꼴이 적힌 줄도 그렇다. 그 줄의 판정에는 까닭에 `경계 밖`을 적는다.

`done-phase-N.md`마다 기록의 "남은 것"에 적힌 줄(부작용과 한계, 동작의 결함, 돌려 보지 않은 위험)을 모두 모아, 줄마다 넷에 대어 문제인지 판정한다. 돌려 보지 않은 위험은 그 동작을 task의 커밋이 바꾼 것에서 직접 읽거나 돌려 보고 판정한다. 판정은 줄마다 회고 절의 "남은 것"에 적고, 문제면 "문제"에도 적는다. 끝내지 못한 TODO의 까닭처럼 이 셋이 아닌 줄은 모으지 않는다.

테스트 먼저가 "예"인 `done-phase-N.md`마다, 기록의 "한 일"에 구현하기 전에 돌린 테스트의 실패 출력과 구현한 뒤의 통과 출력이 이 순서로 있는지도 본다. 본 결과는 통과해도 회고 절의 "확인"에 phase마다 적는다. 없거나 순서가 다르면 문제로 적고 기준은 "계획"이다.

## 5. tasks 끝에 볼 것을 모은다

이 task에서 tasks 끝에 볼 것을 네 갈래로 모은다.

- **문제**: 하네스나 계획이 걸린 곳. `done-phase-N.md`의 기록과 확인 절에 적힌 "하네스에서 걸린 것", 판정이 실패였던 확인 절(무엇이 실패해 다시 수행했는지), 점검하며 본 것(완료 조건의 확인이 조건을 다 보지 못했다, 계획이 맥락 문서 고치기를 빠뜨렸다, 읽을 것이 빠졌다, 확인 명령이 적힌 그대로 돌지 않아 2번대로 고쳐 돌렸다(적힌 명령, 고친 명령, 까닭을 함께), 명령 절이 없거나 줄이 빠졌다)에서 모은다. 다만 확인 절 "하네스에서 걸린 것"의 `남은 것:`으로 시작하는 줄은 이번 회고 절 "남은 것"에서 "문제"로 판정한 것만 모으고, "문제 아님"으로 판정한 줄은 모으지 않는다. 그 줄은 4번에서 이미 판정했고, 문제가 아닌 줄을 `문제`로 넣으면 `FRICTION.md`의 문제 줄과 회고 절의 "문제"가 갈린다.
- **멈춤**: 막힘, 훅의 세 번째 막음, 계획이 틀림, 세 번 실패처럼 실행이 멈추고 사용자에게 물은 자리. `RUNLOG.md`의 물은 줄 가운데 이 task를 실행하며 물은 자리가 `멈춤`인 줄에서 모은다. 물은 자리가 `멈춤`이 아닌 줄(권한, 실행 방식, 커밋하지 않은 변경, 기본 브랜치, 고칠 phase, 다음 task, 고칠지처럼 정해 둔 자리에서 물은 것)은 멈춤이 아니다.
- **스킬로 만들 후보**: 이 task의 여러 phase에서 되풀이된 손일(같은 명령 묶음, 같은 꼴의 확인이나 고치기)로, 스킬로 만들면 줄어들 것. `done-phase-N.md`의 "한 일"과 확인 절에서 모은다.
- **경계 밖**: 4번에서 결정이나 맥락 문서가 약속한 경계 밖에서 찾은 꼴과, 그 꼴을 약속에 넣을지 볼 까닭. 약속을 넓힐지는 사람이 볼 거리라 문제와 나눠 적는다.

모을 때 지키는 것:

- 다른 프로젝트에서도 그대로 읽히게 어느 스킬의 어느 규칙인지, 또는 계획의 어느 곳인지를 적는다.
- 이번 회고에서 직접 읽거나 돌려서 본 것만 적는다. 다른 스킬의 본문은 열지 않고 이름으로만 가리킨다. 다만 그 본문이 task의 커밋이 바꾼 파일이면 1번대로 읽고 그 글에 대어 적는다. 읽지 않은 파일과 이 스킬 밖의 하네스 동작(예: 실행 스킬이 회고 뒤에 하는 일)은 짐작해 적지 않는다.
- `FRICTION.md`에 이 task의 같은 줄이 이미 있으면 다시 모으지 않는다.

## 6. 회고 절을 적는다

task 폴더의 `retro.md` 끝에 아래 양식대로 더한다. 파일이 없으면 첫 줄을 `# 회고`로 만들고 그 아래에 더한다. 이미 회고 절이 있으면 지우거나 고치지 않고 그 아래에 다음 번호로 더한다.

**판정**: 실패한 확인이 없고 문제 목록이 비어 있으면 "통과"다. 그 밖에는 "문제 있음"이다.

## 7. `FRICTION.md`에 더한다

5번에서 모은 것을 `FRICTION.md` 끝에 아래 양식대로 한 줄씩 더한다. 파일이 없으면 첫 줄을 `# FRICTION`으로 만들고 그 아래에 더한다. 이미 있는 줄은 지우거나 고치지 않는다.

- 모은 것이 없고 `FRICTION.md`에 이 task의 줄이 아직 없으면 task 이름과 "없음"을 한 줄로 적는다.
- 모은 것이 없고 이 task의 줄이 이미 있으면 더하지 않는다.

## 8. 커밋한다

판정이 "문제 있음"이어도 커밋한다. `retro.md`와, 7번에서 더한 줄이 있으면 `FRICTION.md`만 넣는다. 이미 스테이징돼 있던 다른 변경이 있어도 커밋에는 이 파일들만 넣는다. 메시지는 `NNN-slug: 회고`다(예: `001-react-setting: 회고`). git 레포가 아니면 커밋하지 않는다.

## 9. 세 줄을 돌려준다

아래 세 줄만 돌려준다. 다른 글을 더하지 않는다.

```
판정: 통과 | 문제 있음
문제: N개
기록: docs/tasks/NNN-slug/retro.md
```

맡은 글에 `부른 쪽: plate:run` 줄도 작업 트리의 스킬 줄(`작업 트리의 {경로}를 읽어 그 절차를 따른다.`로 시작하는 줄)도 없을 때만 사용자가 직접 부른 것으로 보고, 그때는 이 세 줄에 문제 목록을 더해 보여 주고, 고치는 일은 plate의 run 스킬(`plate:run`)을 부르면 이어진다고 적는다. 고치지 않는다.

## 기록의 양식

아래 코드 블록 안쪽이 두 파일에 더하는 것의 꼴이다. 블록을 여닫는 줄은 옮기지 않는다. `{…}`는 그 자리에 무엇을 적는지를 가리키고, 쓴 파일에는 `{…}`가 남지 않는다.

**회고 절** (`retro.md`)

````markdown
## 회고 {몇 번째}

**확인**
- {완료 조건의 글}
  - {돌린 명령, 또는 본 곳} → {나온 결과}. {통과 | 실패}
- 명령 절
  - 빌드: `{돌린 명령}` → {나온 결과}. {통과 | 실패}
  - 린트: `{돌린 명령}` → {나온 결과}. {통과 | 실패}
  - 테스트: `{돌린 명령}` → {나온 결과}. {통과 | 실패}
- 테스트 먼저 기록: phase {번호}
  - {본 곳} → {실패 출력과 통과 출력이 이 순서로 있는지}. {통과 | 실패}

**남은 것**
- phase {번호}: {기록의 "남은 것"의 줄} → {문제 | 문제 아님} ({까닭: 걸린 기준, 또는 걸리지 않은 까닭})

**문제**
- {무엇이 어디서 어떻게 틀렸는지} ({파일의 경로}). 기준: {계획 | 범위 | 맥락 문서 | 결함 | 확인 실패}. 고칠 쪽: {문서 | 코드 | 정하지 못함} ({근거가 된 목표나 결정, 정하지 못했으면 그 까닭})

**판정**: {통과 | 문제 있음}
````

**`FRICTION.md`의 줄**

````markdown
- `{task 이름}` {문제 | 멈춤 | 스킬 후보 | 경계 밖}: {무엇이 어디서 어떻게 걸렸는지, 무엇을 스킬로 만들면 무엇이 줄어드는지, 또는 경계 밖에서 찾은 꼴과 그 꼴을 약속에 넣을지 볼 까닭}
- `{task 이름}` 없음
````

## 적는 규칙

- 제목의 번호는 그 파일의 몇 번째 회고 절인지다. 첫 회고 절은 `## 회고 1`이다.
- 항목의 순서를 바꾸지 않는다. 없는 항목은 "없음"으로 적는다.
- "확인"에는 완료 조건마다 그 조건에 적힌 확인을 모두 적는다.
- "명령 절"에서 "없음"인 명령은 `- 빌드: 없음`처럼 적는다.
- "테스트 먼저 기록" 항목은 테스트 먼저가 "예"인 phase마다 명령 절 뒤에 적는다. 통과해도 적는다. 그런 phase가 없으면 이 항목을 적지 않는다.
- "남은 것"에는 4번에서 모은 줄(부작용과 한계, 동작의 결함, 돌려 보지 않은 위험)마다 phase 번호와 판정(문제 | 문제 아님)과 까닭을 한 줄로 적는다. 모은 줄이 없으면 "없음"으로 적는다. "문제"로 판정한 줄은 "문제"에도 4번의 넷 가운데 걸린 기준으로 적는다.
- 실패한 확인은 "문제"에도 적는다. 명령 절의 실패도 같다. 기준은 "확인 실패"다. "테스트 먼저 기록"이 실패면 기준은 "계획"이다.
- 문제의 기준은 4번의 넷과 확인 실패뿐이다: 목표와 결정, 테스트 먼저대로 되지 않았으면 "계획", 범위 밖이나 다른 task의 일을 건드렸으면 "범위", 맥락 문서와 어긋나거나 바뀐 구조가 맥락 문서에 빠졌으면 "맥락 문서", 동작이 틀리면 "결함"이다.
- "문제"의 "고칠 쪽"은 문서와 코드(또는 계획과 코드)의 어긋남에만 적는다. 어긋남이 아닌 문제에서는 이 칸을 적지 않는다.
- 결정이나 맥락 문서가 정한 경계 밖에서 찾은 꼴은 "문제"에 적지 않고 `FRICTION.md`에 `경계 밖` 줄로 적는다.
- `FRICTION.md`의 줄은 하나에 볼 것 하나를 적는다. 줄마다 앞에 task 이름을 붙인다.
- 스킬의 규칙이 프로젝트의 규칙에 밀린 곳은 `FRICTION.md`에 문제 줄로 "프로젝트의 규칙을 따름: …"으로 적는다.
